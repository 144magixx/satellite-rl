### 建议新增的 Git 使用约定

1. **一次提交对应一个清晰目的。** 例如奖励修复、性能优化、文档整理分别提交；允许在开发分支保存未完成进度，但说明尚未通过的检查。提交前查看 `git status`、`git diff` 和 `git diff --cached`，只暂存属于当前任务的文件。
2. **主分支保持可运行。** 算法、环境和训练机制改动先开独立分支；通过相应正确性检查后再合并到 `main`，并保留学习效果的真实验证状态。纯文档等小改动可以直接提交到主分支，无需建立复杂的分支体系。
3. **正式实验绑定固定提交。** 实验记录写入完整 commit ID、配置、数据/权重校验值及输出目录。优先从干净的冻结版本运行；有未提交差异时，仅记录 commit ID 不能复原实验，须先提交或另外保存完整差异及未跟踪文件。
4. **后台训练与日常编辑隔离。** 长训练优先使用固定提交的独立 worktree 或源码快照，不在实验所用目录切分支或修改代码。当前 DQN 使用可编辑安装，独立目录启动时还应核对 `satellite_rl.__file__` 确实指向实验源码，不能仅凭工作目录判断导入版本。
5. **保留历史，谨慎回退。** 已共享或已用于正式实验的提交不随意改写；需要撤销已提交改动时优先用 `git revert` 追加反向提交。`reset --hard`、`clean -fd`、强制推送和删分支须先明确影响范围并保留需要的文件。
6. **实验资产单独归档，代码另做备份。** `outputs/` 和 `models/runs/` 不在 Git 历史中，重要结果与权重仍需独立保存；可以在版本化文档中记录其实验编号、路径和校验值。不要提交密码、令牌等凭据。本地提交保存在同一磁盘，不提供异地备份；以后配置远程仓库或其他备份，再同步需要保存的内容。

### 日常操作示例

在 PowerShell 中进入项目并查看当前状态：

```powershell
Set-Location D:\paper
git status
git log --oneline -5
```

较大的改动先建分支。以下名称只是示例，并未实际创建：

```powershell
git switch -c fix/reward-calculation
```

修改并完成对应验证后，查看差异，按实际任务暂存具体文件，再提交：

```powershell
git diff
# git add -- 实际修改的文件路径
git diff --cached
git commit -m "fix: 修正奖励计算并补充验证"
```

记录某次实验所使用的完整版本号：

```powershell
git rev-parse HEAD
git status --short
```

确认分支达到合并条件、工作区无待处理改动后，可切回 `main` 合并；例如仅有上述顺序开发时：

```powershell
git switch main
git merge --ff-only fix/reward-calculation
```

若不能快进，先查看两条分支的差异并选择合适的合并方式，不通过强制重置消除分歧。当前未配置远程仓库，`git commit` 仅保存到本地；`git push` 需要先设置远程地址。
