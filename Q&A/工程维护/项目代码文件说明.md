# 项目里有哪些代码，它们如何衔接？

记录日期：2026-09-24。

## 结论

完整清单见项目根目录 [README_CODEBASE.md](../../README_CODEBASE.md)。当前安装包代码在 `src/satellite_rl/`，共 58 个 Python 文件；自动化测试有 23 个文件，示例有 2 个。来源栏里的“历史”表示能在 [迁移清单](../../docs/migration_manifest.json) 找到旧文件对应关系；不表示这段代码已经停用。“新增”表示原迁移对应表没有该文件，随后为匹配规模网络、运行记录、正确性检查、六组单种子实验或其报告加入。

迁移表能一一对应旧文件的模型、环境、基线、旧评估与绘图入口，是历史代码的主要来源。原训练大脚本被拆成算法、环境、训练入口三部分；`paths.py`、包入口和共享配置属于新的项目骨架，不是新的学习算法。

## 六组实验实际用到的文件

六组种子 51001 的 SAC 作业由 `training/experiment_runner.py` 启动，各自用 `agents/sac_transformer.py`、`sac_cnn_matched.py` 或 `sac_mlp_matched.py`，共用 `agents/sac_math.py`，环境为 `envs/satellite.py`，进度和断点由 `training/run_monitor.py` 保存。旧的 `experiment_suite.py` 曾管理被取消的十八组，不再用来启动训练；六组结果采用 `evaluation/single_seed_scope.py` 校验，以 `single_seed_analysis.py` 生成报告与曲线，补充评价分别由 `single_seed_postchecks.py` 和 `single_seed_update_timing.py` 完成。

`outputs/` 中另外保存了 113 个与具体试验一同归档的 Python 核查/性能脚本，它们不是安装包模块，也不会被上述六组训练入口自动调用。提速前源码快照另在 `outputs/verification/performance_only_20260924/before/`，应当仅作为历史对照使用。各脚本的目录归属和用途已列在 README_CODEBASE.md。

项目依赖为 PyTorch、NumPy、pandas 和 Matplotlib；正式训练使用 DQN Conda CUDA 环境。每个研究结论要回到该实验的 manifest、场景数据、原始日志、模型和哈希核对，不能只根据 Python 文件名称推断某个入口曾被调用。
