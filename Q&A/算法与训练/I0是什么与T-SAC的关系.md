## 2026-10-18 问题

S2-FIX方案（Claude维护05）是不是在最新的T-SAC（带0.5瓦档位）基础上做的？I0是什么？

## 结论

**一半是。**方案里有两个学习方法：L2是最新的直出T-SAC（W32最好的配置P01-M1），在新需求和新链路模型下重训，作为历史主线的延续；L1是I0，是方案的主学习方法，与T-SAC不是同一个模型。

**关于"0.5瓦每档"。**W31试过两种加法：只加一个0.5瓦选项（档位0.5、5、10、…、50瓦，11档），和把0.5到50瓦全按0.5瓦一档细分（100档）。两者供需匹配提升几乎相同（+0.139对+0.137），所以后来的W32和这次都用"只加一个0.5瓦选项"的版本，不是每档0.5瓦。

**I0是什么。**名字来自2026-10-09方案19的编号，I指"改进"（improvement），0是第一条改进路线；同批还有C0、C1两条"构造"路线。它和直出T-SAC的区别：

| | 直出T-SAC | I0 |
| --- | --- | --- |
| 起点 | 空白 | 贪心规则给出的合法分配 |
| 模型做什么 | 逐个波束决定频率起点、槽数、功率档位，一次给出完整分配 | 每步从候选修改菜单里挑一个（移动一束的频率块、调整相邻两束的边界、同组两束互换、2到4束窗口重排、回退到最好版本、停止），用真实物理算一次效果 |
| 预算 | 每束一次决策 | 每景最多32步、32次物理探测 |
| 功率 | 自己学离散档位 | 不学，规则给初值，第三阶段SCA定终值 |
| 输出 | 最后一步的分配 | 过程中最好的一版（满足率、供需匹配、基本服务三项都不退步才替换） |
| 历史成绩 | 可变束数下需求满足率从未超过贪心，优势在供需匹配 | 2026-10-09在880景上比贪心高3.26个百分点，比同预算规则搜索高1.75、随机搜索高0.68（第二阶段报告15） |

**为什么主方法选I0而不是T-SAC。**2026-10-09定下"学习负责离散结构、数学优化负责连续功率"的分工，I0正好符合；它也是第二阶段唯一在满足率上稳定胜过贪心的学习结果。T-SAC保留为L2，是为了和W31、W32的结果接得上，只报告不设门槛。

**这次对I0的改动。**候选菜单加"两束交换频率组"（因为热点叠放后组的分配很关键），训练步数从历史40万宏步减到20万，其余超参不动。代码在`src/satellite_rl/sac_improvement/`。

## 2026-10-18 结果（S2-FIX报告12）

**I0比贪心高、能用少十倍的探测达到强搜索的质量，但同样耗时下贪心＋禁忌搜索一样好；直出T-SAC在需求压力下不如贪心。**主档43.2 Mbps、SCA后的业务量加权满足率：

| 方法 | 开发20景 | 确认88景 |
| --- | --- | --- |
| 贪心G1 | 94.4% | 92.5% |
| 贪心＋禁忌搜索32次 | 96.6% | 94.5% |
| 贪心＋禁忌搜索320次 | 96.9% | 94.9% |
| I0（32次） | 96.9% | 94.9% |
| 直出T-SAC | 89.5% | 88.3% |

- I0比贪心高2.5个百分点（过第一条判据），比同预算贪心＋禁忌搜索只高0.3（门槛1.0，不过），与320次贪心＋禁忌搜索持平。按预先写定的结局，第二阶段主算法为贪心＋禁忌搜索，I0记"同质量少探测"。I0每一步要生成候选并过一次网络，一步的耗时约等于贪心＋禁忌搜索三次探测；给贪心＋禁忌搜索同样的耗时（96次探测），两者一样好。
- I0在训练前2万步就学到了好的挑选办法，之后开发集几乎不再提高，加训练步数不会改变结论。新加的"两束交换频率组"动作被大量使用（约四分之一）。
- 直出T-SAC比贪心低4—5个百分点；把Transformer换成多层感知机满足率不变，所以对满足率而言Transformer不必要。
- 历史上I0"比规则搜索高1.75"的那个对手每步按固定优先级挑一个候选、不先看效果；这次的贪心＋禁忌搜索每步按同一优先级试前4个候选、取实测最好的一个，并禁止走回头路，强得多。详见[报告12](../../docs/Claude维护/S2-FIX第二阶段需求压力/12_S2-FIX第二阶段需求压力实验报告.md)。
