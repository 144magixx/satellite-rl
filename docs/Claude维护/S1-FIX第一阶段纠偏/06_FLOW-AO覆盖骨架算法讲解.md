# FLOW-AO 覆盖骨架算法讲解

来源：cc

2026-10-18｜讲的是 S1-FIX 实验里第一阶段用的两个非学习算法：静态布局算法 FLOW-AO，和动态的"每分钟轻量局部修复"规则。结果见[报告04](04_S1-FIX第一阶段纠偏实验报告.md)，本文只讲算法怎么工作、为什么有效。代码在分支 `s1fix` 的 `src/satellite_rl/coverage/s1fix/` 下，静态在 `skeleton.py`，动态在 `dynamic.py`，几何工具在 `geom.py`。

## 1. 一句话说清

**FLOW-AO 把"飞机归哪个波束"和"波束放在哪里"拆成两个问题，前者用网络流精确求到最优，后者用几步简单的几何动作调整，两者交替直到不再改善。** 名字里的 FLOW 指网络流，AO 指交替优化（alternating optimization）。

历史方法差四倍，缺的正是"精确指派"这一步。以前的做法是先把天空划成区，每架飞机归到离它最近的波束中心，再局部挪动修补。问题在于一架飞机往往同时被好几个波束覆盖，"归最近的"是一种随意的选择，密集区（伦敦上空）的波束就被塞爆了。FLOW-AO 允许飞机归给任何覆盖它的波束，然后用网络流一次算出让最忙波束最轻的归属方案。这一步在数学上是精确的，不是启发式。

## 2. 要解的题

输入是某一时刻欧洲上空全部飞机的位置（几百到两千架）和波束数预算 N（最多200）。输出是每个波束的指向中心和宽度，以及每架飞机归哪个波束。规则：

- 每架飞机必须被覆盖，而且只归一个波束。
- 波束宽度 0.3° 到 1.0°，宽度取成员的包络，即刚好罩住它所有飞机。
- 间隔规则（可选）：任意两个波束的中心都不落入对方的足迹。

目标是让最忙的波束负载最低（峰值最小），负载按飞机架数计，每架 21.6 Mbps。峰值相同时再比最忙 10% 波束的平均负载和负载不均衡度（CV）。

角度全部指从卫星看过去的张角。两架飞机在卫星视角下相差 0.5°，地面上大约相距 300 公里。

## 3. 核心一步：精确指派

给定一组波束中心，每个波束有一个覆盖半径 r（见第5节），飞机 a 可以归给波束 j 当且仅当 a 到 j 中心的张角不超过 r_j。这样得到一张"谁能归谁"的二分图。问题变成：在这张图上给每架飞机选一个波束，让最忙波束的架数最少。

**用最大流判断"峰值 P 行不行"。** 建一张流网络：源点连每架飞机（容量1），飞机连它能归的每个波束（容量1），每个波束连汇点（容量 P）。如果最大流等于飞机总数，说明存在一种归属方案，每束不超过 P 架。否则不存在。

**对 P 二分。** P 的下界是 ceil(n/N)，即飞机数除以波束数向上取整，这是任何方案都达不到以下的值。上界取"就近分配"的峰值。二分十来次就能找到最小的可行 P，每次是一个稀疏图上的最大流，两千架飞机、两百个波束时毫秒级。

**峰值定了，再在峰值不变的前提下把负载摊匀。** 做法是把"最小化负载平方和"写成一个线性规划：每个波束开 P 个"名额"，第 k 个名额的代价是 2k−1。一个波束装 L 架飞机，它用掉前 L 个名额，代价合计 1+3+…+(2L−1) = L²。所以总代价就是各束负载的平方和，平方和最小就是最均衡。这个线性规划的约束矩阵是网络流结构（全幺模），解自动是整数，不需要整数规划。代价里再加一个很小的"离中心越近越好"项作并列时的取舍，让波束尽量紧凑。

**空波束要填上。** 最大流可能让某个波束一架飞机也没有。空波束会被删掉，浪费预算。代码沿"交替路径"把飞机从满的波束一路换到空波束，保证峰值不升。

这一步的意义：给定中心，归属问题已经解到最优。剩下的全部不确定性只在"中心放哪"。

## 4. 外层：中心怎么放、怎么调

### 4.1 初始中心：随密度自适应的网

先为每架飞机算一个"局部半径"：它到第 k 近邻飞机的张角，夹在 0.15° 到 0.5° 之间。飞机稀疏处这个半径大，密集处小。然后按半径从大到小扫描：如果这架飞机还没被任何已选中心覆盖，就把它选为新中心，把它半径内的飞机标为已覆盖。稀疏区先放中心，密集区自然会放得密。

k 决定中心数量：k 越大半径越大、中心越少。对 k 二分，找到恰好用满预算的最大 k。

设计初版用的是"逐束二分"的均匀网，在密集区卡住，峰值停在28架；换成自适应网后降到20架左右。

### 4.2 交替改善的一轮

拿到初始中心后，先做一次精确指派得到初始布局，再反复做下面四个动作，每轮都用"峰值、最忙10%平均、CV"这三元组比较，只接受变好的：

1. **重新指派。** 中心不动，重新跑第3节的精确指派（先压峰值，再摊匀）。
2. **重定中心。** 对每个波束，把中心移到它当前成员的最小包围圆圆心，这样宽度最窄。一个一个移，每次检查合法性，某个波束移不了不影响其它波束。移完再指派一次。
3. **删闲束、拆忙束。** 从最闲的波束开始试：删掉它之后，用最大流检查其余波束能否在峰值不升的前提下接收它的飞机。能，就删掉，把省下的名额用在最忙波束上（见动作4）。
4. **拆最忙波束。** 预算有剩余时，把最忙波束的成员分成两堆（取相距最远的两架做种子，做几轮两类聚类），在两堆的圆心各放一个中心。用最大流检查新布局在当前峰值下可行，可行就接受。有间隔规则时，两个新中心会沿它们的连线向外推开，直到满足最小间距。拆完预算还有、峰值大于1，就继续拆下一个最忙的。

三轮没有改善就停，最多30轮。每轮里动作2到4都可能让指派有改进空间，所以下一轮又从动作1开始。

### 4.3 多次重启与时间上限

可以带不同随机种子多跑几次（拆束时随机打乱同负载波束的顺序），取最好的。报告里"3倍、10倍计算量"就是重启3次和10次。每景有时间上限（静态实验120秒），超时就停在当前最好解。实际上100束以内的场景一次重启只要几秒。

## 5. 间隔规则怎么实现

间隔规则原文是"任意两波束中心都不落入对方足迹"。实现上等价于两条更简单的规则，在整个算法里自动满足：

- 任意两个中心相距至少 0.15°。
- 每个波束的覆盖半径不超过它到最近其它中心的距离，且不超过 0.5°。

第二条保证"别的中心不在我的足迹里"，第一条保证宽度不低于 0.3° 的下限。覆盖半径只用来决定"谁能归谁"，最终波束宽度仍取成员包络，通常比覆盖半径小得多。

设计初版把半径固定为 0.5°，波束都接近 1° 宽，拆出的新束被间隔规则并了回去，1752架场景在200束预算下只用了33束。改成"半径不超过到最近中心的距离"后，波束越密半径自动越小，能拆出来。

不加间隔规则时半径固定 0.5°，波束可以叠放。这时峰值能降到下界，但报告第4节说明叠放波束的同频干扰会伤害最差飞机，所以正式方案保留间隔规则。

## 6. 为什么能到下界，为什么有时到不了

**不加间隔时峰值等于 ceil(n/N)。** 原因是飞机每拆一次都用最大流确认峰值不升，拆到预算用满为止；而每个波束半径 0.5° 的叠放网足够密，几乎每架飞机都有多个波束可选，最大流总能把负载摊平。下界是任何算法都不可能突破的，所以这个方向没有剩余空间。

**加间隔时白天卡在伦敦。** 伦敦上空 0.1° 范围内约95架飞机。间隔规则下，一个点最多被约7个波束同时覆盖（中心至少相隔0.15°，半径又不能超过相邻中心距离）。95架分给7个波束，每束至少14架，再加上这些波束还要接收周围的飞机，白天峰值就停在约20到29架。这不是算法没找到，而是规则本身的限制，加10倍计算量也只再降1架。

## 7. 动态版：每分钟轻量局部修复

飞机每分钟移动约15公里，布局不需要每分钟从头算。动态算法分两步：

**第一步，修补（patch）。** 中心全部不动。上一分钟在场的飞机，如果还在原波束的覆盖半径内，就留在原束；不在了，就归给能覆盖它的最闲波束；新进场的飞机同样处理。没有任何波束能覆盖的飞机，在它的位置新开一个波束；预算已满时，先解散一个最闲的、成员都能被别的波束接收的波束。离场的飞机删掉，空波束删掉，各束宽度按新成员重算。这一步只要 0.03 秒，但负载会慢慢漂高。

**第二步，局部修复（repair）。** 只动最忙的6个波束和它们 1° 内的邻束，其余波束的中心、宽度、成员全部冻结。在这个局部区域里跑第4节的交替改善：精确指派、重定中心、删闲束拆忙束。指派时多加一项代价：飞机换波束要付 κ 的罚分，这样同样峰值下尽量少换束。

"轻量"指修复只跑5轮、换束罚分 κ=3。报告里比较过的另外两档是"较深修复"（15轮、κ=0.5）和"整景修复"（全部波束、10轮、κ=0.5），三者峰值差别在0.2架以内，轻量版换束最少。

每帧流程就是"修补，然后轻量修复"，固定执行，不需要判断。单帧 0.5 秒，峰值比每帧全重算只高 0.3 到 0.4 架，换束比例 7% 对 46%。PPO 在五种动作里学到的最优策略就是这条固定规则。

全重算时波束编号按中心位置匹配（1° 内匹配，用匈牙利算法最大化匹配数），用于统计换束。

## 9. 和历史方法的对应关系

| | 历史方法（R8、SH-C） | FLOW-AO |
| --- | --- | --- |
| 飞机归属 | 就近，或按固定分区 | 网络流精确求最小峰值，再摊匀 |
| 中心调整 | 几何排序、局部挪动 | 重定圆心、删闲拆忙，接受条件由最大流判定 |
| 波束数 | 按规则增删 | 拆束直到预算用满或峰值为1 |
| 是否有最优保证 | 无 | 给定中心时归属最优；不加间隔时峰值达下界 |
| 学习的位置 | GNN打分辅助排序 | 无 |

历史方法的峰值约为 FLOW-AO 的四倍。差距的来源可以在报告 3.2 节的对照里看到：同样的初始中心，只按就近分配，峰值就是 FLOW-AO 的三倍；可变宽度再贡献一倍。

## 10. 代码入口

- `skeleton.solve(frame, N_budget, spacing, effort, time_limit)`：静态求解，返回布局、是否可行和分段耗时。`spacing=False` 关闭间隔规则，`fixed_width` 固定宽度，`balance=False` 只压峰值不摊匀。
- `skeleton.assign(centers, members, mode, radii, prev_owner, kappa, eligible_mask)`：精确指派，`mode="peak"` 只压峰值，`"balance"` 再摊匀。
- `skeleton.init_baseline`：对照用的"自适应网＋就近分配"。
- `dynamic.patch`、`dynamic.repair`：修补与局部修复；`dynamic.DynamicEpisode.step(action)` 里动作1就是轻量修复。
- `geom.validate_layout`：唯一的合法性检查（覆盖、宽度、束数、间隔）。
