# 第一阶段纠偏实验设计：先定骨架与底线，再把学习放到时间维度上

来源：cc

2026-10-17｜设计稿；用户已于同日批准在20654执行，见附录。

## 1. 结论

第一阶段过去三周没有做出学习成果，主要原因不是模型不够强，而是**题目摆错了位置**：让学习在一张静态快照上、和已经知道全部信息的几何规则比"谁的最忙波束更闲"，而且是在一批几乎没有改进空间的夜间场景上比。

纠偏分三块，按顺序做：

- **块A 定骨架、算底线。** 把现有几条强规则在同一批场景上正面比一次，选出唯一的非学习骨架；再算出每个场景"最好也只能做到多少"的底线。底线和骨架的差距决定静态布局还值不值得让学习插手。
- **块B 把学习搬到时间维度。** 相邻时刻的增量重配置：上一分钟的波束布局摆在那里，这一分钟飞机动了，什么时候动、动哪片、动多大。这里规则不再拥有全部信息（飞机往哪飞、热点会不会移过来），学习才有胜算；它同时兑现开题承诺的"动态业务"。
- **块C 接到第二、三阶段。** 把第一阶段的真实布局送进频率槽分配和功率优化，看每架飞机最终得到的服务，回答"波束负载更均衡到底有没有用"，并据此定第一阶段该用哪个主指标。

三块共用一套冻结的问题定义、数据划分、指标和报告模板。中期答辩前能完成且不依赖学习结果的是块A和块C。

### 3.3 一个尚未冻结的建模问题

现有几何规则允许两个波束中心任意接近，只要求锚点飞机不同。这样理论上可以把一个热点拆成多个几乎重叠的窄波束来压低峰值，峰值指标会被"堆叠波束"钻空子，真正的代价（同一片空域的频谱复用）要到第二阶段才暴露。建议在块A之前冻结一条**最小中心间隔规则**：任意两个波束的中心不落入对方的足迹内，即中心角距不小于两者半宽的平均值。它物理上温和、便于检查，并让底线更贴近真实可达值。这需要用户决定（第11节）；两种选择下实验流程相同，只是底线和骨架结果不同。

## 4. 冻结的问题定义（v1）

一经用户确认即为第一阶段论文口径，中途不改；要改就升版本号并重跑受影响的块。

| 项目 | 定义 |
| --- | --- |
| 输入 | 一个时刻（或一段连续时刻）欧洲上空GEO 13°E可见的全部飞机，稳定ID、经纬度；每机固定请求21.6 Mbps |
| 决策 | 实际波束数N（非空、≤200）、每束中心、每束全宽（0.3°到1.0°，取成员包络）、每架飞机的唯一归属 |
| 硬约束 | 全部飞机覆盖、唯一归属、各束请求等于成员请求之和、N≤N预算、Ω≤Ω上限、最小中心间隔规则（待定） |
| 资源口径 | N预算作为实验因子，档位60/100/150/200；Ω上限按场景固定为"全部飞机按0.5°锚点铺满"的参考布局的Ω，与方法无关 |
| 静态指标 | 峰值请求（主指标，飞机当量）、最忙10%波束平均请求、全束CV、实际N、Ω、分段耗时（初始解／细调／核验／总计） |
| 动态指标 | 上述指标的时间平均与95分位；重配置代价：换束飞机比例（两帧都在场且归属改变的飞机数／两帧共有飞机数）、波束增删数、中心移动超过0.1°的波束数、宽度变化超过0.05°的波束数；每帧耗时 |
| 不做的事 | 不算干扰、SI、SGM；不删飞机、不改请求；不以CV单项排名 |

一句话：第一阶段只回答"波束怎么摆、每架飞机归谁"，评价是"最忙的波束有多忙、多用了几个波束、花了多少时间"，动态时再加一条"相邻时刻改了多少"。

## 6. 块A：非学习骨架定型与底线

目标：拿到唯一的、可部署的第一阶段骨架，知道它离底线多远，据此决定静态学习是否还值得做。全部为CPU计算。

### A0 几何约束审计（1天）

读取已归档的SH-C、RULE+D5、R04布局，统计违反最小中心间隔规则的波束对比例和重叠程度，用来判断第3.3节的规则是温和约束还是会改变问题。结果只用于冻结定义。

### A1 同景正面对照（3天）

| 臂 | 组合说明 | 来源 |
| --- | --- | --- |
| A1-1 SH-C | 可变束数强顺序结构重构 | 报告23、28（`coverage/ai_search_r5`） |
| A1-2 RULE+D5 | 规则分组后几何修补 | 报告20、21（`coverage/ai_search_r4`） |
| A1-3 R04 | 热点拆分与轻载合并，改为包络宽度 | 报告08（`coverage/variable_design.py`） |
| A1-4 JOINT | 多波束联合重分，接几何修补 | 报告11（`coverage/geoload`） |
| A1-5 SH-C(0.5°) | 同A1-1但宽度固定0.5° | 宽度可变值多少的消融 |

24个开发场景、四档N预算、同一Ω上限和同一间隔规则下运行，报告全部静态指标。选骨架的规则先定好：先比峰值均值，差距小于1飞机当量算平手，再依次比最忙10%均值、CV、耗时。选出的骨架记为**S1-BB**，后面所有块都用它。

### A2 底线与差距（1周）

对24个开发场景、每档N预算算两层底线：（1）平均负载下界ceil(n/N)；（2）考虑几何覆盖的下界：以飞机位置为候选中心、三档宽度为候选足迹，建"最小化峰值"的整数规划，用HiGHS这类开源求解器限时120秒求解，取线性松弛界或分支定界下界，并保留预算内最好可行解；小场景可精确求解。输出每场景"骨架峰值减底线"（飞机当量）和三分类结论：已达底线／证明达不到更低／限时内不确定。

**判读规则。** 白天两层（≥1200架）的12个场景中，若骨架峰值与可证下界差距不超过2飞机当量的场景达到9个以上，判定"静态布局改进空间小"，关闭静态学习（A4不做），论文写"规则已接近可证下界"；否则进入A3。

### A3 预算—质量前沿（3天）

把骨架的搜索预算放大到3倍和10倍（更多重启、更大邻域、模拟退火式接受），在同一批场景上画"算力—峰值"曲线。若10倍预算能把A2的差距缩小一半以上，差距来自搜索不足而不是信息不足，静态学习就只能以"同质量少算力"立论。这条曲线也是以后任何学习方法的尺子：学习方法的点必须落在曲线左下方才算有贡献。

### A4 条件性静态学习调度（1轮，只在A2判有空间且A3未闭合差距时做）

按[方案33](../../第一阶段/方案/33_非学习骨架与学习调度的分层优化实验设计.md)的分工做一轮简化版：骨架给合法布局和有限邻域，小模型决定下一步在哪片区域花求解预算，同一后端执行。保留方案33的M（学习）、H（锁定强规则）、R（固定随机）三臂与两条费用轨；门槛改为"相对H峰值平均降低不少于1飞机当量，95%区间不含0，3个种子均非劣"。只做一轮，不通过就关闭并作为论文负结果。

## 7. 块B：相邻时刻的增量重配置

### 7.1 为什么学习在这里有优势

静态快照上规则知道一切；连续时刻上有两样东西规则天然不擅长。一是**预判**：飞机有地速和航向，30到60秒后的位置能外推，热点会移动，哪些波束很快会超载可以提前看出来。二是**权衡**：每帧都重新规划能得到最低峰值，但大量飞机要换束、波束频繁开关；完全不动又会让峰值失控。什么时候动、动哪片、动多大，是"一步步做决定、每步决定影响下一步局面"的问题，这正是开题把覆盖优化建模为马尔可夫决策过程的本意。

### 7.2 问题定义

每一帧t：已知上一帧布局L(t−1)、当前全部飞机位置、按地速航向外推60秒的位置。策略输出一组区域决策，由冻结的骨架算子执行，得到L(t)。目标是在整段序列上同时压低峰值和重配置代价：

每帧收益 r(t) ＝ −峰值(t)（飞机当量） − λ×代价(t)，代价(t) ＝ 换束飞机比例 ＋ 0.5×（波束增删数＋移动数）/N(t)。

λ取三档分别训练，得到一条"峰值—代价"折中曲线，而不是一个点。

动作沿用"规则执行、学习调度"的分工：策略只在候选区域（最忙的4个波束及其接触邻束）上选{保持、局部重分飞机、局部拆分或合并、整景重算}之一；几何合法性、覆盖检查和归属守恒由骨架算子保证。学习算法用现有PPO实现（`coverage/ppo.py`），小网络，3个种子，每种子训练预算不超过2000段序列回放。

| B0 逐帧全重算 | 每帧从头运行骨架S1-BB | 质量上限参照，代价最高 |
| B1 只修补 | 保留上一帧布局，只处理新进／离开飞机和失覆盖 | 代价下限参照，质量最差 |
| B2 规则滞回 | 峰值超过阈值θ或覆盖失效时，只对受影响区域运行骨架算子；θ在开发集三档中选一次 | 可部署的强规则："不到门槛不动，避免来回切换" |
| B2+ 规则滞回＋外推 | 同B2，但用同样的60秒外推位置判断阈值 | 把"预判信息"的功劳和"学习"的功劳分开 |
| B3 R12温启动 | 报告08的历史时序路线 | 历史参照 |
| B4 学习调度 | 7.2节的PPO策略，3种子×3档λ | 唯一主学习方法 |
| B4−外推 | 同B4但不给外推特征 | 消融：学习是否依赖预判 |

### 7.4 成功判据

主判据以B2+为对照，因为它拥有和学习同样的信息。在开发序列上，取与B2+重配置代价相当的学习臂（换束比例在B2+的±10%内，或按折中曲线插值），要求：时间平均峰值降低不少于1飞机当量，且不少于60%的序列更好，按日期和序列分块的自举95%区间不含0；3个种子各自非劣、均值达标。对偶判据：峰值非劣（不高于B2+加0.5当量）时，换束比例降低不少于25%。护栏：每帧全部飞机覆盖；每帧耗时中位数不超过B0；N和Ω不超过B0。开发集通过后，确认日期只跑一遍。

两种可能的结局都是可接受的论文结果：若B4只胜B2而不胜B2+，结论是"预判有用、学习本身无增量"，B2+成为第一阶段的动态方法，学习作负结果；若B4连B2也不胜，第一阶段的贡献写为"满足全覆盖的可变束数、可变宽度骨架＋可证底线＋滞回式动态重配置"。设计上不为学习留后门。

### 7.5 灵感来源

分工来自方案10第4.12节"相邻时刻的连续重配置"和方案14第29、30条（滚动规划、前帧温启动加切换门槛）中已核链接的文献；"学习决定在哪里花求解预算、求解器负责执行"见报告29第6节引用的Li等（Learning to Delegate, NeurIPS 2021）与Song等（学习型大邻域搜索, NeurIPS 2020）。它们提供分工依据，不提供可移植的性能数字。

## 8. 块C：三阶段连通评价

目标：回答"第一阶段负载更均衡，飞机最终得到的服务是否更好"，并用答案反过来定第一阶段的主指标。

做法：对24个开发场景和确认场景，取同一场景下**不同均衡程度**的多个合法布局（骨架在60/100/150/200束预算下的输出，加块B各臂在若干帧的输出），经已核验的三阶段接口（`shared_interface/contracts.py`）送入冻结的第二阶段按需求配槽的贪心和第三阶段SCA，不用任何学习模型，避免混入第二阶段的算法偏好。以原始飞机为分母报告每机需求满足率、全需求承载比例、最差10%飞机平均满足率，以及SI、SGM。

分析：同一场景内，看第一阶段各指标（峰值、最忙10%均值、CV、N、Ω）哪个和最终服务相关最强；若不是峰值，论文把主指标改为相关最强者并说明依据。同时回答"多用波束是否真的提高服务"，供N预算选择。前提：第二阶段物理模型须接受N≤200和0.3°到1.0°的宽度（W26起已用第一阶段几何产生器的真实宽度数据，接入前再核一次）。

## 9. 执行规程

1. **轮次上限。** 每块最多两轮：一轮主试验、一轮确认。加新变体前先写半页：上一轮为什么失败，属于报告29第9节四类原因中的哪一类，哪个检验能区分。
2. **效果量口径。** 门槛以飞机当量或比例表述，不用"5%"这类相对门；差距小于1飞机当量算平手。门槛在数据生成前写定。
3. **种子与统计。** 学习方法3个种子，规则方法1次；区间估计用日期分块自举，不把同一天的帧当独立样本。
4. **开发集分层。** 按飞机数分层、按预定帧序号规则抽，不再"每隔6帧"取夜间帧。
5. **报告模板。** 每块一份不超过6页的中文报告：问题、设置、一张主表（编号＋实验组合）、两到三张原始数据生成的图、结论、限制。回执、SHA、预算账只留在`outputs/`。
6. **正式任务仍经工作台发起、绑定冻结源码；工程资格样例限1组、独审限1次。**
7. **存储。** 序列数据约每天150 MB，布局与结果每块2 GB以内；准入前登记峰值空间，收尾清理可再生副本。
8. **定义不热改。** 问题定义、指标、N预算档、间隔规则一经确认不在实验中途改；要改就升版本并重跑受影响块。

## 14. 限制

- 第3节的底线是平均负载下界，没有考虑几何，可能偏松；这正是A2要补的。数字由两个CSV算术推算，分母、束数、峰值取原字段。
- 原始日包的地速与航向字段按readsb格式存在，但现有适配器`workbench/aviation.py`只读位置与高度，序列构造要小幅扩展。
- 第二阶段贪心与SCA对N≤200、宽度0.3°到1.0°的支持以方案26以来的实验为据，正式接入前再核一次。
- 预算与时间是估算，实际以工作台准入和运行清单为准。

## 15. 执行版调整（v1.1，2026-10-17用户批准执行后）

用户批准在20654执行，四项待定按推荐默认：采纳最小中心间隔规则；块B用20654的GPU与CPU；接受A2判读规则；确认日用本地已有、第一阶段从未用过的2024-01-15和2024-01-18，不另下载3月数据。实现规格见[03 给Codex的实现说明](03_S1-FIX给Codex的实现说明.md)。相对前文的改动：

- **骨架改为新写的FLOW-AO**：给定波束中心后，"哪架飞机归哪个波束"用网络流精确求解，再交替做重定中心、拆最忙束、并最闲束。历史SH-C和R8的代码层层套着身份校验与预算账，不再包装重跑；改为在它们原来的场景上、用不超过它们的波束数，与已归档的逐场景结果直接对照（HIST12、HIST20）。
- **Ω只报告不约束**：宽度由成员包络决定、上限1.0°，真正起约束的资源是波束数。
- **间隔规则的精确写法**：任意两束中心夹角不小于两者宽度较大者的一半，即任一束中心都不落入另一束足迹内。按此规则，一个点最多被约7个波束同时覆盖，"无限堆叠窄波束"被排除。
- **块B对照**：历史R12温启动不再重跑，换成"每k帧全重算"（B3）；PPO每帧在5个动作中选一个（只修补、两档局部修复、整景修复、全重算）。
- **A4静态学习分支本次不做**，等A2底线结果出来再决定。
