# 改进式T-SAC 换 Transformer 与网络规模对照方案

来源：cc

## 要回答的问题

改进式T-SAC（I0／L1：从一套合法方案出发，每步从候选菜单里挑一个修改）现在用的是多层感知机，名字里的"T"没有落实。把它换成 Transformer，以及换成别的网络结构、改变参数量，满足率有没有差别？

## 怎么比

只换网络，其余与 S2-FIX 的 L1 完全一致：同一训练集（576 景）、同一候选菜单和奖励（刷新历史最好时给 100×满足率提升）、γ=1、固定温度 0.01、批量 128、回放 2 万、热身 2000 步、每步一次更新、每景 32 次试算。为省算力，统一训练 8 万步（L1 原来约 20 万步，但它的训练曲线在 3—4 万步后就基本走平），只按步数停。

参加比较的 11 种网络（参数量指策略网络，两个评论家同结构）：

| 编号 | 结构 | 说明 | 参数量 |
| --- | --- | --- | ---: |
| mlp64 / mlp128 / mlp256 / mlp512 | 多层感知机 | 整个状态（200 束×14 特征＋12 个全局量）拉平后过两层；mlp128 就是原 L1 | 19 万 / 40 万 / 89 万 / 211 万 |
| ds128p | DeepSets | 每束单独编码后取平均和最大值汇总，波束之间不交互；加"指针" | 12 万 |
| tf64L2 / tf128L2 | Transformer | 每束一个令牌，外加一个全局令牌，2 层自注意力；用全局令牌的输出代表整套方案 | 11 万 / 44 万 |
| tf64L2p / tf128L2p | Transformer＋指针 | 同上，再把候选修改涉及的那几束的编码取出来一起打分 | 12 万 / 45 万 |
| tf128L4p | Transformer＋指针 | 4 层（看深度） | 85 万 |
| tf256L4p | Transformer＋指针 | 256 维 4 层（看规模） | 337 万 |

"指针"的意思：候选修改改的是哪几束，就直接把这几束在编码器里的表示拿来打分，而不是只看一个笼统的全局摘要。

设计上的几组对照：
- 同参数量看结构：mlp128（40 万）对 tf128L2/tf128L2p（44—45 万）；
- 看规模：mlp64→mlp512，tf64→tf128→tf256；
- 看自注意力：ds128p 对 tf128L2p（都有指针，前者波束间不交互）；
- 看指针：tf64L2 对 tf64L2p，tf128L2 对 tf128L2p。

## 三个阶段

- **A（已开跑）：** 贪心起点，11 种网络 × 3 个种子，各 8 万步，四张卡并行。用贪心起点是因为这里学习的提升空间最大（L1 比贪心高约 2.5 点），网络之间的差别最容易看出来。
- **B：** 全部 33 个模型在开发集 20 景上评价（每模型每景 3 次抽样，种子与 S2-FIX 相同），先看功率细调（SCA）前的满足率；每类结构选代表，连同 mlp128 在确认集 88 景上评价并接 SCA。
- **C：** 选出的最好 Transformer 与 mlp128 从分散摆放规则起点重训（报告21的 X1＋X3），看换起点后学习还能不能拉开差距。

判据：开发集上相对 mlp128 的逐景配对差，Transformer 高 ≥0.2 个百分点且区间不含 0 算"有用"；规模之间同样比较。结论如实写，包括"没有差别"。

## 实现

分支 `cc/i0-network-study`（从 s2fix 分出），新增 `sac_improvement/networks.py`（三种结构与指针）、`s2fix/i0net.py`（训练与评价）、`s2fix/greedy.py` 里的 `spread_allocation`（分散摆放规则），默认配置下与原 L1 完全一致（原 L1 权重可直接加载，单元测试 `tests/test_i0net.py`）。

为了算得动，有两处工程处理：
- Transformer／DeepSets 的编码部分在 GPU 上用 bf16 混合精度，打分头仍用 fp32。本机实测，大 Transformer 每次更新从 238 毫秒降到 115 毫秒。
- 断点只存网络权重，不存 2 万条回放（原 L1 每个断点约 700 MB）。

数据用远端 S2-FIX 原数据，只读。
