## 1. 这一轮要回答什么

**把单机需求放大到现在的4倍、让功率、频谱和单束容量都吃紧之后，第二阶段的学习方法比贪心规则、比同样预算的强搜索还能多拿到多少需求满足率；三个阶段连起来，每架飞机最终得到什么服务。**

为什么现在做这个：第一阶段已经定型（新骨架FLOW-AO在静态布局上达到可证下界，动态用"每分钟轻量修复"一条规则），第三阶段的SCA功率优化稳定可用，论文里学习的主线和最缺的端到端结果表都在第二阶段。而W32刚证明，在现有需求下第二阶段已经饱和：贪心的需求满足率98.7%，各方法只在供需匹配和功率上有差别。满功率下贪心只用三成频率槽就能提供需求的两倍容量，SCA实际只用了一成功率。不把需求抬上去，第二阶段的实验说明不了算法好坏。

## 3. 第一阶段前置：FLOW-AO v2

第一阶段的算法和布局与需求值无关，但需求值决定了"一个波束最多能装几架飞机"。链路模型v2下单束上限约1.1 Gbps，按86.4 Mbps算是13架。白天伦敦上空0.3°范围内有约240架飞机，要放19个以上波束才装得下，而"中心不落入彼此足迹"的间隔规则在一个点上最多放7个。所以第一阶段要做三处改动，由Codex在S1-FIX代码上改，预计一天：

1. **每束飞机数上限成为硬约束。** 上限＝单束容量上限÷单机请求，向下取整；网络流里每个波束到汇的容量从"峰值"改为min(峰值, 上限)。
2. **热点叠放豁免。** 间隔规则照旧，但当某一带在满足上限的前提下放不下足够波束时，允许在那里把波束叠起来（中心可以重合或只差一点）。叠起来的波束同频会互相干扰，这正是第二阶段要处理的事：把它们分到不同极化，或放进同一频率组用互不重叠的频率槽（同极化的不同组会互相干扰）。布局输出时标出哪些波束属于同一叠放簇，供第二阶段贪心使用。
3. **目标改为：满足上限的前提下，波束尽量窄。** 字典序为"全部波束不超上限 → 用满波束预算 → 最忙波束最低 → 宽度之和最小"。

**产出三套布局**（飞机集合、ID、位置与W32完全相同，只换归属）：

| 需求档 | 单束上限（架） | 用途 |
| --- | ---: | --- |
| 86.4 Mbps（主） | 13 | 训练576景、开发20景、确认88景 |
| 43.2 Mbps | 26 | 只用于评价 |
| 21.6 Mbps | 52（不约束，等于原FLOW-AO） | 只用于评价，与W32衔接 |

波束预算统一150束（白天按13架上限至少需要131束；200束留作鲁棒性评价）。生成后核验：每架飞机恰归一束、总需求守恒、宽度0.3°到1.0°、每束不超上限、叠放簇登记完整。

## 4. 第二阶段对照臂

第二阶段的任务：给每个波束选频率组、频率起点和槽数（1到10），初始功率由规则给、最终功率由第三阶段SCA定。学习只负责离散的频率结构，这是2026-10-09定下的分工。

两个学习方法先用一句话说清。**直出T-SAC**是历史主线：模型从空白开始，逐个波束决定频率起点、槽数和功率档位，一次性直接给出完整分配。**I0**（名字来自2026-10-09方案19的编号，I指"改进"，0是第一条改进路线）走另一条路：先让贪心规则给出一份合法分配，模型再一步一步改它，每步从一份候选修改菜单里挑一个，用真实物理算一次效果，最多改32步，始终保留过程中最好的一版作为输出；功率不由它学，交给规则和SCA。它是第二阶段唯一在需求满足率上稳定胜过贪心的学习结果。

| 编号 | 实验组合 | 作用 |
| --- | --- | --- |
| G1 | **容量感知贪心**：按需求从大到小，选同极化干扰最小的组；槽数按"估计单槽容量"配，超额时组内按需求比例缩减；起点取与同极化其他组重叠最少处；功率按需求比例 | 主对照。是S1-FIX块C的贪心升级版，槽数不再按固定100 Mbps一槽，叠放簇内的波束优先分到不同极化，同极化的放进同一频率组（组内频率槽互斥、互不干扰）；同极化的不同组会互相干扰，不能这样分 |
| R | 随机局部搜索：G1起点，同一动作菜单，32次决策/32次探测，随机选候选，每景3次 | 排除"只要搜一搜就能好"的解释 |
| S1 | **贪心＋禁忌搜索**：同起点、同菜单、同32/32预算，禁止最近8步的逆动作 | 同预算的强搜索，学习必须胜过它才算有贡献 |
| S2 | 贪心＋禁忌搜索，预算放大10倍（320/320） | 质量—算力前沿；学习若用32探测达到它的质量，算"同质量少探测" |
| **L1** | **I0改进SAC**：G1起点，学习在候选菜单里选下一步（移块、边界调整、同组交换、2到4束窗口重划、回退、停止，**新增两束交换频率组**），32/32预算，3个训练种子 | T-SAC 主线的改进式用法，本轮主学习臂之一。历史上它在880景上比贪心高3.26个百分点、比规则搜索高1.75，是第二阶段站得住的正面结果 |
| L2 | **直出T-SAC**：W32最好的配置P01-M1，功率档位为0.5、5、10、…、50 W共11档，带余量摘要，在新需求与新链路模型下重训，3个种子 | T-SAC 主线在已发表协议下的直出式；与L1按同一判据判定，谁过谁当本轮主学习臂（论文主方法始终是 T-SAC）。W31试过把0.5到50 W全按0.5 W一档细分（100档），比只加一个0.5 W选项没有额外收益，所以不用 |
| L3 | L2的Transformer编码器换成参数量相近的多层感知机，其余与L2相同，3个种子 | 回答开题"Transformer是否必要"。I0本身用的是多层感知机，没有Transformer，所以消融放在T-SAC上；无条件执行 |
| 历史 | W32的P01-M1模型在21.6 Mbps档直接评价 | 与报告24衔接，不重训 |

所有方法的候选生成规则、合法性检查、输出保护（直接满足率、供需匹配、基本服务三项不退步才替换当前最好解）、停止条件完全相同，只有"谁来选下一步"不同。

## 5. 第三阶段与端到端评价

每个方法的输出都接同一套SCA（第三阶段的连续功率优化，加每束50 W上限），再按链路模型v2算每架飞机的服务。

**主指标**：业务量加权需求满足率，即全部飞机实际承载之和÷总需求。请求相同时它等于飞机平均满足率。按"SCA前（规则功率）"和"SCA后"两套都报，论文以SCA后为准。

**护栏**：每景约束全部合法；总功率不高于G1的110%；单景耗时不高于S2。

**诊断**：最差10%飞机的平均满足率、满足率≥0.9的飞机比例、波束平均满足率（历史口径SI）、供需匹配程度SGM、总功率、用槽数、同极化重叠槽数、单景分段耗时（初解／搜索或推理／SCA／总计）。

**需求压力档**：训练只在86.4 Mbps上做；用训练好的模型在21.6和43.2两档的布局上直接评价，与G1、S1对照。这是鲁棒性检查，不是主结果（W32已表明模型对输入分布敏感）。
