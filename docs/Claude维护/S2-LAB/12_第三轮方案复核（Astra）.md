# S2-LAB 第三轮方案复核（Astra）
来源：codex（GPT-6 Astra）。复核日期：2026-10-27。对象：[11_第三轮方案](<D:/paper-s2lab/docs/Claude维护/S2-LAB/11_第三轮方案.md>)。共 **22 条意见**。

## 总体判断

**方向值得做，但当前草案需要实质性修改，尚不足以直接实现后铺开 60 个运行。** 最值得优先验证的是完整动作双 Q、合法落位、适度加宽，以及让模型看懂“满足需求需要多少功率”；第二轮原始数据支持这些问题值得追查。自回归 SAC 和连续功率都可实现，但草案尚未把联合概率、评论家、熵、预算预留和比较对象写清，照现有文字实施会混入多项变化。“后续同极化邻居”的极化尚未确定、“所需功率”可能物理上不存在、续训判据受终点重复日志影响，这几项必须在开跑前解决。建议先做少量能分清原因的核心对照，并将同口径 PPO/DQN/MLP 对照提前，组合版与新日期测试放在选择规则冻结之后。

## 逐条意见

### 1. 先冻结可复现的基线，不能只写“14 令牌＋delta”

**问题。** [方案：7—10 行](<D:/paper-s2lab/docs/Claude维护/S2-LAB/11_第三轮方案.md#L7>)的名称不足以保证基线重跑时保持原算法；尤其不能把新增的历史双 Q 或合法窗口规则顺手变成所有组默认值。

**证据或理由。** 第二轮实际[基线配置：6—35 行](<D:/paper/outputs/experiments/s2lab_round2_20261025/account_B/runs2/t14-in-delta-s1/config.json#L6>)是 I/N 干扰编码、宽 128、2 层、8 头、FFN 512、贪心定组、固定温度 0.01、γ=0.99，以及“求期望后取小”。[环境：290—298、372—383 行](<D:/paper-s2lab/src/satellite_rl/s2lab/env.py#L290>)仍允许申请槽数在执行时截短。独立复算三个种子的确认 CSV，SGM 为 0.866/0.856/0.845，均值 0.856，与[第二轮汇总](<D:/paper/outputs/experiments/s2lab_round2_20261025/report/numbers.json#L355>)一致。

**影响。** 改了默认值再重跑，得到的是新基线，无法知道单项改善来自何处。

**具体改法。** 增加一张“冻结配置表”，逐项列出状态字段、归一化、动作/执行语义、组规则、双 Q 运算顺序、功率菜单、学习率、温度、更新次数、数据划分和选模。原基线记为 R0，所有新组明确写“相对哪个父组改什么”。先以固定输入核新代码的 R0 前向、掩码、执行和目标值与第二轮一致，再重跑三种子。

### 2. 自回归策略可行，但评论家不必与策略同样分解；功率仅条件于槽数是有意保留的限制

**问题。** [方案：14—19 行](<D:/paper-s2lab/docs/Claude维护/S2-LAB/11_第三轮方案.md#L14>)一方面称“后一个看得到前一个”，另一方面写成 π(c)π(x|c)π(p|c)，功率并未看到刚选的起点 x；“评论家也按同样条件结构拆开”则没有给出明确的 Q 定义。

**证据或理由。** 下文用 o 表示当前观测、x 表示组与起点。π(c|o)π(x|o,c)π(p|o,c)是合法的受限策略，但不同位置的路径增益和入向干扰不同，见[容量计算：209—218 行](<D:/paper-s2lab/src/satellite_rl/s2lab/env.py#L209>)。当前评论家是 `Q_c(o,c)+Q_x(o,x)+Q_p(o,p)`，见[动作 Q 聚合：185—188 行](<D:/paper-s2lab/src/satellite_rl/s2lab/agents.py#L185>)。换成自回归策略并不要求同时换评论家；相反，条件加性 `Q_c(o,c)+Q_x(o,c,x)+Q_p(o,c,p)`仍无法表达固定 c 时的位置—功率交互。

**影响。** 仅补“条件结构”可能被实现成三个各自预测同一回报的头再相加，或者把策略收益与更强评论家的收益混在一起。

**具体改法。** 第一项自回归实验可保留现有加性 Q，只增加演员对 c 的条件输入及合法起点掩码，明确它是“槽数条件化版本”。若要实现完整顺序依赖，写成 `π(c|o)π(x|o,c)π(p|o,c,x)`，并单列对应对照。增强评论家时明确输出的是一个完整动作 Q：可以用标量 `Q(o,c,x,p)`，或含 `Q_p(o,c,x,p)` 的条件加性结构；训练完整动作的总 Q，不给三个头分别套同一个完整 Bellman 目标。

### 3. 历史双 Q 要在完整动作上取小；自回归期望和熵必须按条件概率加权

**问题。** [方案：19、29 行](<D:/paper-s2lab/docs/Claude维护/S2-LAB/11_第三轮方案.md#L19>)的方向正确，但不足以指导实现演员损失、目标值和条件熵，计算量估计也过于笼统。

**证据或理由。** 当前代码是 `min(EQ1,EQ2)`，见[目标值与演员：177—205 行](<D:/paper-s2lab/src/satellite_rl/s2lab/agents.py#L177>)；[历史共享函数：5—18 行](<D:/paper-s2lab/src/satellite_rl/agents/sac_math.py#L5>)与[历史 power30：191—217 行](<D:/paper-s2lab/src/satellite_rl/power30/agent.py#L191>)在完整动作上取小。两个等概率动作，Q1=(0,10)、Q2=(10,0)，前者给 5，后者给 0。本次将历史共享函数与显式枚举比较，值和概率梯度误差均约 2×10⁻¹⁶，见[数学核验](<D:/paper/outputs/experiments/s2lab_round2_20261025/astra_review/round3_plan/checks.json>)。

**影响。** 若仍先对每头取小，或先求期望再取小，就没有做成计划中的历史对照；不加权地相加所有条件分支的熵，会人为放大探索奖励。

**具体改法。** 对完整动作 a=(c,x,p)，写清：

- 联合概率 `w(a|o)=π_c(c|o)π_x(x|o,c)π_p(p|o,c[,x])`；`log w` 是这三个实际条件概率的对数之和。
- 历史目标 `V(o′)=Σ_a w(a|o′)[min(Q1_t(o′,a),Q2_t(o′,a))−α log w(a|o′)]`，`y=r+γ(1−done)V(o′)`。
- 演员损失 `E_o Σ_a w(a|o)[α log w(a|o)−min(Q1(o,a),Q2(o,a))]`；离散概率保留梯度，评论家参数不参与这一步更新。
- 熵为 `H(c)+E_c H(x|c)+E_{c,x}H(p|c,x)`；功率只条件于 c 时，最后一项化为 `E_c H(p|c)`。

先在 R0 上仅替换取小顺序，保留原独立策略、加性 Q 与掩码，才是单因素历史双 Q 对照。条件策略不能直接把边缘概率塞进只支持三个独立概率的旧函数。

计算上，未裁去禁用组时一个 `[256,800,10,13]` float32 联合张量约 **102 MiB**，还未计双 Q、概率及反向中间量；14 令牌每次只允许一个组，可精确取其 100 个位置，降至约 **13 MiB/张量**，再沿起点分块。每个网络的编码器对同一观测编码一次即可，演员、两个评论家及两个目标网络仍各有编码器。实现可接受，但需实测更新耗时和峰值显存，不能预先承诺“代价不大”。

### 4. 条件掩码必须同时满足完整窗口和后续预留，不能只去掉截断

**问题。** [方案：16 行](<D:/paper-s2lab/docs/Claude维护/S2-LAB/11_第三轮方案.md#L16>)只说窗口连续空闲，没有完整规定槽数掩码、预算预留和无合法动作时的语义。

**证据或理由。** [当前槽数上限：247—255 行](<D:/paper-s2lab/src/satellite_rl/s2lab/env.py#L247>)同时受允许组最长空闲段与“全部组空闲槽减后续束数”约束；[功率掩码：286—298 行](<D:/paper-s2lab/src/satellite_rl/s2lab/env.py#L286>)减去每个后续波束 0.5 W。当前贪心定组是每步动态决定的，[265—272 行](<D:/paper-s2lab/src/satellite_rl/s2lab/env.py#L265>)没有预先固定全部未来组。

**影响。** 只要求窗口完整可能提前耗尽总槽位或功率；沿用“无合法动作就放开索引 0”还会把失败伪装成合法样本。

**具体改法。** 先按原规则定本束组 g，再令 `c≤min(10,本组最长空闲段,全组空闲槽数−后续束数)`；仅对存在合法位置的 c 分配概率。给定 c 后，x 掩码只保留本组完整 c 槽窗口；B 组在这些合法窗口中取至多 8 个最低干扰者。功率独立使用原预留上限。按当前动态定组语义，总量预留每束一槽是合适起点；若改成预先固定未来组，则须改为逐组预留，这是另一项变化。训练采样、热身随机动作、目标期望、确定性评价共用这些规则。记录申请与实际槽数/瓦数，正常合法路径要求二者相等；终止样本不计算有效 bootstrap。

### 5. 拆成三个小步并非“标准 SAC 不用改”，会改变折扣、熵与步数口径

**问题。** [方案：21 行](<D:/paper-s2lab/docs/Claude维护/S2-LAB/11_第三轮方案.md#L21>)把代价归为回合长度增加，漏掉了算法目标变化。

**证据或理由。** 当前[γ=0.99 的更新](<D:/paper-s2lab/src/satellite_rl/s2lab/agents.py#L184>)每个波束只折扣一次。若三个小步都照用 0.99，每束间折扣变成 0.99³≈0.9703，第三小步奖励相对第一小步也被额外折扣；回放容量、热身和更新量的单位随之变化。

**影响。** 三小步版与一次完整动作版的结果不再只是实现方式对比。

**具体改法。** 仍推荐一次环境动作的自回归实现。若保留三小步备选，状态加入阶段编号与已选动作，内部两次转换折扣设为 1，跨束转换为原 γ，前两步物理状态不变且奖励为 0；明确各阶段熵的计入方式。按“完整波束决策数”对齐交互预算，另报小步样本数与更新次数。这不是本轮必加的训练组。

### 6. 增加一个“只保证完整窗口”的桥接组，才能解释自回归收益

**问题。** [方案：8、63 行](<D:/paper-s2lab/docs/Claude维护/S2-LAB/11_第三轮方案.md#L8>)的“一次只改一样”与自回归组实际同时改变合法性、策略条件依赖、可能的 Q 结构和计算量不一致。

**证据或理由。** 当前[三个动作头独立采样](<D:/paper-s2lab/src/satellite_rl/s2lab/agents.py#L75>)，槽数执行时会被[截短](<D:/paper-s2lab/src/satellite_rl/s2lab/env.py#L372>)。第二轮 B 组的 0.823 对 12 令牌基线 0.835，混有这一执行差异；不能直接用于第三轮自回归 B 的原因解释。

**影响。** 新组提高后无法说清是“终于按申请数量执行”还是“学到了条件关系”。

**具体改法。** 最少形成三组链：R0 原基线；L 组保持原头参数化和 Q，只先抽 c、对原起点 logits 应用 c 条件合法掩码、功率头仍独立；A 组在 L 基础上把 c 显式送入起点和功率头。L 已因掩码产生条件概率，不能仍把原三个独立头的 softmax 当作实际联合分布的边缘概率。若保留加性 Q 和 R0 的取小顺序，可先从条件分布算出正确边缘再求各 Q 期望；熵仍须按条件链计算。L−R0 测合法性/动作分布重构的整体收益，A−L 测学习条件依赖的增益。B 与 A 比较；若还增强 Q，须另加 Q 匹配对照，或把结果明确称为“动作与评论家组合改动”。确定性评价统一逐级 argmax；若采用联合最大概率动作或搜索，也须单独声明。

### 7. 混合动作 SAC 需要完整动作评论家；连续演员的 Q 路径不能被 detach

**问题。** [方案：54 行](<D:/paper-s2lab/docs/Claude维护/S2-LAB/11_第三轮方案.md#L54>)只有一句“功率作为输入、重参数化”，尚缺可执行的目标与梯度定义。

**证据或理由。** 当前[SAC 演员更新：193—205 行](<D:/paper-s2lab/src/satellite_rl/s2lab/agents.py#L193>)将离散 Q 输出全部 detach，这是离散枚举路径的写法。若原样搬到连续版，演员无法通过 `Q(o,c,x,p)` 对 p 求梯度；仅保留一个与位置无关的功率 Q 头，也学不到在哪放时该给多少功率。

**影响。** 代码能运行，连续功率却可能只受熵推动，或者学到错误的资源交互。

**具体改法。** 取 d=(c,x)，双评论家输出标量 `Q_i(o,d,p)`，连续策略为 `p=fθ(o,d,ε)`；对合法离散 d 精确求和，对每个 d 的连续变量做重参数化采样。目标和演员都使用 `min(Q1,Q2)`，并分别减/加 `α_d log π_d(d|o)` 与 `α_p log π_p(p|o,d)`。演员更新时冻结评论家参数，但保留 Q 对 p 的导数；下一状态目标在无梯度上下文中计算。先测小动作空间的枚举/采样一致性和有限差分梯度，再测实际批量开销。它是可行的混合 SAC；不必依赖某一种特定自回归代码，只需要离散联合分布和正确的条件功率策略。

### 8. 连续功率须统一预留、熵坐标及离散对照；旧 100 档结果不能直接充当该对照

**问题。** [方案：54—56 行](<D:/paper-s2lab/docs/Claude维护/S2-LAB/11_第三轮方案.md#L54>)没有说明“剩余可用预算”是否扣除预留，并把第二轮 100 档负结果列为参照。

**证据或理由。** [功率 100 档配置：81—88 行](<D:/paper-s2lab/src/satellite_rl/s2lab/matrix.py#L81>)基于 **12 令牌＋独立动作＋原加性 Q**。本次复算其 SGM 为 0.822，相对同口径 12 令牌 0.835 低 0.013；这不是相对 14 令牌自回归版的差。现有[功率预留](<D:/paper-s2lab/src/satellite_rl/s2lab/env.py#L286>)为每个后续波束 0.5 W。

**影响。** 连续版若不预留，或同时更换策略条件和评论家，成绩变化无法归于连续化；熵若以瓦为单位计算，还会随预算区间宽度变化。

**具体改法。** 明确 `p_min=0.5 W`，`p_max=min(50 W,2000−已用功率−0.5×后续束数)`，采用有界变换直接落入区间，不在执行时硬截断。区间退化到单点时作确定性动作并停止该样本的连续熵更新；区间不足最低档应在合法性测试中暴露。推荐在归一化变量 u∈(0,1) 上定义熵，包含 sigmoid/tanh 变换的 Jacobian；若改用物理功率密度，再计 `−log(p_max−p_min)`，目标熵也必须一致。连续目标熵不得照搬分类头的 `κ log K`。

主比较用**同 14 令牌、同离散条件结构、同预算规则、同完整动作 Q 输入结构**的 13 档与连续版；离散版枚举档位，连续版采样功率。若要分清“连续参数化”与“档位变细”，再加同底座 100 档。旧 100 档保留背景证据，不能充当新组。功率条件于 c,x 若仅在连续版启用，必须给离散参照也启用。离散熵与连续微分熵没有天然相同的数值尺度，需冻结各自熵定义并给相同有限调参预算；结论应称“功率策略参数化及其学习配套的比较”，不能把差值全部归给可行功率值变多。

### 9. “槽数 1—10 各需多少瓦”有些情况下没有有限答案，必须给出可达性标志

**问题。** [方案：39 行](<D:/paper-s2lab/docs/Claude维护/S2-LAB/11_第三轮方案.md#L39>)默认十种槽数都能算出一个满足需求的功率，并仅写“除以 50 W”。

**证据或理由。** [物理上限：26、33、37 行](<D:/paper-s2lab/src/satellite_rl/s2lab/physics.py#L26>)决定一槽最多 137.5 Mbps、十槽最多 1375 Mbps；一束若有 26 架飞机、每机 80 Mbps，则需 2080 Mbps，十槽也无法满足。即使未到频谱效率上限，计算功率仍可能超过 50 W。当前[贪心反算：63—65 行](<D:/paper-s2lab/src/satellite_rl/s2lab/rules.py#L63>)先截效率再算功率，这个结果不能直接改名为“保证满足需求的功率”。

**影响。** 直接反算会出现极大值；截成 50 W 又会把“刚好要 50 W”和“无论多少瓦都不行”混为一谈。

**具体改法。** 第一版定义为**无干扰、平均路径增益下的所需整束功率参考**。令 `a=实现系数×有用信号增益×平均路径增益/噪声`，当 `D/(c×25 MHz)≤5.5` 时，`P_req(c)=c/a×[2^(D/(c×25 MHz))−1]`；否则标为频谱不可达。输入十个经过有界或对数缩放的功率值，同时给出不可达/超过单束上限标志，不能存 inf；当前预算是否足够可由独立预算量判断。起点尚未选择，不能把这个平均、无干扰参考说成实际窗口下的保证值。特征须保持单调关系：同链路同槽数下需求增大，需求功率不下降。

### 10. “功率份额”是已有总量的显式组合，不是全新的信息，且应对齐贪心实际公式

**问题。** [方案：40 行](<D:/paper-s2lab/docs/Claude维护/S2-LAB/11_第三轮方案.md#L40>)的文字没有明确分母包含哪些束，也未包含贪心的预留及 50 W 上限。

**证据或理由。** [贪心：46—51 行](<D:/paper-s2lab/src/satellite_rl/s2lab/rules.py#L46>)用“含本束的剩余总需求”，分子先扣后续 0.5 W 预留，并将份额限制为 50 W。14 令牌已经输入本束需求、剩余功率比例和剩余总需求，见[观测：305—318 行](<D:/paper-s2lab/src/satellite_rl/s2lab/env.py#L305>)；剩余束数和 N 并未直接完整送入 14 令牌编码器。

**影响。** 得分改善可能来自把乘除运算提前算好，或补上预留所需的束数信息；不能全部解释为补齐了未知预算信息。

**具体改法。** 采用与贪心同式的 `min(50,B_available×D_current/D_remaining)`，单位 W，除以 50 后输入；分母包含本束。报告称“显式按需份额特征”。同时明确是否提供剩余束数/预算预留量，避免让它们暗中随本组改变。所需功率回答“物理上需要多少”，份额回答“当前预算愿意给多少”，两者都保留单项对照是有意义的。

### 11. 出向干扰与信噪比必须明确接收方向、每槽功率单位和聚合方式

**问题。** [方案：41—42 行](<D:/paper-s2lab/docs/Claude维护/S2-LAB/11_第三轮方案.md#L41>)没有规定多个受害波束如何聚合，“每瓦”的口径也可能被误解为整束 1 W。

**证据或理由。** [耦合定义：102—104 行](<D:/paper-s2lab/src/satellite_rl/s2lab/physics.py#L102>)是接收 i←发射 j，路径增益属于接收端；[动作执行：392—397 行](<D:/paper-s2lab/src/satellite_rl/s2lab/env.py#L392>)将整束功率均摊到 c 个槽。因此本束每槽 1 W 对邻束 j 的影响，应乘邻束 j 的路径增益，而不是当前束的；整束 P W 的实际每槽影响再乘 P/c。现有物理还包含 20 dB 交叉极化泄漏。

**影响。** 方向或单位错误会重演第一轮耦合特征失真；只说“干扰大小”也不能说明对业务损失有多大。

**具体改法。** 出向通道建议定义为“本束在该槽发射 **1 W 每槽功率** 时，对当前已分配、正在使用该槽的其它束新增 I/N 的总和”；明确是否包含异极化的 0.01 系数，同组因合法掩码不能共槽。总和是工程摘要，不是精确容量损失。另两个通道定义为 `SNR_perW=η sig_i path_i(s)/N0` 与 `SINR_perW=η sig_i path_i(s)/(N0+I_i(s))`，实际值乘 P/c；“扣掉干扰”应改为“把干扰加进分母”。规定 dB 或 log1p 映射及训练数据确定的尺度，检查非饱和值比例。若二者与已有 I/N 重复较多，明确这是物理特征显式化的对照。

### 12. W30 的“余量摘要”并非“还差多少速率”，方案需要二选一并明确名称

**问题。** [方案：43 行](<D:/paper-s2lab/docs/Claude维护/S2-LAB/11_第三轮方案.md#L43>)把历史 W30 思路写成每槽离满足需求还差多少，但历史实际公式不同。

**证据或理由。** [W30：88—102 行](<D:/paper-s2lab/src/satellite_rl/power30/environment.py#L88>)计算的是 `log1p(Σ_j exp(−|C_j/D_j−1|)×kappa_j/(noise+interference_j))`，只累加同极化异组的已分配束；它是按接近需求程度加权的干扰敏感度，不是速率余量。也不能认为“已过供的邻居一定不会受伤”：损失达到其余量后仍会不足，且 SGM 在过供区可能因容量下降而提高。

**影响。** 按文字实现与按历史函数移植会产生两个不同实验，可能误称复现。

**具体改法。** 推荐本轮明确选择“已放邻束的干扰敏感度摘要”，按上述公式适配 S2-LAB 的耦合、接收路径和噪声，并写清同/异极化范围和归一化。如果坚持真正余量，则先定义每束 `m_j=(C_j−D_j)/D_j`，再规定每槽按哪些占用邻束、什么权重聚合，保留余量正负和空槽标志；不要把聚合量叫作可直接扣除的容许干扰。只用动作前容量与已分配集合，不能读取本步执行后的量。

### 13. 后续波束信息本身不泄漏，但“后续同极化”尚不可知；全局余量也没有逐组剩余束数

**问题。** [方案：44—45 行](<D:/paper-s2lab/docs/Claude维护/S2-LAB/11_第三轮方案.md#L44>)隐含后续组/极化已经固定，与当前环境不符。

**证据或理由。** 当前场景一开始就有全部位置、需求、耦合及按需求排序的处理顺序，[装载：159—170 行](<D:/paper-s2lab/src/satellite_rl/s2lab/env.py#L159>)可支持已知静态信息；但[贪心定组：265—272 行](<D:/paper-s2lab/src/satellite_rl/s2lab/env.py#L265>)依赖当时的已分配干扰。未来策略改变当前动作后，后续选择的组和极化也可能改变。

**影响。** 读取完整 rollout 的后续实际分组就是未来决策泄漏；提前为未来固定分组则改变了环境。按“剩余本组束数”归一化全局槽位也没有现成定义。

**具体改法。** 后续特征先改为“未处理几何邻居数、需求总量、入/出耦合总量”，邻居阈值沿用物理定义的 1°或预先冻结的耦合阈值，不称同极化。若需要极化预估，明确它是基于当前状态的规则预测，不是未来事实，并计入特征计算成本。全局频谱输入固定八组的空闲槽数/100、最长空闲段/100，再给全局剩余束数/N；若要表达相对紧张程度，用“全部空闲槽/剩余束数”，不要假造逐组剩余束数。新特征全部来自决策时已知快照。计数和需求汇总可以反映后续竞争，但不含逐槽位置偏好，不能据此承诺能为特定后续邻居留位置。

### 14. “去掉全局令牌”混合了信息删除和结构变化，“全部补充”也不是单因素

**问题。** [方案：46、48—50 行](<D:/paper-s2lab/docs/Claude维护/S2-LAB/11_第三轮方案.md#L46>)将这两组一起列为状态单因素消融；去掉令牌后实际只有 13 个令牌。

**证据或理由。** [14 令牌编码：82—102 行](<D:/paper-s2lab/src/satellite_rl/s2lab/nets.py#L82>)把三维全局信息投影为一个参与注意力的令牌，移除它同时改变注意力序列与参数。第二轮 12 令牌还改变了位置/需求/功率的合并、输入字段和读出，因此本轮删掉一个全局令牌也不能单独解释过去 14 对 12 的全部差距。

**影响。** 容易把结构变化说成三个总量的贡献，或者把全部补充的结果说成某项特征有效。

**具体改法。** 若问题是“全局信息值多少”，主消融保留 14 个令牌和相同结构，将全局输入三维固定为常数，并从头训练；它测的是去除这条显式输入通道的效果，掩码等侧路仍可能透露进度与预算。真正删除令牌可另作结构实验，优先级较低。“全部补充”改称七项特征的联合包，排到单项检查之后，直接与无补充基线比较；不把它当作第八种独立信息，也不据其结果推断每一项都有用。

### 15. 去掉干扰输入只能测网络通道的增量价值，规则与掩码不会随之失去干扰感知

**问题。** [方案：47 行](<D:/paper-s2lab/docs/Claude维护/S2-LAB/11_第三轮方案.md#L47>)的研究问题写得过宽，而且只写“训练时置零”。

**证据或理由。** [规则定组](<D:/paper-s2lab/src/satellite_rl/s2lab/env.py#L265>)始终使用真实干扰；B 组的[起点筛选](<D:/paper-s2lab/src/satellite_rl/s2lab/env.py#L322>)也是如此。普通 R0 的空闲掩码本身不按干扰排序，但允许组的选择已携带规则作用。当前[回放与网络](<D:/paper-s2lab/src/satellite_rl/s2lab/agents.py#L14>)还区分 I/N 和绝对 dBW 通道。

**影响。** 无掉分只能说明“在这套规则辅助下，该网络输入的额外价值小”，不能说干扰无用或模型不需要物理信息。

**具体改法。** 主消融在训练、开发和评价一致遮掉演员与评论家的对应干扰通道，固定规则、合法性及其它输入；名称写“去掉显式干扰输入”。它应与 R0 比，不与 B 或新增 SINR/出向干扰的组合比。另做低成本诊断：同一状态下固定组、实际槽数和功率，仅替换合法起点，分别记录入向损失、对已放束的影响和总目标变化。若论文确实要回答“全部干扰信息值多少”，再独立安排网络输入×干扰感知规则的交叉对照；无需本轮先把四格全训完。

### 16. 回放池和演员学习率对照可保留，但应先认识到当前更新密度很高

**问题。** [方案：31—32 行](<D:/paper-s2lab/docs/Claude维护/S2-LAB/11_第三轮方案.md#L31>)只从“池太短、学习率低”解释慢学习，没有同时考虑更新密度及大池的旧策略样本比例。

**证据或理由。** [矩阵：12 行](<D:/paper-s2lab/src/satellite_rl/s2lab/matrix.py#L12>)为每个环境转移 1 次更新、每批 256；[更新调度：155—163 行](<D:/paper-s2lab/src/satellite_rl/s2lab/agents.py#L155>)在 64 个环境转移后做 64 次更新。第二轮 20 万步实际约 **19.8 万次更新、5070 万条样本抽取**。增大回放池不会自动降低同一转移生命周期内的平均重复抽样次数，而是扩大历史跨度、改变样本年龄和相关性。[回放：29—63 行](<D:/paper-s2lab/src/satellite_rl/s2lab/agents.py#L29>)全部驻留设备。

**影响。** 大池可能提高多样性，也可能增加过时样本；不能仅凭 2 万比 20 万小就判断不足。新增字段或条件掩码还会改变显存和存盘成本。

**具体改法。** 两组都固定其它超参，先记录样本年龄、场景/负载/进度覆盖、TD 误差、各头熵和实际更新次数，再决定是否升级为优先实验。当前 14 令牌存储字段的 10 万容量回放，含前后状态与动作约 **0.46 GiB**；若额外存前后两个 800×10 布尔掩码，单此项再加约 **1.49 GiB**，尚未计网络与特征。优先从已存占用和规则信息重建或压紧本组掩码，且核重建一致。不要本轮同时再改更新密度，把它留为出现过拟合/开销证据后的候选。

### 17. 自动温度和加宽都要补精确配置，不能只写开关或参数总数

**问题。** [方案：30、33 行](<D:/paper-s2lab/docs/Claude维护/S2-LAB/11_第三轮方案.md#L30>)缺加宽时的 FFN 规格和自动温度目标、初值、学习率。

**证据或理由。** 本次实例化当前网络：14 令牌 d128/FF512 的演员约 **50.9 万**参数；d256/FF512 约 **127.8 万**，d256/FF1024 才约 **180.3 万**，见[参数量核验](<D:/paper/outputs/experiments/s2lab_round2_20261025/astra_review/round3_plan/checks.json>)。第二轮加宽组还把 FFN 设成 4d，见[矩阵：99—103 行](<D:/paper-s2lab/src/satellite_rl/s2lab/matrix.py#L99>)。现有[自动温度：211—218 行](<D:/paper-s2lab/src/satellite_rl/s2lab/agents.py#L211>)默认 κ=0.3，针对独立头的合法动作数求和，不适用于直接拼接所有自回归分支。

**影响。** 参数数不一致会令“复验加宽”含义改变；温度目标不可达或熵定义错位会持续抬高 α。

**具体改法。** 加宽明确为 d256、FF1024、2 层、8 头、其余一致，称“同一规格族整体加宽”，同时报演员、双评论家、目标网络总参数与显存。先在 R0 的独立动作上做自动温度，写明初值 0.01、α 学习率和 κ。自回归版若之后启用，采用第 3 条的完整条件熵，并定义可达的联合目标，例如 κ×log(合法完整动作数)；按状态计算并与当前熵使用同一支持集。若采用分头目标，按条件分支访问概率加权并说明与联合目标不同。记录 α、目标/实际熵、合法动作数和 αH，不能复用一次 CNN 自动温度不佳就认定该路线无效。

### 18. 20/30 万步的延长规则必须事先固定，先修正重复终点和断点续训语义

**问题。** [方案：8 行](<D:/paper-s2lab/docs/Claude维护/S2-LAB/11_第三轮方案.md#L8>)的“还在涨就续到 30 万步”没有可执行判据，背景收敛判断也存在窗口错位。

**证据或理由。** [训练：194—207 行](<D:/paper-s2lab/src/satellite_rl/s2lab/train.py#L194>)在到达评价节点后又在完成分支评价，导致[基线种子 1 日志：20—21 行](<D:/paper/outputs/experiments/s2lab_round2_20261025/account_B/runs2/t14-in-delta-s1/dev.jsonl#L20>)两次记录 200000 步。[收敛脚本：31—37 行](<D:/paper-s2lab/scripts/s2lab/convergence.py#L31>)直接取最后五行。按 step 去重，基线三种子“16—20 万均值减 11—15 万均值”为 **+0.0107、−0.0025、+0.0083**；种子 1 原脚本为 +0.0043。另，[断点：130—134 行](<D:/paper-s2lab/src/satellite_rl/s2lab/train.py#L130>)未保存环境部分分配；[恢复：87—109 行](<D:/paper-s2lab/src/satellite_rl/s2lab/train.py#L87>)先新建环境再恢复随机状态，重启并非严格延续原轨迹。

**具体改法。** 主表统一 **20 万步预算**、每 1 万步一次唯一开发节点、只在前 20 万节点选模。另设 30 万补充表：例如在去重后的两段五节点均值差达到 0.01且末八点斜率为正时，触发该候选及它的父对照三种子一起延长；阈值在开跑前冻结，不能看确认集再定。对有前景但平台不明确的核心组也可事先统一 30 万。需精确接续就保存并恢复 64 个环境的部分分配、计数及采样状态，做中断前后轨迹对比；否则明确称“从学习断点重启环境继续训练”，并对所有对应组使用相同规则。末段走平只说明当前预算内平台，不等于达到算法上限。

### 19. 选模、训练目标和统计口径应分别固定，已反复使用的确认集不能承担最终证明

**问题。** [方案：8 行](<D:/paper-s2lab/docs/Claude维护/S2-LAB/11_第三轮方案.md#L8>)只规定 SGM 选模和列指标，没有说明跨种子、分档、时间相关性与最终测试。

**证据或理由。** [delta 实际目标：236—238 行](<D:/paper-s2lab/src/satellite_rl/s2lab/env.py#L236>)是各束 SGM＋束平均满足率项之和，而 W 是业务量加权满足率；γ=0.99 下折扣 delta 回报也不等于纯终态目标。保持奖励不变是合理的，但三者不能混称。[第二轮报告：66 行](<D:/paper-s2lab/docs/Claude维护/S2-LAB/08_第二轮实验报告.md#L66>)已说明确认集被用于前轮设计；本次从规则 CSV 再核到 **255/287 景来自同一天**。

**影响。** 仅按场景独立自举会低估时间相关性；三种子均值的小改进可能被误写成稳定超过贪心或全面改善服务。

**具体改法。** 仍用开发集 SGM 选模，不改用户指定的 delta 奖励和 γ；主表报告每种子分数、同种子差值、均值及样本标准差并标清定义。逐景按相同 key 与需求配对，三档分别报 SGM/W/最差10%/功率/干扰/约束。时间块重采样的块长事前固定，并给逐日期敏感性结果；只有三天，不能把日期自举区间视为充分的跨日期证据。旧确认集作为已知域复核集，最终组合与主要基线冻结后用新日期一次测试。模型选择和优胜项选择均不得回看该最终测试。

### 20. 组合版不能事后把所有正增益相加，必须规定筛选门槛和冲突处理

**问题。** [方案：10、67 行](<D:/paper-s2lab/docs/Claude维护/S2-LAB/11_第三轮方案.md#L10>)没有定义“有效”，也未说明多个改动相互冲突或性能互相抵消时怎么处理。

**证据或理由。** 完整动作双 Q 改变优化目标；自回归、连续功率改变条件结构；所需功率、SINR、份额和全部补充有信息重叠。单项都比 R0 好，不保证叠加仍更好。若逐组看确认集再挑组合，该集合继续承担了开发用途。

**影响。** 最后一个组合可能只是很多次尝试中的偶然赢家，失败组合也可能诱发无上限追加。

**具体改法。** 在实现前冻结开发集选择规则。可采用一个待确认的具体标准：同父组的三种子开发 SGM 平均增加至少 0.005、至少两种子同向，同时平均 W 和最差10%下降不超过各 0.005，合法性零退步；这些数是建议的工程取舍，不是已有统计结论。有“保持当前服务”的目标时，单列严格的服务非劣条件和分档检查。指定固定加入顺序，最多形成一个预先定义的组合与一个必要的冲突排查组；“全部补充”独立作为特征包对照。确认结果出来后不再为提高同一测试成绩反复改组合；若正式要声称稳定收益，另用新训练种子与新日期验证最终少数配置。

### 21. 60 次是上限候选清单，不应一次铺开；80 卡小时缺了关键并行假设

**问题。** [方案：60—72 行](<D:/paper-s2lab/docs/Claude维护/S2-LAB/11_第三轮方案.md#L60>)的配置数算对了，但卡时与完成时间的推导没有写明并发条件，也没有给新增动作结构实测。

**证据或理由。** 按方案自己的 57 次×2.5小时＋3 次加宽×5小时，应是 **157.5 运行小时**。只有假设“每卡两运行并行且每个运行仍保持这些耗时”，才约 78.8 卡小时；[排队器：49 行](<D:/paper-s2lab/scripts/s2lab/lane.py#L49>)默认并发却是 1。第二轮基线本次核到 2.40—2.77 小时，加宽旧组为 4.45—5.81 小时；新条件 Q、混合连续动作和新增状态的耗时尚无实测。组合版已经包含在 60 次里，随后再跑会增加依赖等待，不应在总计算量上重复计一次。

**影响。** “八卡十小时、十六卡五小时”可能失准；最慢组和前后依赖也决定实际完成时间。

**具体改法。** 预算拆成运行小时、卡小时、依赖链墙钟三项；先测 R0、精确双 Q、自回归/连续候选、全部特征、加宽各类代表的训练吞吐和峰值显存，再排队。优先删掉不回答新问题的重复组，延后全部补充、弱信息摘要、自动温度与大回放池的全量展开。三种子用于正式核心结论；单种子短段只检查数值与机制，不凭一次低分淘汰整个科学假设。下节给出可执行的优先级。

### 22. 同口径 PPO/DQN/MLP 应纳入本轮较高优先级，但先列清到底比哪几组

1. **方案定义能落到配置。** 上述 22 条逐条回填；每组有父对照、唯一差异、明确是否改动作执行/评论家/熵。统一数据、物理、delta 奖励、γ及逐束决策预算；不改动历史归档。

3. **动作语义通过。** 片段化空位、最后一束、总槽位刚好够、预算只剩预留、B 候选少于 8、终止/自动重置等例子中，L/A/B 与连续版的新合法动作路径要求申请和实际动作一致、无预算/同组共槽违规、不会产生空分支 NaN。R0 及沿用其执行语义的单项组保留原截断行为并记录截断量，避免为满足新不变量而暗改参照。新策略生成、回放、目标网络、评价用同一条件掩码。
4. **状态定义与特征体检通过。** 七项补充各有公式、单位、维度、动作前来源、缩放和异常物理状态表示；列出真实训练/开发场景的分位数、常数列、饱和比例与不可达比例。核出向接收方向、P/c、效率封顶及未知未来分组；确认无后验量。输入扩展须贯通[观测字段/存储 dtype](<D:/paper-s2lab/src/satellite_rl/s2lab/agents.py#L14>)、演员、评论家、目标网、回放与模型配置；仅在环境字典里加字段会被现有白名单丢弃。用非零输入扰动验证新通道确实影响网络前向，不能只检查形状。

6. **已知答案小场景通过。** 至少包含“两束需错开才更好”“宽裕时过供降低SGM”“窄空隙不能容纳长窗口”三个例子；先用枚举求同一奖励/折扣口径下的答案，再验证环境、掩码和目标计算，最后做有限学习检查。若失败，先找原因，不凭损失有限就铺开训练。
7. **科学比较规则冻结。** 去重后的开发评价节点、20/30万表、选模并列/并列时如何决胜、三种子、分档汇总、组合筛选与新日期用途事先写明。明确 W、束平均 SI、SGM 和干扰损失的定义；不能只看SGM就声称“服务全面改善”。

9. **代码独审后再分批训练。** 方案复核不替代实现复核。按用户既定要求，在实现和相关测试完成后交 Astra 复核、逐条回填，再按已知答案测试与代表组短段结果进入核心矩阵；无需等全部低优先级特征实现完才验证核心问题。
