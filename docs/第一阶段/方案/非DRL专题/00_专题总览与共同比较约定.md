## 2 两条比较轨道

| 轨道 | 共同条件 | 能回答什么 |
| --- | --- | --- |
| 同束数机制轨 | 先固定0.5°全宽；同一场景各方法使用共同强初解确定的相同实际束数N，跨场景N可不同 | 除去“多加束”的因素后，重分组、中心调整或学习决策是否有用 |
| 可变束数应用轨 | 固定相同飞机、需求、合法几何和资源条件，方法可自主选N但不超过200 | 布局质量、承载、束数和耗时的整体取舍 |

不能将只参加同束数轨的MLM首版与可变N方法混成一个冠军表。候选池方法在各自配对消融中使用完全相同的池；连续／几何构造方法不强行塞入该池，但要清楚记录搜索域不同，不能把差值完全归因网络。

可变角宽与真实时序是后续扩展：先核载荷允许范围、增益／干扰模型及重配置代价。某路线支持变宽或时序的设计，不等于首轮已经实施；其它路线无需等待MLM成功。

## 3 必须相同的口径

- 每景全部飞机几何覆盖、逐机唯一归属、需求守恒、N≤200；空束不得拿来降低均衡指标，零需求但服务飞机的束不能悄悄删除。
- 全体实际波束负载CV与正需求束CV分开；需求带内为正需求束均值的0.8–1.2。负载为零／全零需求的边界规则先冻结。
- 几何覆盖、负载均衡和模型估计承载分开报告。逐机TDMA承载以全部飞机需求为分母；600 Mbps不作真实容量。原RF模型未独立重算的限制保留。
- 共同强初解保存身份和哈希；构造类可用其作回退，但初解、模型、搜索、修复和最终核验耗时均单列。回退后可行不等于原始模型提议可行。
- 改动归属、中心或宽度后，重新核整个场景的几何、负载、资源和干扰影响，不能只看局部代理目标。
- 比较AI净贡献时，保留无AI的同区域／同候选数／同求解器对照。列生成、修复、数学求解和教师的收益不都归给模型。

首轮共同下游建议冻结现有`variable_downstream.evaluate_layout`中的分配器、天线与逐机TDMA版本，不在不同路线间换资源分配器或求解精度。这是模型估计评价，不等于已经运行完整第二／三阶段学习与连续功率优化；如需后者，另列共同扩展与调用预算。

统计统一为：先对每个母场景的三档求均值，再对母场景等权平均；相对CV改善按“方法均值／基线均值−1”计算，下降为改善，不平均各景百分比。时间的中位数与P95也以各母三档平均后的值计算，300行分布只作描述。基线CV≤1e-12时不报告相对改善百分比，改报绝对差和数值容差；全零需求景不计算CV和需求加权承载比例，单列数量及可行性，不能补成0或1。

## 4 数据、预算与推进规则（建议，尚未冻结执行）

数据先按母场景与时间块分开，再产生局部区域、候选、标签、掩码或扰动。已有考核已经看过，可作历史诊断，不能回流为新模型训练后仍称独立考核。建议开发20母、新验证20母、最后新100母；三档需求同母相关。统一倍率不代替热点、异质需求或真实时序。

首轮学习种子建议仅51001；各篇给出可核对的教师问题数、候选试算数、标签数、监督更新数与离线耗时上限，**不把每篇上限自动相加成已授权预算**。兼容教师和数据可共享，但需证明输入、动作、目标与划分一致。不同样本大小下，相同更新数不等于相同训练计算量。

同束数轨可沿用MLM提案的2秒算法预算作起步建议，覆盖新增候选、模型／规则、求解和搜索中的核验；共同初解和最终一次固定下游核验另计，完整端到端时间必须包含它们。正式时限以短工程验证后统一冻结；不能只对某路线放宽。非学习方法无神经训练预算，仍记录调参和候选评价成本。

推进顺序：正确性小例 → 开发集可达改善与吞吐筛选 → 必要学习／求解试点 → 固定验证筛选 → 新共同考核。每条独立过闸，不因其它路线失败而一起停。正确性失败先修复；无改善／超时则按预设上限留失败，不能无限加预算。

MLM的原建议门槛是开发教师至少在6/20母取得超过1%的CV相对改善；其它篇须依据自身轨道提出具体门槛，不能不解释就照抄。正式质量或效率门槛必须在考核前固定，并同时要求可行与承载不明显退步。

同束数轨的共同提议：质量分支在相同在线预算下，相对事前指定强基线平均CV至少降低5%；效率分支在CV平均不劣于2%、逐机承载平均下降不超过0.5个百分点时，完整总时中位数至少减半且P95不增。均要求全部发布布局可行，并公布逐景退步。应用轨另冻结跨N选择准则，不能拿固定N的平方目标等价关系跨N使用，也不在考核上挑Pareto点。

两条成功分支都要求逐机承载平均下降不超过0.5个百分点、全部发布布局可行且不劣于共同初解；不能只给效率分支加承载条件。各篇须事前写明主基线与必要附加对照，例如01需对HO和O均验，而05的主比较对象是11。超时、无解及目标首达失败保留；不可中断的模型／几何／下游调用按实际结束时间计入，不伪造2秒硬截止。不完整教师试算标未知／删失，不能自动作负标签。

在线／发布承载保护统一锚定该场景的共同初解I0：候选的逐机模型估计承载不得比I0低超过0.5个百分点，不能每步相对前一步各降0.5个百分点而累计退步。同N机制轨发布精确CV也不得高于I0；正式成功的5%／2%及承载均值条件另外相对下表指定比较方计算。对全零需求景不做比例判断，只保留几何、归属与资源检查。连续中心等内部探索状态不是发布结果，不要求中心单独移动就能降低CV。

05与11首轮共享一个重建内核：每轮最多12个候选区域、每区域2–6束、每原束最多8个新增中心候选、每次求解≤0.1秒、每景最多40次重建提案，且2秒总算法预算先到先停。原区域候选与原可行归属必须保留。两者只在区域选择上不同，均仅接受全景更优的可行态，连续两次无改善停；不另外学习STOP。允许暂时变差或换重建器是后续双方共同扩展，不能单边加入。

### 正式主比较对象

以下属于本专题的建议矩阵，执行前连同算法实现一起冻结，不在考核后改比较方。定义共同贪心基线 **BH**：从同一个I0出发，在同N下按冻结顺序尝试整机转移、交换及中心候选替换；只接受全景改善的可行解，和所比路线共用生成／核验上限及总时限。BH是新的受限对照定义，不把历史会改变束数的R04原样改名搬入。所有正式入选路线还要在对应轨道交叉比较，不能只与自己的较弱消融排行。

| 路线 | 主比较对象与必须保留的归因检查 |
| --- | --- |
| 01 | M独立对H验共同门槛；MO对HO与O均验。两种推理分别下结论，不能相互借成功 |
| 02 | 对同菜单规则H和同预算强搜索T均验；有求解器时还需同求解器无学习对照 |
| 03 | DR对相同修复器的HR；原始D可行率另列，不以失败样本删减后的均值排名 |
| 04 | 对开发阶段已冻结的低成本规则排序H；同池全试算仅为有限池一步审计参照 |
| 05 | 对11的规则选区版本；只改变选区次序，重建、接受与停止完全相同 |
| 06 | 对BH；“只重分配／只移中心”等作为额外机制消融 |
| 07 | 对BH，同时与同邻域“只改归属”比较；若后者同样好且不更慢，不能声称中心更新有净收益 |
| 08 | 对需求加权Voronoi＋同整机化修复，以及仅整数分配＋同修复均验；不能把修复器收益归给OT |
| 09 | 对BH；距离边权、需求边权、几何剪枝三层为消融 |
| 10 | 对BH；初始池／扩池在相同总预算下比较，限时结果不冒充精确最优 |
| 11 | 对BH；另与相同重建器的随机／单一破坏算子比较，作为多邻域的增量分析 |
| 12 | 发布单解对BH；前沿另与同编码、同预算的单目标进化比较，不能只用前沿点数声称更好 |

12条路线共享一份最终任务矩阵。重复的初解、基线或求解器结果不重复算作新模型；每篇的消融只在贡献归因需要时增加。正式运行仍须独立工作台任务、冻结配置／源码、实际DQN/CUDA核验和四端资源检查，本专题本身不触发这些操作。
