# 03 监督学习直接构造布局：从场景提议完整分组

**执行更新（2026-10-12）：**本路线已纳入获授权的S1-ND12四端首轮验证。以下保留方案形成时的建议；实际任务、分账及停止条件以[专题执行状态与冻结计划](00_专题总览与共同比较约定.md)为准。当前处于正式数据准备，尚无新效果结论。

日期：2026-10-12。状态：独立方案，训练与考核预算**尚未获准执行**。遵循[专题总览](00_专题总览与共同比较约定.md)；此路线从原始场景一次提议完整布局，不依赖[01 MLM](01_MLM掩码布局重构.md)或[02逐步BC](02_强教师与模仿学习BC.md)成功。

**一句话做法：**用教师的多份高质量完整布局监督一个集合模型，让它由全部飞机位置和需求直接产生分组与指向，再对原始提议和必要修复分别核验、计时。

## 场景、变量与可学习输出

输入只含当前已知飞机方向、业务需求、可用足迹几何、总束数上限及可选的目标N；首轮0.5°固定宽度。不能输入教师最终分组、最终束中心、每束负载、按终局计算的候选池或未来时刻业务。首版明确采用**同N、连续中心回归**：输出N个束槽中心及每机对N槽的归属概率，不再增加另一个启用/终止头。飞机与束槽都是无序集合；模型需在飞机重排下等变，且同一布局的束槽交换不改变训练目标。飞机身份只用于审计，不作可记忆标签。

首轮使用**同N条件模型**：场景的N由共同强初解冻结，网络提议N个束槽的分组与中心，便于区分布局质量与束数。共同初解仅提供N和回退布局，其构造成本仍计入端到端耗时，不能称完全不依赖初解计算。可变N应用轨再预测启用槽或条件N≤200，并在验证前冻结跨N选择准则。不能用空槽掩盖差负载；零需求但服务飞机的束仍是实际束。N个输出槽不保证N个非空束，原始布局若有空槽即未通过同N机制验收。连续中心回归没有几何全覆盖保证；候选中心分类另列后续变体，不在首轮同时训练两个模型。

## 参考布局、损失和解码

1. 先以母场景和时间块划分训练/验证/考核，再在训练母场景用多起点强搜索或整数局部优化收集经过整景核验的可行完整布局。每景保留质量接近但结构不同的多解、真实束数、候选域、求解状态和离线成本。教师超时可行解是参考解，不是最优真值；不把旧考核场景或相邻时间泄漏进训练。
2. 建议使用飞机集合编码器加可学习束查询，128维、4层、4头作为短验证起点；对每机与束查询打分，并回归束中心的卫星视角方向。训练时先对预测槽与每份教师槽作最小费用二分匹配，再在匹配下计算归属交叉熵与中心位置损失。首版匹配费用和训练损失均采用“全机平均交叉熵＋以0.5°归一化的中心角距平方均值”，两项权重各1；方向输出归一化并限制于冻结服务视域。对每份完整教师解分别匹配、计损失，再取整份最低损失，不把不同分组逐机混成一个无法实现的标签。费用与权重只经开发短检后冻结，不能按考核表现改。几何惩罚若以后增加，须另作消融，首版不靠软惩罚宣称可行。
3. 推理时网络一次产生原始槽、中心和逐机最大概率归属。先独立保存原始提议，验收逐机唯一归属、所有飞机被所归束足迹覆盖、恰好N个非空束及需求守恒；对失败提议用冻结的确定性有界修复：优先把非法飞机移到可覆盖束，必要时局部移动中心，最多4轮、每束最多8个由当前场景生成的中心候选，受共同时间预算约束。称“有界修复”不称最小改动保证；所有移动后重核整景且同N不变。修复仍失败或质量未改善时回退共同强初解。修复前后质量、耗时、改动飞机/束数须分开记录。

**多解不是噪声：**两份等质分组可能在束槽编号上完全相反，直接逐编号交叉熵会让同一布局出现矛盾标签；最小匹配解决纯置换，但不同的实质分组仍要通过多解目标或质量评价处理。模型高标签准确率不保证物理覆盖，也不保证CV改善。教师中心只作标签，不能放进模型或修复器的候选特征。若以后改为候选中心分类，必须先由场景生成池、保存哈希，再让教师在该池中求解；教师池外连续中心不可直接取最近候选当标签，须在池内重新分配并核验，且不能把教师中心补回池。

承载复核统一冻结现有`variable_downstream.evaluate_layout`的分配器、天线和逐机TDMA版本。此处的估计不等于第二阶段学习分配与第三阶段连续功率优化均已执行；各路线不能私自换下游以改善本方法成绩。

## 对照、上限与判断

同N轨对照共同强初解I0、相同N的无AI直接构造H、网络原始提议D、D加修复DR、H加**同一修复器**HR。DR与HR的修复规则、容量、时限及验收相同；具体候选因待修布局不同可以不同，须保存而不冒称逐项同池。若D原始提议不可行而DR可行，须把修复器收益单列。D的失败样本保留，原始CV只作附带可行率的条件诊断，不把删去失败后的均值与全样本发布布局排行。D与[01局部补全](01_MLM掩码布局重构.md)不同：D没有完整局部布局作为上下文；I0只提供目标N、回退及配对基线，不能把其中心/归属暗藏输入。

**待批准上限：**开发与训练合计最多10000个教师问题，每题对应一个母场景及需求档、最多4份不同可行参考解；每题离线搜索最多4秒，总教师求解时间≤40000秒，候选准备和核验另账。同母不同档不是独立母场景，母场景数单列。单seed51001，最多12000次监督更新、batch 16个完整场景，1000更新一次固定验证；多解数量、标签数、更新数和实际GPU时分别记。开发20母、新验证20母、新共同考核100母×三档；在线完整构造与修复建议共用2秒算法预算起步，经吞吐短试后与其它方法统一冻结。上述数据量是上限而非必做配额，也不自动获批。

开发先检查同N教师可达性：20母均须有通过审计的参考布局（可保留I0，但单列无改善），至少6/20母相对I0 CV改善>1%。开发调用计入10000教师问题及40000秒总账。短学习取前2000更新且包含在12000总额内，拟以冻结验证原始完整布局可行率≥80%、DR相对HR至少在6/20母改善>1%作为继续闸门；未过即报告试点未达，不自动靠更多训练补救。可行率80%只用于判断是否继续，不是最终发布可放宽覆盖的许可。正式权重用预算终点，考核不选权重。**小例：**两束四机，两组中心互换编号但每机归属的几何分区不变，置换匹配后的损失应相同；再将一机归入足迹外束，原始核验必须失败，即便修复后布局可行。失败信号是匹配损失下降而原始可行率仍低、修复几乎总是重造布局、模型只在教师中心泄漏时表现好。

正式质量/效率门槛采用[共同冻结提议](00_专题总览与共同比较约定.md#4-数据预算与推进规则建议尚未冻结执行)：DR对HR同在线预算平均CV降≥5%且不劣于I0；或对HR在CV均值劣化≤2%时完整总时中位数减半且P95不增。两支均要求逐机承载下降≤0.5个百分点、全部发布可行，并公开原始提议可行率、回退率和逐景退步。I0是共同计时组成，不要求先算I0再声称总时比I0减半。若网络贡献被修复器完全覆盖，报告未证明直接构造价值。单种子不能推出训练稳定性。

可变N时按真实N报告质量/承载/耗时取舍，不能拿同N平方负载目标跨N评分；变宽须联动天线增益与干扰；动态轨只使用历史和当前可知业务并计切换。三者需另冻数据与预算，首轮固定宽度结果不代表全部完成。

实现拟复用`coverage/variable_dataset.py`、`variable_design.py`和几何/下游接口，新增完整布局教师、多解匹配、集合解码、确定性修复与运行器。短验证包括置换等变、多解等价小例、输入泄漏审计、原始/修复分账、真实梯度更新、200束边界及整景物理复核。正式工作台应提供同N/可变N、连续/候选中心、参考解上限、匹配与修复预算、监督更新和模型选择配置，服务端冻结校验并展示原始/修复差异；本轮仅写文档，无前端改动。

方法来源：[Combinatorial Optimization with Graph Convolutional Networks and Guided Tree Search](https://arxiv.org/abs/1810.10659)提供图结构构造与搜索结合的通用启发，[Attention, Learn to Solve Routing Problems!](https://arxiv.org/abs/1803.08475)提供注意力编码参照（原论文用强化学习训练，本篇只借结构），[Neural Diving](https://arxiv.org/abs/2012.13349)提醒学习提议与后续求解须分账。它们的图、车辆路径或整数规划结果均不能移植为卫星飞机覆盖保证；本篇的完整布局匹配与硬几何核验是本项目待检设计。
