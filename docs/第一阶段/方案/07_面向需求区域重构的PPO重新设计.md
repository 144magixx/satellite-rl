# 07 面向需求区域重构的PPO重新设计

日期：2026-10-05。状态：**新方案讨论，尚未实现、未启动训练或评价，效果待验证**。用户要求重新设计PPO、放弃此前做法。本方案保留用户的覆盖与主体负载目标，重新定义智能体承担的决策；不恢复已交付的S1-02任务和已暂停的自动化，也不把旧训练授权延伸为新实验授权。

建议把PPO改为决定**业务区域怎样重新划分、波束数量怎样在区域之间转移**。一项决策可以同时合并轻载区域、拆分热点区域，并重新确定相关波束中心和用户归属。聚类结果可以作为一个初始参考，但不再决定某束永久服务哪一群用户，也不再限制波束只能在原聚类中心周围移动。

这是一项待验证的建模选择，不能保证主体CV达到0.20。先检验新动作能否产生可行改善，再检验PPO能否比相同动作与计算条件下的非学习决策更好。

## 1 从用户目标重新定义问题

第一阶段输出波束中心、宽度、唯一用户归属及各束需求D。覆盖优先：争取用户覆盖与需求覆盖同时100%；只能达到双99.9%的场景单列，不能用均值隐藏漏覆盖。负载均衡关注至少90/100束接近主体均值，允许最多10个有几何证据的轻载边缘专用束；不删除普通低负载束或过载束。继续同时报告主体CV、全体CV、均值带内束数与峰值负载比。

[开题报告](../../资料/01_开题报告_导出1212最终版.docx)的研究内容是指向与宽度调整、覆盖与负载均衡、单智能体集中决策及后续资源分配接口。原文可定位[正文提取](../../../outputs/verification/stage1_plan_review_20260930/proposal_text.txt)P141、P148–164、P218；提取文本遗漏嵌入公式，不据其猜写原式。本方案把集中式固定顺序轮询改为集中式主动选区，是研究方法调整，不能说开题报告已经规定了这种新算法。

首个验证版本建议继续用100束、0.5°全宽，以便控制问题规模和现有接口；二者是本轮比较条件，不是永远不能改变的研究边界。可变宽度是开题报告中的后续必要内容，但扩大宽度会改变天线增益及下游链路条件，应单独定义物理版本，不能只靠扩大覆盖圆得到看似更好的几何覆盖。

| 处理 | 本方案的决定 |
| --- | --- |
| 保留 | 真实用户位置、逐机不可拆需求、唯一归属、合法卫星指向、覆盖优先与边缘认证、100束完整分母 |
| 取消作为新算法默认 | 固定波束ID轮询、上下左右小步菜单、原聚类中心累计0.25°限制、20万归属尝试全程共用的旧计数方式 |
| 重新设计 | 区域与配额动作、关系状态、连续负载目标、主动STOP、每次重构的固定计算额度与计时 |
| 单独比较 | 新可达中心范围与算法收益；不能把解除0.25°限制带来的收益归给PPO |
| 暂不加入 | 联合训练第二阶段、频率或功率动作、任意放宽宽度、额外训练种子 |

取消旧中心偏移限制，是拟议的新实验条件；仍须遵守实际允许的波位集合/视场。如果系统确有重配置距离或速度约束，应从硬件/时序需求另行定义，不能默认无限可移动。静态快照内重新布局不等于已经验证在线连续移动。

## 2 已有证据与尚未证明的解释

[A报告04](../实验报告/04_覆盖优先与主体负载均衡A阶段对照.md)显示，用户归属调整比之后的小步调位贡献更大；A3的100景都先触及归属尝试上限，82景不足一轮。因此旧结果没有证明“完整调位10轮仍无法均衡”。[B报告05](../实验报告/05_动作空间与PPO负载均衡B阶段对照.md)显示，三PPO保留结果主体CV约0.53，主体目标均0/100，三原终态CV还差于同菜单搜索。

源码核对也提示目标表达需要统一：[balancing_env.py](../../../src/satellite_rl/coverage/balancing_env.py)的`_balance_metrics`使用多个加权项评分，增加1个均值带内束的分数相当于主体CV降低0.1；`_quality`却先按均值带内束数、再按CV作字典序比较。旧训练gamma=1，差分奖励完整求和对应原终态标量分数，并非单纯的逐步贪心；但最终发布主字段是另一排序保留的布局。新方案要消除这种目标与主输出口径的差异。旧动作0只是“不动”，仍计处理次数，并非主动STOP。

这些现象不能证明单一失败原因。尚未证明PPO网络太小、训练太少、固定100束/0.5°下目标不可达，或重新设计后必然更好。另一个需要澄清的实现事实是：旧候选特征不含每个动作执行后的真实CV/覆盖分数，不能把它批评成已经泄露动作答案。

## 3 三条不同路线及选择理由

| 新建模路线 | PPO真正决定的内容 | 机会 | 风险与本轮选择 |
| --- | --- | --- | --- |
| 区域重构与跨区配额转移 | 合并哪里、拆分哪里、哪些用户群重新分区 | 在保留完整覆盖布局的同时改变空间分配和归属关系 | 主推；要防重构器过强掩盖学习、局部重构仍不可达更好解 |
| 从零构造整套布局 | 下一束投向哪个需求区域、怎样安排剩余束数 | 完全摆脱初始聚类拓扑 | 有吸引力的独立备选；剩余覆盖的必要条件不能保证最终可行，必须分开报告构造失败与回退 |
| 一次或少数几次输出全部中心 | 全100束的联合位置及后续宽度 | 直接整体规划，适合研究连续动作 | 高维输出、波束交换对称性及覆盖投影可能造成训练困难；不把“大网络＋200维坐标”当当然优解 |

旧S1-01的P0构造式PPO覆盖退步，只说明旧实现的表现，不能否定所有构造式建模。此次主推区域重构，是因为它能在每次提交时保留完整可核的覆盖，同时实现跨区域束数转移；并不是因为构造式PPO已被证明无效。首轮只训练主推路线，避免一开始把三种完整系统一起做成大矩阵。

## 4 动作由移动方向改为服务区域重构

一个环境动作是一次完整重构提议。PPO以条件动作头依次选操作类型、相关区域/波束集合、必要的需求切分锚点；所有选择组成一个宏动作。选择器可以跨地理区域决定配额转移，不再只在当前束邻居中选方向。

| 操作 | 内容 | 束数变化 |
| --- | --- | --- |
| 合并并拆分 | 将可被一束覆盖的两束用户合并，同时把另一个热点服务群拆为两束 | 2→1与1→2同时执行，总数不变 |
| 重新划分 | 将2束或3束的用户集合合并考虑，重新划成同样数量的服务群，再拟合中心 | 2→2或3→3 |
| 重分配重叠用户 | 对选中区域内可由多束覆盖的用户，成组改变归属，必要时同步拟合中心 | 总数不变 |
| STOP | 策略认为继续重构收益不足，交出当前完整布局 | 明确结束，不等同不动 |

**说明性例子，非实验结果：**一处相邻稀疏区的两束各承担30单位需求，另一个热点由一束承担180单位。如果稀疏区的全部用户确实可由一束覆盖，就可提议把它们合成60，腾出的一束用于把热点划成90与90。三束总需求始终为240，用户一个也不减少。它改变的是“两个区域各分几束”，不是把原三束各挪一格。

低负载并不代表能合并：若两群用户不能装进一个合法0.5°足迹，该合并无效。热点按需求均分也不保证两个分区都能被波束覆盖。策略先提出操作，几何层必须给出真实可行布局，不能只在抽象负载数组上平衡。

不直接枚举全部波束三元组。操作后条件选择可写为

\[
\pi(a\mid s)=\pi(o\mid s)\pi(i\mid o,s)\pi(j\mid i,o,s)
\pi(k\mid j,i,o,s)\pi(z\mid k,j,i,o,s),
\]

其中不适用的动作头跳过；`z`是切分锚点/模板的有限选择。只对明显不可能的选择做便宜的几何预筛，不能声称这个掩码已证明最终可行。首版模板及锚点集合必须固定，并对所有对照相同；动作空间里保留已覆盖用户群的成组交换，不用候选生成器提前删去所有可能暂时使负载变差的选择。

## 5 几何层的职责和覆盖保证

几何层负责把策略选定的区域与切分参数落实成中心和归属，不自主选择“还应改哪个区域”。对合并使用完整用户集合的球面/卫星射线覆盖检查；对拆分及重新划分使用确定性需求分区和有限次几何拟合，最后仍按实际卫星视角逐机核验。不能把平面包围圆结果直接当精确卫星覆盖证据。

每次在临时副本完成整项操作，只有以下检查全部通过才一次性提交：合法指向及束数、全部已覆盖用户仍被覆盖、每个覆盖用户唯一归属、需求守恒、无伪造需求或不合格空束、例外证书仍适用。其余波束及其用户不被修复器擅自改写。联合重构的中间草稿可以暂时不完整，不能作为已部署布局或策略已实现覆盖的证据。

失败则整项回退，记录原提议、失败原因、实际执行结果及计算量；该尝试仍计入预算与训练轨迹，不反复重抽到成功后才算一步。覆盖合格但均衡暂时变差的动作允许提交，给PPO学习多步调整的空间；不能又用只接受即时改善的外部规则把策略变成贪心搜索。

如果起点已100%覆盖，以上守护可保证每个提交状态继续100%覆盖。如果起点只有双99.9%，只能保证不丢失已覆盖用户，不能说已经100%。首轮均衡PPO之前安排共同覆盖初始化，低于双99.9%的场景标记初始化失败并保留完整评价分母；不能静默删景。以后若让同一策略也负责从覆盖失败中恢复，须显式增加覆盖修补任务及奖励阶段，不把该能力混入本次均衡训练。

共同初始化不再绑定旧A2的固定聚类身份：可以从覆盖优先的确定性构造产生布局；初始化代码、调用次数、耗时和输出由所有方法共用。旧A2仅作为开发参考之一。若新的初始化本身已解决大部分均衡问题，也必须如实说明，不能算成PPO收益。

## 6 状态与网络

建议使用“用户—波束关系图”的集中式Actor-Critic，而非把固定编号的100束压进一个无结构向量。

| 信息 | 作用 |
| --- | --- |
| 用户位置、需求、当前归属、可覆盖波束集合 | 识别业务在空间上的分布和归属可调整性 |
| 每束负载、相对主体均值、覆盖裕量、独占用户需求、边界用户 | 分清负载高和无法轻易移走用户的原因 |
| 波束间可共享用户、几何接近关系、拟合可合并性的便宜代理 | 支持合并、重划和跨区配额选择 |
| 全局覆盖、负载分布、认证边缘区域、剩余宏动作及重构计算额度 | 学习整体取舍与主动结束 |

图编码或集合注意力都是可用实现。首版可用两层关系消息传递、128维表示，Actor分条件选区，Critic汇总全局状态；这些是待工程验证的起点，不宣称换成图网络就必然改善。用户顺序与波束编号随机置换后，几何和输出应保持等价；稳定ID仅用于记账，不能作为隐含地理标签。稀疏化/汇聚时不能丢掉独占用户与偏远用户，最终约束检查始终使用原始逐机数据。

状态只含当前可获得的信息。无需先把全部宏动作完整重构并计算终值，再把结果送入策略选最高项；那样应被描述为昂贵的候选搜索，并与直接选最优的规则比较。策略可以使用便宜的几何代理，真正的后果在选中动作后由环境计算。

## 7 奖励与最终交付口径一致

覆盖通过约束与完整提交核验处理，低于入口门槛的布局不能拿低CV抵偿。对已达到覆盖入口门槛的状态，设主体集合为\(S\)，主体均值为\(\mu\)，\(x_i=D_i/\mu\)。建议首先用以下可解释的连续代价：

\[
J(s)=CV_S(s)^2+\frac{1}{|S|}\sum_{i\in S}
\left[\max\left(0,|x_i-1|-0.20\right)\right]^2.
\]

第一项控制整体离散，第二项持续惩罚超出均值±20%的程度。两项初始权重同为1是方案起点，只能在开发/验证中修改并在正式训练前冻结。它是学习用的连续代理，**不等价于也不保证90束达标**；严格达标仍同时检查主体CV、全体100束带内计数和覆盖。

为使仅双99.9%的起点也有动力达到严格100%，先将负载代价压到有界区间，再明确覆盖等级：

\[
B(s)=\frac{J(s)}{1+J(s)},\qquad
Q(s)=2\,\mathbf 1[\text{用户与需求均严格全覆盖}]-B(s).
\]

同一覆盖等级内Q按J单调排序；严格全覆盖与仅接近全覆盖的Q区间不重叠。它是本方案明确定义的新效用，不声称最大化期望Q与最小化期望J在所有随机策略下等价。几何、唯一归属和已有覆盖不退步依然由硬检查保证，不能由奖励代替。

首版有限回合取gamma=1，奖励建议为

\[
r_t=Q(s_{t+1})-Q(s_t).
\]

首轮主训练不加入计算成本惩罚，完整回合回报可望远镜求和为\(Q(s_T)-Q(s_0)\)，允许中间出现负奖励，不只奖励向好变化。计算量通过相同硬预算控制，并独立报告调用量与墙钟；不能用并发下波动的墙钟作为训练奖励。以后若增加\(-\eta c_t\)，即便\(c_t\)按回合额度归一且累计不超过1，小成本仍可能改变同覆盖等级内两个接近负载结果的选择，届时应明确是新的质量—计算折中，不称与本轮目标严格同序；本次不另建此训练变体。

主成绩是策略STOP或额度结束时的**原终态**，训练和评价一致。轨迹最好布局继续保存作诊断，但不自动替换主输出；若以后部署要交出轨迹最好布局，应将它作为明确的另一个系统版本，并给所有对照相同机制。所有覆盖失败、被拒提议、无效动作、立即STOP和到上限次数都需要报告。

边缘例外资格依据原始用户几何在共同合法中心范围内预先认证。新版本取消旧偏移限制后要重新核证，不能照搬旧可达范围下的证书。冻结的是必要服务区域及其例外资格，不是任意最低负载的波束标签；它们需要的专用束不得被合并挪用。超过10个或证据不足时如实报告，PPO不能通过改变例外集合降低J。

## 8 PPO训练与停止机制

一回合对应一个静态需求快照；一个宏动作可能处理多束，首版建议最多32次宏动作，可主动STOP，覆盖与主体目标共同满足时提前结束。32是待开发验证的起点，不叫32轮遍历，也不能与旧1000次束处理直接等量比较。

每项重构有固定的拟合/归属候选调用上限，回合另设总调用上限，全部进入状态和日志。具体额度需通过开发阶段真实开销确定，正式前冻结；不继承旧“所有尝试混在20万计数中”的终止逻辑。安全墙钟上限只作异常保险；正式计时若触顶，单列失败/截断，不能偷偷增加额度补跑。

训练实现必须核对：

- PPO概率比使用整个条件动作的联合log概率；重用轨迹中原掩码与候选身份，不在更新时重算出另一候选集合。
- STOP和真正的回合上限是所定义有限任务的终止；采集批次切断只是截断，需正确自举。剩余预算必须进入状态。
- 归一化只用训练数据；验证保存/恢复训练随机状态，不能通过验证推进训练环境。
- 记录每种操作选中率、可行率、实际执行率、J变化、终态达标率及STOP分布，防止只看回报上升。
- 若大部分尝试无效或策略立即STOP，先检查动作可行空间、状态和工程实现，不直接加训练量。可用已知存在可行改善的小例验证学习机制，但这些不是正式ADS-B泛化结果。

当前建议只训练一个新PPO，seed51001；候选总预算262144次宏动作交互，65536为包含在总预算内的开发检查节点，未通过机制检查则停止诊断，不自动追加。该预算是待确认提议，不是沿用旧1228800预算。宏动作比旧单束动作更贵，应同时记录处理束数、几何/归属调用、参数更新、真实时间与内存；不能宣称交互更少即更省计算。

保留标准PPO更新作为首版，暂不同时加入模仿预训练、多个额外奖励、复杂课程和大规模网络切换。向量化用户几何、批量图推理、有限重构操作可作为实现方向；是否获得吞吐提升要实测，不能先承诺GPU满载。

## 9 先证明动作有用 再证明PPO有用

进入训练前，在开发场景检查：每个用户有合法覆盖位置、同宽同束数下存在覆盖可行证据、低负载可合并区域是否足够、热点可否拆分、单个不可拆用户需求是否已经超过目标负载带。对小场景可用精确或限时优化给出可行布局及上下界；覆盖下界不超过100只是必要条件，求解器超时只能写未知。

开发阶段先运行同一重构算子的规则或小规模搜索。如果几乎没有可行的负载改善，优先改动作/几何建模或讨论束宽与束数条件，不让PPO去学习不存在的选择。即便有限搜索没找到改进，也不能据此证明全局不可行。

| 对照编号＋完整组合 | 区分的收益 |
| --- | --- |
| R0：共同覆盖初始化，不重构 | 初始化自身达到什么水平 |
| R1：同重构器＋确定性规则选完整宏动作 | 新动作和几何层本身是否已有效 |
| R2：同重构器＋随机选完整宏动作 | 策略是否优于盲目探索 |
| R3：同重构器＋计算额度匹配搜索完整宏动作 | PPO是否真正优于强非学习决策 |
| P1：同重构器＋新PPO选完整宏动作 | 学习决策的追加价值 |

R1/R2/R3/P1均可选择同一完整条件动作\((o,i,j,k,z)\)，使用同一操作、区域候选、切分锚点/模板及预筛掩码；不能只给PPO额外的切分选择权。除选择器及其必要学习机制外，共用输入、中心可达域、宽度、例外规则、初始化、重构器、原终态口径与资源计数。R3试算多个候选的代价必须计入；R0不消耗未执行的重构预算。比较首先做等几何/重构调用预算下的质量，再单独给实测墙钟与质量曲线，不能要求耗时和调用量两个预算同时完全相等。随机对照提前冻结独立随机源，不把一次随机重复当多个独立场景。

旧S1-02模型/四向搜索保留为历史参照；它们受旧0.25°范围约束，不能用新方案对旧分数的差值证明PPO优越。若需要证明解除范围本身的作用，应在开发阶段对同一新规则方法做范围有无的配对诊断，而不是混在最终PPO成绩中。

训练拟复用Jan08/09原576场景，按新初始化重新生成完整资格表，不能假定仍是旧551合格。Jan12原20景用于开发/验证，已看过的Jan28/Jan30只作历史诊断。独立考核需要另选未参与本次设计与筛选的新日期100景；数据日期、时刻、去重、用户需求及SHA必须在新训练前冻结，当前尚未选择或下载。

建议先做20景非学习开发闸门，再进行单模型训练及固定节点验证，最后按上述五组合在新100景各1次考核。默认主模型采用固定训练预算终点；若65536节点因故停止，不能将它包装成262144终点。完整分母报告覆盖、主体/全体CV、90束目标、峰值、例外及失败；分段记录初始化、策略推断、重构、最终核验、单场景总时间，保留均值、中位数、P95和逐景记录。

如果P1与R3没有明确质量优势，也没有达到相当质量但更低实际计算代价，应如实判定PPO无追加价值，不继续围绕回报或最好个例包装效果。只有单种子时不能声称跨种子稳定。

## 11 方法依据及适用边界

- [PPO原论文](https://arxiv.org/abs/1707.06347)：提供策略更新方法，不能替代本项目的状态、动作和目标设计，也不保证本项目优于搜索。
- [Learning to Perform Local Rewriting for Combinatorial Optimization](https://arxiv.org/abs/1810.00337)：学习选择区域和改写规则，为把决策放在服务区域层面提供方法参照。
- [Learning Large Neighborhood Search Policy for Integer Programming](https://arxiv.org/abs/2111.03466)：将学习的邻域选择与固定求解器分工，为“PPO选区、几何层落实、同求解器对照”提供参考。该文不是本项目PPO或卫星覆盖的有效性证明。
- [Attention Learn to Solve Routing Problems](https://arxiv.org/abs/1803.08475)：说明集合注意力用于构造式组合决策的可借鉴性；其训练使用REINFORCE，不能误称该文已验证这里的PPO。
- [Invalid Action Masking](https://arxiv.org/abs/2006.14171)：支持按当前合法集合构造策略分布，但不说明便宜的局部掩码能够保证本项目最终覆盖。
- [Policy invariance under reward transformations](https://people.eecs.berkeley.edu/~russell/papers/icml99-shaping.pdf)：说明奖励塑形需与任务目标一致。本方案的有限回合差分求和是显式设计，加入成本项会改变质量与计算的取舍，不能声称任何奖励修改都不影响最优策略。

上述论文提供方法基础；区域拆并的动作、边缘例外和本方案J是本项目提出的设计假设，均未获本项目实验验证。
