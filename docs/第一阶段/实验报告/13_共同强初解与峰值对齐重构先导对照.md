# 共同强初解与峰值对齐重构先导对照

S1-AI17-R2｜2026-10-13｜6母24案例的开发先导报告；无模型训练，无新验证或test算法评价。

**本轮在真实共同强初解上找到了进一步降低负载的办法，但没有建立“需要AI来给这八项任务排序”的证据。** 有限活动集重构D1在24个案例中全部完成了可判任务池，9例达到“峰值降低至少1%、上尾和CV不恶化”的预定目标，覆盖5个母场景。原邻域对照D0有8例达到目标，覆盖4母，但只有12个任务池完全闭合。与此同时，固定执行“A区重分”就能覆盖D1同样的9个目标成功案例，主成本已接近离线oracle，因此排序学习门槛未通过。

这支持按原计划检查剩余开发场景，保留有用的非学习重构；不支持直接启动原10000更新模型，也不等于AI整体无用。目标命中、最终发布布局与完整波束数/宽度档案是不同层次，不能互相替代。

## 这次共同起点是真的相同

[报告12](12_可变束数与束宽联合搜索首轮开发对照.md)曾发现，各方法独立限时构造初解会造成缺档。本轮不重新运行旧基线，而从同景已审计的07-CV、07-LEX、JOINT-CV、JOINT-LEX、POST_SHRINK各取一个真实终态，冻结共同强档案。在原0.5°几何初解定义的N≤N₀、Ω≤Ω₀内，按峰值、上尾、CV选共同起点。D0/D1逐字节使用同一parent、场景和八任务描述；24个案例的实际共同来源与SHA均已核对。

数据是Jan12开发母按UTC排序索引[0,4,8,11,15,19]抽取的6母，每母四种合成请求分布，合计24案例。四分布共用位置、飞机ID及该母总请求，不是24个独立母样本。全部评价只涉及第一阶段的飞机几何覆盖、唯一归属、请求守恒、非空束数N≤200及逐束全宽[0.3°,1.0°]；不使用业务满足、承载、PHY、SI或SGM。

主质量比较限制N≤N₀、Ω≤Ω₀；Ω是各束立体角之和，仅为几何占用代理。切片外几何合法的增束、宽度调整结果仍保留到完整五维档案，但不能拿它们的额外资源收益通过主门槛。跨N按原单位峰值、上尾、CV与N/Ω取舍解释，不用P/T归一化分数排冠军。

D0保留较大的原区域邻域、最多8个起点和4次中心交替；D1只改变最多64架活动飞机的归属，使用2个起点、1次中心更新，其余飞机保持原归属并完整核验。两法都使用局部归属资格矩阵和逐机所属束覆盖审核，不只给D1换用更快的核验器。A区围绕最重束，B区围绕稀疏束，每区各有重分、宽度调整、合并、拆分四任务，共八槽；每项独立从同一parent出发，不是连续执行八步。

每任务最多262144次射线对比较、256次几何调用、32个完整候选，D1另受最多8候选限制；3秒是名义安全护栏，不是不可超出的严格墙钟保证。共同准备成本对每法全额加回，实际共享计算不重复计耗；纯射线均值或坐标构造另记调用、输入规模与时间，不冒充射线对比较。

## 改善首先来自飞机归属重分

最容易解释的结果是固定任务槽0，即“A区重分”。它围绕当前最重束重新安排活动飞机的唯一归属，不需要先预测哪个任务最有价值。D1这项任务的9个首次目标命中候选，全部保持N和逐束宽度数值不变，全部改变飞机归属；其中8例中心也不变，1例同时改变中心。因而，这9个早期目标已经可由既有覆盖条件内的负载重分达到，不能把它们全部归功于增加波束或改变宽度。

其它任务也可以产生目标点：D1的A区宽度调整在7例、A区合并在5例命中，和前述9例有重叠，不应相加成21个成功案例。完整任务池还保留增减N、逐束宽度及角域的不同取舍；找到一个满足1%目标的早期点，不等于找到了最终最佳质量点或完整前沿。

最终发布层面，D0有14/24例同时改变N与实际宽度值，D1为17/24；这是另一组真实机制证据，与固定A区重分的首次命中不能混写。实际宽度变化按稳定beam ID对齐保留束，再单列新增束宽度与删除束，不能仅凭宽度数组长度不同计变宽。候选、入档、主切片选择、最终发布分层保存。

本轮仍是同一父布局上的独立八任务探针，尚未完成跨区域、多步联合资源调节。增加最重束宽度这一有限菜单，也不能穷尽“扩大邻近接收束以转移热点请求”等其它变宽机会。即使某任务不成功，也不能推断所有联合N/宽度方法无效。用户要求的最终两变量自适应方案仍需后续完整开发与独立数据验证。

## 为什么暂不训练任务排序模型

离线oracle在已完成的池内知道各任务真实结果，可以挑出达到同一目标的射线对成本最小的实际命中前缀；它不是AI模型，也不是可在线直接使用的策略。规则与随机的成本包含前面任务的实际消耗、命中任务的首次成功前缀以及相同的公共准备成本。随机主对照为事前固定的一份排列，其后100份只描述波动，不挑最好的一份。

D1有9个完整、命中的可判池。相对规则顺序，oracle的射线对成本中位节省**5.3517%**；相对单随机顺序节省**64.4440%**。两组逐案例几何调用均不增加，但前者未达到预定20%门槛。因此，即使能完全知道真实收益，现有规则顺序下可节省的这部分主成本也没有达到本轮要求。

更直接的对照是固定A区重分：它覆盖oracle同样的9个目标成功案例，射线对成本的逐案例相对超额中位仅**5.6543%**，落在结果产生前规定的20%范围内。无需学习就有一个足够接近该目标成本的规则，这构成暂不进入排序学习的第二条依据。

固定槽的几何调用“不增加”检查没有通过，故**不能说固定槽在所有成本、墙钟、最好终点或完整Pareto档案上等价于oracle**。按照事前记录，固定槽反证采用主射线成本，几何调用另报；这不是看见结果后删掉一个不利门槛。G3失败仅针对当前八任务和目标下学习排序的必要性，不否定学习更好的初始归属、构造强布局、可行修复或生成新候选的可能性。

## 计算、审计和本轮能够说明的范围

每法24池×8槽，共192项任务。D0有153项完成并产出候选、2项完成但未找到可行候选、13项工作量截断、24项因区域超过256机而截断；D1为188项完成并产出候选、4项未找到可行候选，没有这些截断。区域上限是D0有限机制的边界，不表示该场景几何不可行，也不能从分母删除。

在每法均全额加入共同准备的可比增量账中，D0累计3,025,944次射线对比较、24,308次几何调用、2,923次候选核验尝试；D1为1,092,147次、6,122次和927次。相应观测时间合计约10.277秒与4.187秒。这些成本说明D1本轮较少计算便能完成池并取得上述质量点；由于两法工作深度、截断和结果集合不同，不能把比值直接称为同质量端到端加速倍数。计数中的“尝试”包括先扣账但未完整结束的审核，与有效候选数分开。

强起点来自历史五法的计算成果，获取成本没有消失；本轮主要比较共享起点之后的增量搜索。实际共享准备只执行一次，可比账对每法加回全额，不把加回量误称重复发生的物理计算。三端任务在同景交错执行，但运行很短，没有取得计算中的CPU/GPU峰值采样，不能补造利用率；射线均值、坐标构造和I/O亦不等于射线对比较。

![全24案例的观测增量成本与工作量；共同准备对每法全额加回，历史强起点成本另账，不宣称严格端到端加速。](../../../outputs/experiments/first_stage_ai_search_20261013/round2/analysis/publication_pilot/figures/05_observed_cost.png)

## 已进入剩余开发范围，AI路线保持开放

G0正确性、G1完整池与G2负载空间均通过，按[方案18](../方案/18_共同强初解与峰值对齐小池重构开发方案.md)已准入剩余14母56案例、896个新任务槽。原24案例直接复用，合计最多80开发案例；算法核心保持f02的Git blob逐字节一致；操作层为扩展准入、安全服务升级等形成独立新执行提交，实际来源以扩展清单为准，不能把全部执行源码仍写成f02。旧先导源码、任务、24案例原字节与原审计保持不动，不热改运行科学源。后续累计统计须合并两段逐案例原始证据，不能重复先导或把新增56误写成全新80。扩展实际启动与进度由运行清单记录，本报告不预报尚未产出的结果。

G3未过不阻止这一已授权的非学习机制确认，但不准入模型训练，也不打开新验证或test算法评价。下一条AI路线优先考虑从原始飞机输入学习构造或修复同质量强布局，以完整初始化和推理成本检验摊销效率；也可根据任务失败与覆盖资格变化研究有证据的新候选生成。它们仍需另行冻结小预算方案，不能把当前固定规则改名为AI，或仅因想获得正结果就追加旧10000更新。
