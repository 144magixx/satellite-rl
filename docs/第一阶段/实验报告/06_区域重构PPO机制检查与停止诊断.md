## 3 动作为什么大量被拒绝

最近窗口为49153–65536，含16384条实际宏动作记录；其中102条STOP、16282条非STOP。

| 非STOP结果 | 次数 |
| --- | ---: |
| 接受并改变布局 | 578 |
| 归属超出所判定的波束足迹 | 9959 |
| 无法为所选用户群找到合法中心 | 5686 |
| 几何覆盖与用户归属不一致 | 42 |
| 布局没有变化 | 17 |

拒绝日志本身不能证明动作在真实几何上不可行。源码核对发现：`apply_action`接受提议后复制了新中心、归属和负载，却没有复制提议中已验证的距离矩阵；下一步继续使用旧中心对应的缓存。尤其当前动作没有再移动某一已变动波束时，该列几何不会被重新计算，可能造成假拒绝。

| 最近窗口分层 | 非STOP提议 | 接受 | 接受率 |
| --- | ---: | ---: | ---: |
| 本回合此前没有接受动作 | 912 | 559 | 61.2939% |
| 本回合此前已有接受动作 | 15370 | 19 | 0.1236% |

9959次“归属超出足迹”全部在此前已有接受动作之后；全65k中同类38977次也全部位于这一分层。确定性回归进一步复现了该缺陷，因此不只是依据统计相关性猜测原因。但5686次“找不到合法中心”中仍可能存在真实不可行情形，不能把全部拒绝都归因于缓存。

完整`actions.jsonl`有65536条，非STOP64423条、接受3095条；原闸门中63876/3064是完成回合内的累计非STOP/接受数。前者还包含停止时未完成并行轨迹中的547条非STOP、31条接受动作。最近窗口分母始终是完整动作日志的16282/578，两套累计口径没有混用。
