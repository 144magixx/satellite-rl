# 保覆盖局部引导完整开发对照与停止

S1-AI17-R8｜2026-10-14｜原20个统一请求开发母场景、A/G/R三法共60槽全部完成；固定2000更新模型的缓存分数，新模型前向与更新均为0。科学分支停止，验证与test保持封存。

**完整合法覆盖已解决，但本轮没有证明固定模型分数带来了足够的增量收益。** A在全部20景都完成局部转移并经D5非回退发布，实际N与宽度也均发生变化；然而，相对同景G/R较好结果达到预定质量条件的仅2景，低于5景门槛。A的平均峰值还略高于几何排序G。因此停止本轮“旧owner亲和只用于同收益候选排序”的分支，不能据合法率、优于随机或变量确实变化而宣称AI有效。[根全60原数组与门槛验收](../../../outputs/experiments/first_stage_ai_search_20261013/round8/analysis/root_actual60_and_gate_acceptance.json)已接受这一负结果；整体后续研究须另立方案。

## 问题、方法与共同条件

R7的集合模型直接给出整套分组时，19/20景未完成孤机补全。R8依[方案25](../方案/25_保覆盖骨架下的固定模型局部引导试点.md)改为从共同合法Wenv布局出发，每步只接受通过覆盖与资源检查的整机转移。模型不再负责从零猜出完整布局，只用已经保存的full200 owner分数，改变相同整数负载收益候选的尝试次序。每种方法的局部终态再交给同一个原D5一次。

| 方法 | 相同主要负载键下的次序 | 模型信息 |
| --- | --- | --- |
| A：模型亲和排序 | 目的束共归属亲和增量降序，再按几何距离 | 原2000更新模型缓存owner分数，温度1 |
| G：几何排序 | 目的锚点方向距离减来源锚点方向距离，升序 | 无 |
| R：固定哈希排序 | seed51001及原身份转移元组的SHA256升序 | 无 |

三法共享原20景、初始Wenv、候选池、负载键、接受条件及计算上限。池最多512个原始转移元组，每法最多取出128个；过期或拒绝项也消耗名额。局部阶段保持N和锚点不变，使用精确整数键“最大束人数、最重ceil(0.1N)束人数之和、全束人数平方和”，严格改善才可能接受。随后原D5可改变实际N和成员包络宽度。A只能改变次要排序，不能改变候选池或接受规则，未训练新动作模型。

每机请求固定21,600,000 bit/s；完整飞机、稳定ID、唯一整机归属、请求守恒、实际非空N≤200、全宽[0.3°,1.0°]及同景Ncap/Ωcap均保持。请求负载不代表实际承载，第一阶段不使用PHY、SI、SGM或业务满足指标。峰值为最大束请求，上尾为最重ceil(0.1N)束请求的均值，CV为全部非空束请求的总体标准差除以均值。下表Mbps只将原bit/s除以10⁶。

本批是已反复使用的20个开发母场景，不是新独立test。只有一个历史训练seed51001、一个固定2000更新模型；本轮没有多种子稳定性或独立泛化结论。

## 为何合法率与变宽不能代替AI贡献

R8从一开始就提供完整合法Wenv，接受规则逐步保覆盖，共同D5还会继续调整布局。三法全部20景非回退，说明这套公共方法在本批输入上可用；它不能解释为只有A解决了R7的分组失败。R7与R8的提议构造也不同，不把非回退1/20到20/20写成同算法继续训练的进步。

A实际发布全宽范围为0.3°–0.993145943°，G为0.3°–0.994938312°，R为0.3°–0.994387165°，真实变量没有被固定为100束或0.5°。但原R5宽度分布判定在束数变化时即可计分布改变；若原布局已有异宽，仅增删floor束也可能满足该判定。因此20/20的能力计数不能单独证明模型学会调宽。局部阶段不调N，模型只决定候选次序，最终N和宽度变化还包含共同D5的作用。

本轮更重要的反证是A没有稳定超过同预算几何排序G，且相对G/R较好者只在2景达到预定质量条件。较随机好只排除了部分无信息次序，不能替代对强规则的增量证明。

## 与原强参照的关系及下一步线索

同景原R7 RULE和T只读复用，未新增调用，也不作为隐藏追加门槛。按reader保存的完整20项原参照计算：

| 原参照 | 峰值均值（Mbps） | 上尾均值（Mbps） | CV均值 | N均值 |
| --- | ---: | ---: | ---: | ---: |
| R7 RULE＋D5 | 892.080 | 582.990234 | 0.700742968 | 97.15 |
| R7 T | 960.120 | 720.912545 | 0.793072287 | 88.15 |

A的峰值、上尾和CV均值均弱于原RULE；因此本轮不能称作当前最好的负载规划方法。T与A则各有不同指标取舍，不能笼统说T全面更好。各法实际N不同，也不能称这些均值构成同N优势或完整Pareto支配。新局部处理还增加了工作量，原RULE/T的历史获取成本各自保留，不作相同总预算或速度排名。

较少的实际束数是解释负载差异的一条线索：A平均92.05束，原RULE为97.15束。但束数、锚点、成员结构和搜索轨迹同时不同，本轮没有隔离它们，不能断言“少束”是唯一原因。另一条直接的设计限制是：R8保护了Wenv的合法性，却没有把已知更强的RULE结果作为质量保底；它也只在固定主要负载键相等时利用模型，可能留下很小的可学习决策空间。后续应先保护可靠强终点，再验证具体局部结构动作是否确有超越强规则的可学习差异，而非继续调旧亲和温度或放宽门槛。该判断是下一轮假设，不是已证因果结论。

[已存布局与轨迹的只读诊断](../../../outputs/experiments/first_stage_ai_search_20261013/round8/analysis/mechanism_01/mechanism_observations.json)进一步收窄了解释范围。原RULE的初始槽数在20景都等于Wenv，并非靠更多初始槽获益；本批实际Ncap为59–123、中位110，不能把统一N≤200误当每景都能增加到200。全部60条局部轨迹都增加Ω，利用率中位数从Wenv的69.1479%升至87.2634%，局部终点最高99.9990%；但D5最终仅7/60达到各自Ncap。D5累计接受625次SPLIT、113次REFIT和42次MOVE，53/60条SPLIT阶段触及64候选上限。由此可以提出“局部负载改善消耗角域余量，随后拆分又受资源与有限搜索共同限制”的假设；原日志并未完整记录所有资源拒绝原因，因此这些关联不能将Ω或候选上限单独判为根因。该诊断没有新几何搜索或模型调用。

## 计算、故障与恢复边界

实际科学计算为60次local与60次D5，新增W、T、模型前向及参数更新均为0；四个手写fixture三法各一次的12次工程local单列。旧2000训练及前向属于已发生成本，不能填成0。

首段完成0:G后，0:A原生子进程因压缩引用缺少读取器要求的字段，在进入局部算法前失败。该次native guard耗时2.708343秒；故全过程local原生启动61次、实际local算法60次，D5为60次，两者分列。原G0、失败WAL、请求、日志和旧索引均保留，修复仅涉及有界输入读取与恢复控制，未修改四个科学核心、旧模型或D5数学。

本组按07:00要求暂停；用户08:10明确“继续”后，经新执行时段和重启后真实资源核验，以原ID接续其余59槽。旧G0来自旧boot，后59槽来自新boot，未重跑G0。原暂停文件保留，新暂停仍有效。独立reader在精确本地来源到远端控制引用映射修复后完成全部审核，其[原生执行回执](../../../outputs/experiments/first_stage_ai_search_20261013/round8/analysis/actual_v4_01/native_reader_execution_receipt.json)记录exit0、外部观察33.274385秒；内部审核32.643077秒包含在内，两者不相加。reader及根复核均未执行新搜索或模型调用。

原失败父进程的精确完整费用仍未知，保守外部上界141.577495秒包含观察等待，不能冒充方法耗时；完整方法费用保留null。因此本报告不作速度、摊销或回本结论。三图PNG/PDF、原数值CSV和绘图脚本已生成，见[图表核验](../../../outputs/experiments/first_stage_ai_search_20261013/round8/figures/visual_QA_receipt.json)。科学计算与数值审计已闭合；完整双端归档以真实归档回执为准，不由本报告提前声称完成。
