# 欧洲训练异常诊断与下一阶段方案

诊断日期：2026-09-28晚启动，2026-09-29凌晨归档。对象为G07：`train_sac_20260928_142100_38559f37`，冻结源码`01457f245bf0ab0e23873616e44975693014e3d0`。方案编号P03。

**结论：价值网络确有明显估计偏差，训练过程尚不能称为稳定收敛；但“模型完全没有学到东西”和“所有loss一直上涨”也不符合完整日志。下一阶段优先做一组关闭Critic训练随机性的对照，随后再单独检验场景顺序；状态信息与奖励改动分开安排。**

本轮完成原始日志分析、冻结源码审计、最终断点的少量只读前向与确定性环境小例。没有修改训练算法、原数据或权重，没有启动新训练或长评价。以下实验是建议，未获本轮运行授权。

### 1.3 Actor loss上升有一部分来自Q整体下移

本实现优化的策略损失为`−平均(策略期望Q + α×动作熵)`。其中Q是价值网络估计的后续收益，动作熵表示选择的分散程度。若Q整体从正值移到很大的负值，即使动作概率变化不大，Actor loss也会变成很大的正数；因此它不是“越接近0越好”的训练成绩。

该解释符合冻结源码`agents/workbench_algorithms.py:352–359`和[离散SAC原始推导](https://arxiv.org/html/1910.07207v2)。但它不能替Critic的估计偏差开脱，下面的终止状态核验是更直接的异常证据。

## 2. 原因定位：哪些已证实，哪些仍需对照

### 优先级1：Critic的价值拟合失准，dropout模式差值得首先检验

从最终断点最近2万条经验中，以固定种子51001分层无放回抽取64条终止、64条非终止转移，仅在CPU做前向，没有参数更新。

对于64条“分配最后一束之前的状态＋实际采取的动作”：

- 评估态Critic的Q均值为**−46.13**，对应即时奖励均值仅为**+0.065**；平均绝对终止TD误差为46.20。
- 最后一步的正确目标就是即时奖励，**没有下一步价值项**。所以这是明确的价值拟合不足证据，不依赖猜测未来回报。
- 对同一批状态和同一组权重，Critic训练态做12次前向，Q均值为−29.03，比评估态高17.10；同一条转移跨前向的标准差平均为12.24。

原因线索是：在线Critic用带0.1 dropout的训练态拟合，目标Critic固定使用关闭dropout的评估态。Dropout会在训练前向时随机屏蔽一部分网络信息；当前实测的两种模式预测差别很大，目标又依赖网络自身预测，可能相互放大偏差。**模式差已确认，是否导致整段训练异常还要通过同条件重训验证，不能认定为唯一原因。**

固定随机样本的最终结果以上述−46.13/+0.065为准；早期按顺序抽样的临时检查约为−43.56/+0.04，不用于正式统计。探针保存了取样方法、种子、解释器和冻结导入路径。

双Q取小值也有保守作用：64条非终止样本的策略加权双Q最小值，比两者均值平均低3.20。这个数是**相对双Q均值的差**，不是对真实价值低估3.20的证明。本实现先合成完整动作Q再取最小，未发现历史“逐头取小再求和”的错误。离散SAC文献确实讨论过低估和熵—价值耦合不稳定，但文献不能代替本项目因果实验，现阶段不直接更换为平均Q或整套新算法。[相关原始研究](https://arxiv.org/html/2209.10081v4)

旁证：G01中国有掩码参照的最后5万步日志，Q均值约+58.00、Critic 1 loss均值0.657、TD均值0.629；G07相同日志窗口分别约−477.75、892.30、13.88。两组配置的网络、学习参数和奖励相同，场景/环境不同；这只能说明此类数值漂移并非每个运行都必然出现，**不能跨环境排名或据此确定dropout因果**。

### 优先级2：按时间顺序喂场景，经验池看到的负载范围不均衡

已核对每个训练回合的来源SHA：`场景序号=回合序号%576`，同一序号各轮数组相同。576场景按两日时间顺序排列，一个循环需要57600步，而20000条经验只覆盖最近约200回合，即约34.7%的循环。

结果是模型会连续经历一段低负载，再连续经历另一段高负载；经验池的抽样虽随机，池内的业务范围仍随时间整体变化。前2000步预热也只覆盖最初20个夜间快照。第2与第6轮同场景回报相关系数约0.821，需求满足率约0.902，说明原曲线有很强的场景难度形状。

这解释了**为什么原始训练曲线不能直接看成学习进展**，也使遗忘及目标分布变化成为合理候选原因；尚未证明打乱顺序就能消除Critic失准。应只打乱场景顺序，不改变场景数组、每轮出现次数或单个场景内的100束需求排序。

### 优先级3：当前204维输入遗漏了会影响奖励和后续分配的信息

当前只输入本束位置/需求、剩余功率、本组逐槽干扰与占用。配置写“需求已知”，并不等于把全场景需求输入了网络；平均业务需求β、明确处理进度和剩余需求都未选择。

已构造一个确定性欧洲小例：当前束与位置布局不变，只将未来99束需求减半，排序仍然成立。两份初始204维观测的SHA完全一致，同一动作得到相同容量293.46 Mbit/s，但β从61.81变为32.19 Mbit/s，奖励从1.905变为1.682。**模型看到相同输入，却被要求解释不同即时奖励。** 这证明存在观测缺项，不证明它独自造成G07负Q漂移。

处理进度没有直接输入，也可能增加末步价值与其他阶段的区分难度。占用和剩余功率能提供部分线索，但不能据此声称已有完整进度信息。增加β/进度等少量信息也不能补齐未来全布局的干扰关系，后者仍是后续问题。

### 优先级4：业务分布变了，旧奖励和输入尺度没有重新校准

576个训练场景的波束需求范围约4.13–3514.92 Mbit/s；42.97%低于旧基础档位的100 Mbit/s，2.59%高于1000 Mbit/s。这里的100–1000是旧基础档位参考范围，旧数据还有扰动，**不是合法范围限制**。当前需求仍除以550 Mbit/s，不会截断，最大归一化值约6.39；未发现数据被裁成原范围。

旧奖励包括：全体已服务波束的SI增量达到1给+1，否则−1；加本束当时的SGM；扣供需差超过50 Mbit/s后的惩罚。它不是“达到本束10%基本需求就加分”，也没有直接保证最后100束都达到基本服务门槛。

固定验证中SI上升而回报、SGM下降，说明模型在多个目标之间发生取舍。4000回合的四个奖励分量重新相加，与原回报最大差约`9.95×10⁻¹⁴`，未发现绘图拼错奖励。因此“回报未上升”不能全部归咎于图；但也不能用回报一个数判断需求满足率退化。奖励改造应在价值学习稳定后单独比较，暂不直接切换历史上失败过的融合奖励。

## 3. 本轮排查没有支持哪些解释

- 未发现终止状态继续自举、温度更新符号相反、联合掩码采样与学习概率不一致等明确公式错误；查的是本次冻结工作台实现，不是旧脚本。
- Actor行动和更新均使用一致的评估态概率，目标Critic也固定为评估态；风险集中在在线Critic的训练前向，不能泛称所有网络都忘记调用`eval()`。
- 原始任务正常完成，结果有有限数值；没有依据认定是CUDA故障或NaN导致这组曲线。
- 损失不等于服务成绩，88.93%考核成绩也不等于训练已经稳定收敛；目前缺同一验证集上的未训练同结构/规则参照，不能量化模型相对这些参照的学习净收益。
- 最终恢复断点已滚动覆盖，当前只有最终完整断点及最终/验证最好等策略文件。40次验证日志存在，**不代表40份历史Critic断点都存在**；不能从最终模型还原早期模式差。

## 4. 下一阶段建议怎样做

### 第一批：只检验Critic训练随机性，优先复用已有G07参照

建议只新增**1组40万步**，从头训练、种子51001：把网络`dropout`从0.1改为0，其他网络尺寸、204维状态、旧奖励、联合掩码、576个训练场景及顺序、20000经验池、学习率、温度规则和验证协议保持相同。

Actor在现实现中始终用评估态计算动作概率，所以该参数变化的主要实际作用是关闭在线Critic的dropout；仍须核对运行配置和前向模式。模型参数量不变，不把临时关闭旧模型dropout后再测的结果称为重训改善。关闭dropout会改变随机数消耗；相同种子不代表两次训练的动作或经验逐步相同，“单因素”指只改一项学习配置，最终在同场景下比较结果。

| 项目 | 参照A | 候选B |
| --- | --- | --- |
| 来源 | 已完成G07及其保存日志/权重 | 待授权的新工作台任务 |
| 唯一学习配置差异 | dropout=0.1 | dropout=0 |
| 种子、预算 | 51001，400000步 | 51001，400000步 |
| 数据与奖励 | 同一冻结场景；旧奖励/联合掩码 | 与A相同 |
| 主结果模型 | 固定40万步终点 | 固定40万步终点 |
| 日常比较 | 原20验证场景，各3次随机动作 | 相同场景与动作种子 |

实施前用冻结版本做少量实际更新与恢复正确性检查，确认额外诊断没有改变随机状态或训练轨迹；这些是工程检查。正式任务使用工作台、DQN/CUDA、冻结提交和后台子agent，不在主对话长期同步等待。

**12万步设诊断检查点，不设为临时挑最优模型的依据。** 这个位置覆盖G07在8万–11万步发生的大幅Q变化，也经历了两轮以上完整场景。预定查看60k、90k、100k、120k及后续每1万步的诊断，不能看到某个好节点就提前宣布成功。出现非有限值、数据/资源账错误等硬故障时停止并保留断点；仅loss变大不能作为随意提前终止或延长预算的理由。

新增保存应包括：每1万步轻量Actor/Critic/目标网络/α快照、固定探针的终止与非终止TD、同权重训练/评估态差、双Q差、裁剪触发比例和场景分层验证结果。完整恢复断点仍滚动保留，并保留阶段末断点，避免为每个节点复制完整经验池。现有Q、目标Q、TD、梯度、熵和温度日志继续使用，不把已有字段说成尚未记录。

判断方向需预先固定：终止TD与模式差下降、Q尺度不再持续漂移；同时验证SI、10%达标束数、全部100束达标率、SGM与资源约束不能只挑有利项。新增诊断没有G07对应历史快照的部分明确记缺失；若必须做早期同批机制比较，再单独提出新增参照训练，不默认重复G07。

### 第二批：若仍有周期波动，再只改场景出现顺序

在已选定的学习设置下，对照“固定顺序循环”和“每轮576场景无放回随机排列”。每个场景每轮仍出现一次、需求数组不变、经验池仍20000；场景内仍按需求排序分配100束。场景顺序使用独立随机源，保存种子、每轮排列和断点位置。

先不同时扩大经验池、改学习率或改需求生成器。若随机排列后仍有明显跨负载遗忘，再另立20000与60000经验容量对照。第二批预算与任务另行确定，不包含在首批新增1组40万步内。

### 第三批：分别检验缺失状态、奖励目标和剩余学习设置

1. **补充必要状态。** 优先β、处理进度和剩余需求等少量信息。原13令牌结构被服务端锁定为原204维，不能直接勾选后就假定兼容。可设计独立版本的全局信息令牌；做“同一扩展结构、额外信息屏蔽/实际输入”的对照，使参数量和结构一致，原G07只作补充参照。全布局/相互干扰信息以后再扩展。
2. **对齐奖励。** 在学习设置和状态固定后，再比较旧奖励与围绕终态基本服务、需求满足率的连续增量奖励。保持SGM和功率为独立报告指标，候选权重须由量级检查确定；不同时切换掩码、网络和奖励，也不把历史融合奖励改名当新方案。
3. **其他参数后置。** 学习率、温度目标、双Q聚合、Huber损失或Q截断，仅在对应误差/梯度证据支持时各自对照。单纯降低学习率或把loss画在更窄坐标上，不能消除隐含状态与目标失准。

这三项均不是本轮获批实施清单，不能一次性打包修改后声称找到了单个原因。

## 5. 比较与考核如何避免得到误导性结论

- 日常分析继续使用现有训练集和20个验证场景，按训练场景总需求预先分低/中/高负载，阈值只从训练集确定。报告逐场景配对差、各层均值和全部100束基本服务比例。
- 当前01-15考核结果已经参与问题定位。后续同一考核集可以保留为“历史固定比较集”，不能再把反复围绕它改方案后的成绩当全新独立考核。最终结论需预先冻结未用于本轮诊断的新日期；数据取得后再锁定100场景、每场3次动作。原/新权重在新考核上一起测。
