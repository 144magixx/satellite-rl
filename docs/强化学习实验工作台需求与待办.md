## 1. 目标与使用流程

建设本机浏览器可用的“卫星资源分配实验工作台”。用户选择算法、状态特征、网络、奖励、动作约束和训练参数，看到实际输入维度、网络结构、奖励公式，保存方案后，一键提交到本机 DQN/CUDA 后台运行；页面能查看真实训练进度、日志、指标、模型和同场景评价。

流程：新建/复制方案 → 配置与检查 → 保存不可变配置 → 后台训练 → 查看曲线与日志 → 选择/导入模型 → 导入或选择实际测试场景 → 逐束查看与配对比较 → 导出结果。

首版拟按“本机单用户、浏览器界面、本地 Python 后台、单 GPU 资源队列”设计。局域网多用户访问、云训练和权限管理后置。技术选型在实施前结合本地依赖确定，不把纯静态网页当成能启动训练的完整系统。

### 3.1 状态空间：特征库与研究内容

当前输入是 **3＋1＋100＋100＝204 维**：当前波束经纬度与业务需求、剩余功率比例、面向当前波束的逐槽干扰、本组频谱占用。见 `envs/satellite.py:357-387,434-458,752-774`。它未直接提供处理进度、全场景平均需求、剩余需求、历史逐束分配和当前服务情况、其余七组占用。

已有[204维诊断](../outputs/experiments/sac_comparison_20260924_r2/single_seed_51001/state_diagnosis/中文204维状态诊断.md)基于冻结提交 `36c14d74cbe6b9cf7410ee0595ee6d73083afdc8`：改变未来 99 束需求，可以保持动作前观测完全相同，而相同动作的旧奖励改变，因为 SGM 用到了观测未显示的全场景平均需求 beta。这是已有信息缺口证据；不是本轮新实验，也不证明扩充输入一定提高成绩。诊断的历史零槽功率口径不能冒充当前所有奖励版本的共同规则。

候选库按可解释的特征块组织：

| 特征组 | 候选内容 | 规模及信息条件 |
| --- | --- | --- |
| 当前波束 | 位置、业务需求；可选路径损耗、无干扰可达速率 | 原有3维；后两者是现有信息的衍生量，不是独立新信息 |
| 进度与资源 | 当前序号、剩余波束数、组号、剩余功率、每个剩余波束可用功率 | 每项标量或组号编码；有明显相关和重复，不能全部默认勾选 |
| 全局与后续业务 | beta、剩余需求总量/均值、需求分布摘要 | 仅在调度时已知业务需求时使用；在线业务只能使用当时可得预测及误差信息 |
| 当前服务质量 | 已处理束平均欠供、达标比例、最低/低分位满足率 | 通常每项1维；明确已处理/全部波束口径、空集合值与动作前时点 |
| 频谱与干扰 | 本组占用、逐槽干扰；其余组占用、最长连续空槽、可行组合数量 | 原有200维；其余7组完整占用增加700维，摘要可减维但会丢信息 |
| 历史逐束集合 | 位置、需求、现速率、组号、起点、槽数、功率、有效记录标记 | 后续高级候选；规模依字段编码，需专用集合/序列编码器 |
| 历史观测窗口 | 最近若干步可见观测、动作、反馈 | 用于部分信息场景的研究候选；须区分回合边界，不能把最终结果塞回早期输入 |

每个勾选项保存：唯一名称/版本、中文含义、形状、单位、归一化、计算时点、数据来源、缺失值/掩码、依赖、与其他项的重复关系。特征顺序固定或通过显式操作重排，输出维数和字段清单一同保存。CNN 的槽位块和 Transformer 的片段不能任意打散；改变布局需同步编码器。

训练输入与页面展示字段独立：界面可以显示测试结束后的速率，但不能把它作为该回合早期动作的观测。场景预先已知全部需求还是逐步获知，必须是显式配置。归一化不从最终考核集估计。

首个候选研究宜从“进度、已服务平均欠供”两个小特征分别核对，再考虑 beta；一次只改一个因素便于解释。先证明时点、维数、归一化和信息来源正确，再用同条件训练判断是否有益。维数更多不是验收指标。

### 3.2 网络与算法

首版建议“结构模板＋参数编辑＋自动结构图”：MLP 的层数/宽度/激活，CNN 的卷积层/通道/核/步幅，Transformer 的编码维度/层数/头数/前馈宽度/Dropout。逐层显示输入输出形状、参数量；可展开策略网络、价值网络和目标网络。图由后端真实构建结果生成，不能只画一个与实际模型无关的示意图。

SAC 展示 Actor、双 Critic 及目标网络；PPO 展示 Actor 与 V；DQN 展示 Q 与目标 Q。策略网络和价值网络是否共享编码器必须明确，默认保留各算法已核实结构。首版先接入各算法已有骨干，跨算法骨干组合逐项开放；能力不支持时禁用并说明原因。

算法名称之外保存实现变体：SAC 公式版本，PPO direct/grouped，DQN 分量式动作价值。当前三分量输出的价值组合不等于完整联合动作价值。动作定义包括频率起点、连续槽数、功率档位、单位、组号来源、可行性规则；不同旧入口的功率步长并不相同，不把旧算法直接放在一起称同条件对比。

任意拖拽搭层、分支/残差、循环网络、图网络和联合动作价值模型列为后续扩展。首版参数式编辑已能看见并改变网络结构，同时避免无法训练的自由连线。

### 3.3 奖励与惩罚：覆盖广，定义严格

组合形式为：`r_t = Σ(权重 × 归一化步进奖励项) − Σ(权重 × 归一化步进惩罚项) ＋ 终态指示 × 终态项`。每项可选是否启用、权重、结算方式与尺度；界面显示数学公式、中文含义和一条真实样本的分项计算。

| 候选类别 | 可提供的项 | 必须说明 |
| --- | --- | --- |
| 需求满足 | 全体波束需求满足率增量、终态满足率、欠供量减少 | S=Σ min(R_i/D_i,1)；区分总分与均值，计入新动作对旧束的影响 |
| 基本服务 | 基本容量达标程度增量、达标束数、未达标比例 | 明确基本容量阈值，达标数与连续达标程度不是同一项 |
| 供需匹配 | 本束SGM、全局SGM增量、终态SGM | 明确beta与取值尺度，本束项和全局项可能重复 |
| 吞吐量 | 总速率增量、终态总速率、按需求截断的有效吞吐 | 过量供给是否继续加分须明确 |
| 公平性 | Jain公平性、最低/低分位满足率、服务差异 | 需新增定义和检查；全零时、未服务束及全部波束分母必须规定 |
| 资源成本 | 实际功率、频率槽用量、单位服务的资源成本 | 比值分母为零的规则；不能把低服务导致的低功耗说成节能改善 |
| 干扰 | 历史波束速率损失、SINR余量不足、干扰风险 | 与全局满足率/吞吐增量可能重复；SINR与风险需补充明确计算 |
| 供给偏差 | 欠供、过量供给、基本容量缺口 | 与SI/SGM/基本服务项有重叠，显示提醒 |
| 行为与失败 | 零槽、占用冲突、越界裁剪、请求/实际动作偏差、提前终止 | 原始请求动作须在环境改写前保存；失败回合不可删除 |
| 约束违反 | 超功率量、非法动作、未完整处理 | 奖励惩罚与硬约束分开，不承诺靠负分保证合法 |
| 辅助反馈 | 向目标靠近的势函数塑形 | 高级研究项；与改变业务目标的奖励组合分开标记 |

当前已有 `legacy_original/legacy_repaired/fused` 保留为明确命名的预设。`legacy_original` 和 `legacy_repaired` 还涉及零槽功率记账差异，所以应在新配置中把奖励、物理环境和记账版本分开保存，不能当成只切换一个系数。现有融合奖励为 `2ΔB＋ΔS＋0.2ΔG−P_actual/3000`；已有正式单种子结果下降，不能作为“推荐最佳奖励”。出处：`envs/satellite.py:916-919,993-1041` 及[当前奖励函数](../Q&A/算法与训练/当前奖励函数.md)。

库中候选不等于全部实现，更不等于全部应同时启用。每项须经过精确口径、来源和正确性检查后才进入可训练菜单；未接入项显示“待实现”。公式预览与后台计算共用同一份配置定义；记录原始项、归一化项、加权项和总和。首版支持受控项组合；任意Python表达式不作为默认输入方式。

物理约束另列：总功率、起点/槽数边界、连续空槽、合法功率档位、无可行动作时的处理、可选最低资源预留。联合可行性要检查起点×槽数×功率组合；三个独立可选集合不保证组合合法。预留/保底规则属于新增环境机制，须单独验证；并非当前默认已实现。

### 3.4 训练参数与运行管理

公共项：交互步预算、种子、优化器、学习率、折扣、批大小、梯度处理、评估频率、断点频率、场景来源和排序、数据划分、运行目录、模型选择规则。只显示当前算法支持项，不把不可调的参数做成无效输入框。

专属项：SAC 的回放容量、预热、更新频率、τ、温度与目标熵；PPO 的采样长度、GAE λ、裁剪范围、更新轮数、熵系数与价值损失系数；DQN 的ε探索日程、回放、目标网络间隔及损失选项。参数默认值从可追溯预设读取，界面改动后以实际后台配置为准。

启动流程：检查配置/模型可构建 → 检查实际 DQN 解释器、CUDA 和导入路径 → 保存源码版本、配置、实际场景与校验值 → 资源允许即运行，否则排队。若 GPU 不可用明确报错，不静默回退 CPU。双击或断线重试不得重复创建训练任务。

持久后台进程负责训练，页面刷新、关闭或主对话停止不会取消任务；重启服务后从磁盘恢复任务记录，并结合实际进程核对，不能只信滞留的 running 字段。停止与恢复边界应明确，先支持可验证的保存点恢复，不承诺任意时刻精确续跑。改变配置需复制为新实验，不覆盖正在运行的配置。

曲线分别显示回报、各奖励项、验证业务成绩、损失、SAC温度/熵、DQN探索率、PPO相关诊断、资源消耗和动作分布。缺失值显示缺失；平滑不改原始数据；错误保留堆栈、场景、最后正常断点与运行状态。

### 3.5 模型导入与测试

模型包应包含权重、算法变体、网络配置、特征清单/顺序/归一化、动作映射、环境/奖励版本、代码版本与训练来历。仅 `.pt/.pth` 文件时，先识别支持的格式；无法恢复配置则由导入向导补全并严格校验，不能猜测后静默加载。只支持明确的权重/断点格式，不默认执行任意序列化模型对象。

相同维数不代表相同状态语义。改变特征顺序、归一化、动作档位或网络后，旧权重通常不能继续冒充同一个模型。推理权重与可续训断点分开呈现；缺优化器/回放/RNG等内容时不提供“精确续训”。

测试场景支持仓库已有场景格式，导入表格模板的字段与单位在实施时固定：至少包括波束身份、位置、需求、处理顺序、分组及必要环境参数。保存实际数组与哈希，不能仅存种子。训练/验证/最终考核分开，禁止用最终考核集自动挑最好模型。

成绩按全体目标波束最终速率计算，包含后续干扰和未服务束。需求满足率、SGM、基本服务达标数、零容量、公平性、吞吐、功率、频谱、裁剪、超限、完整处理率并列。图表支持逐束需求与速率、频率槽分配、功率分布、地理布局（有真实位置时）和动作逐步回放。贪心/固定等基线使用相同实际场景、环境及约束；不同奖励的累计回报不直接排名。

## 6. 理论依据与限制

[Kaelbling、Littman、Cassandra（1998）作者原文](https://people.csail.mit.edu/lpk/papers/aij98-pomdp.pdf)研究部分可见环境中的决策：当前观测未包含所需信息时，可考虑保留历史或对未知状态的估计。对本项目采用哪些字段，仍以可获得信息和本地对照为准。

[Ng、Harada、Russell（1999）原论文](https://people.eecs.berkeley.edu/~russell/papers/icml99-shaping.pdf)说明，在其MDP假设和边界条件下，`γΦ(s')−Φ(s)` 形式的辅助奖励具有保持最优策略的性质。普通的 `ΔS`、`ΔB` 与任意加权和不能自动套用这个保证；也不能据此承诺函数近似模型训练会改善。本文只是设计依据，不宣称本项目已实现此项。
