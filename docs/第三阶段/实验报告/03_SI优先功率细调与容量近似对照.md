# S3-P03 SI优先功率细调与容量近似对照

报告交付：2026-10-04。两端工作台实际完成状态最后核验：2026-10-03 23:35（北京时间）；只读归档与审计随后完成。

**主要结论：**在相同100景中，B、C继续调整A给出的功率后，两种预算的平均SI都上升，但幅度很小：B比A高0.00158/0.00171个百分点，C比A高0.00229/0.00248个百分点（前者为3000 W，后者为初始总功率上限）。C比B平均再高约0.00071/0.00077个百分点，但有15/8景反而低于B。两种追加路线的SGM普遍低于A；C的完整单次路线约11秒，A约3.9秒。B/C没有新增把波束推过严格基本服务门槛的情况。就本次考核而言，SI确有微小改善，同时付出了更多时间和一些供需匹配程度，不能说C全面优于B或A。

双端Jan27考核均完成。共100个共同场景、每景3次动作、两种功率预算、A/B/C三组，合计1800条方法结果和18万条终态逐束记录；新增训练交互为0。下面所有场景比较先将同景3次动作平均，再比较100个场景。

## 实验范围与方法

T0固定使用G11的150000步终点（训练seed 51001、固定α=0.01），权重SHA256为 `ae095e8246d22b2716ba154315cee18584917d215580821cb53f9aeba78eb824`。考核为事先冻结的ADS-B 2024-01-27共同100景，动作seed 53001–53003。冻结科学源码为 `e85a9429461a358ba2e11614a3cce4671d12b68e`。3000 W和初始总功率上限各在独立远端4090D实例并行运行，两端共享存储但任务目录隔离；每端可见16个逻辑处理器、CPU亲和性为16，OMP/MKL/OPENBLAS/NUMEXPR四个线程环境变量均设为1。T0模型在GPU推理，功率求解在CPU执行。DQN为Python 3.11.11、PyTorch 2.3.1+cu121、NumPy 1.26.4、SciPy 1.14.1、CVXPY 1.6.5及Clarabel 0.11.1。运行ID、GPU身份与配置见[运行清单](../../../outputs/experiments/stage3_si_priority_20261003/run_manifest.json)。

T0先给每束选择频率槽和初始功率，之后固定频率槽。A是原SCA；B从同一A结果继续调整功率，先提高全部波束的需求满足率SI，再守住找到的最高可行SI尽量提高供需匹配程度SGM；C与B采用相同目标和追加预算，改用更贴近真实容量变化的功率估计。B、C允许SGM低于A或T0。B对A同时改变目标顺序并增加一次求解，不能把差值只归因于其中一项；C对B主要比较容量估计方式。

A和B/C各追加段的共同限制是每段最多2000次物理容量调用和30秒求解；每段内部的SI阶段与SGM阶段各最多300轮。B/C完整路线含公共A，最多4000次容量调用和两段共60秒求解（最终调用与检查可能造成几毫秒墙钟尾差）。SGM阶段把找到的最高可行SI作为固定门槛，只允许1×10⁻⁸的SI数值容差（按0–1表示），不随较差的新解反复下调。连续功率非负，仅受整景总功率限制，空槽束为0。最终SI/SGM按全部100个目标束在最后动作及全部干扰后的结果计算。有效承载为环境计算的 `min(C,D)`，并非实测流量。

## 证据、限制与复现
