# 公开数据集与合成业务场景调研

调研日期：2026-09-28。关联：[P02方案](../方案/04_训练场景泛化与第一阶段衔接方案.md)。初始请求为公开数据与生成方法调研；用户随后明确允许使用欧洲数据，并要求单独建立欧洲训练环境。该补充授权用于环境实现，正式训练配置与预算仍待确定。

## 1. 结论与选择

**有公开可用的数据，但需要组合使用。** 已找到用户坐标与Mbps需求的卫星仿真样例、开放航空轨迹、船舶数量栅格、人口栅格和真实移动通信活动数据。本轮未找到同时具备明确开放许可、无申请获取、真实通信请求量、精确时空位置、长期航空/卫星覆盖的完整数据集；这不等于证明这样的数据绝不存在。

建议采用“真实位置或轨迹＋可解释业务模型＋受约束的场景变化”的路线。航空主线优先核查开题报告已有ADS-B资产；公开替代首选ADSB.lol，OpenSky作为有使用条件的补充。没有真实轨迹时用航路/机场布局与轨迹模型生成；地面业务可以利用WorldPop。通信活动数据用于校准时空形状，绝对需求仍需业务依据或明确假设。

必须区分四种量：

| 数据量 | 可以说明什么 | 不能直接当作什么 |
| --- | --- | --- |
| 飞机/船舶/人口数量及位置 | 用户潜在空间分布、移动规律 | Mbps需求 |
| 归一化活动/CDR数量 | 相对忙闲、热点与周期 | 字节数或请求速率 |
| 服务流量/已实现吞吐 | 已被网络传送的业务、链路表现 | 未受容量限制的全部请求 |
| 生成器输出的Mbps需求 | 给定业务假设下的请求 | 运营商实测需求 |

“公开可下载”“可用于研究”“开放许可证”分别记录。以下访问状态是本次核查事实，不保证链接以后不变；本轮未代用户填表、申请账号、签署许可或发送邮件。

## 4. 缺少完整真实业务数据时怎样生成

### 4.1 先定义可解释的业务，而非只换随机分布

建议先实现轻量场景生成器，第一版仍输出一个时刻的静态需求；没有必要先搭建整套包级网络仿真。依赖顺序如下：

```mermaid
flowchart LR
    A[服务区域 日期 业务类型] --> B[用户位置或航空轨迹]
    B --> C[接入人数 会话活动 请求量]
    C --> D[时空相关的业务需求]
    D --> E[覆盖规划与用户归属]
    E --> F[每束需求与对应物理场景]
```

业务类型至少包含分散地面、单/多热点、航路带状、枢纽聚集与局部突发。每个家族内部变化总量、热点位置、范围和强度；航空器沿连续航路移动，不能每时刻独立均匀抽坐标。真实轨迹缺失时可参考[OpenAP轨迹生成](https://openap.dev/trajectory_gen.html)，由机场/航路、机型和时刻生成轨迹；仍需自己定义航班出现强度和通信业务。

### 4.2 两种生成层级

**快速可用的聚合层：**每个服务单元的需求由“潜在终端数×接入比例×活跃比例×活跃终端速率”形成，再添加有持续时间的区域事件。航空场景在每架飞机内部建人数与业务，不把飞机数直接当Mbps；地面场景加入卫星接入概率，体现地面网络替代性。

**更细的会话层：**为每个接入用户抽取网页、视频、语音、办公等业务类别，每类有独立的会话持续时间、间隔和速率。使用ON/OFF状态表示“正在产生业务/暂时没有业务”。[SNS3官方接口](https://www.sns3.org/api/classns3_1_1_sat_traffic_helper.html)提供CBR、ON/OFF、HTTP、NRTV、VoIP等类型，可借鉴结构；其默认参数不能直接视作航空卫星实测值。

在时间窗内把预先生成的请求字节转换为需求：

\[
d_u(t)=\frac{8B_u^{\mathrm{request}}(t)}{10^6\Delta t}\quad[\mathrm{Mbit/s}].
\]

该式得到窗口中新到达业务的平均请求速率。第一版须固定统计窗口与服务期限，并明确把窗口平均请求速率作为需求近似；文件下载、持续视频和语音的期限不同，不能把一次文件请求的全部字节默认要求立即传送，也不能通过任意缩短窗口制造峰值。

`B_request`必须是请求量，不能用资源分配后实际传送的字节替代。为配对比较应冻结同一请求记录；积压队列若跨时刻保留，则另定义排队和重配置任务，不能悄悄加入当前静态回合。聚合层若已经乘瞬时活跃比例，就不要在会话层再重复乘同一比例。

### 4.3 让变化具有空间和时间联系

| 现实特征 | 候选实现 | 需要标定的量 |
| --- | --- | --- |
| 日内与工作日变化 | 按当地时刻、业务类别设置周期曲线 | 峰值时段、幅度、周末差异；航空不能一律套白天高夜间低 |
| 热点与航路 | 椭圆热点、沿航路距离衰减的带状权重 | 热点数量、尺度、密度、航路宽度 |
| 邻近区域一起变化 | 共享区域因子叠加局部波动 | 空间相关距离与强度 |
| 业务持续 | 相邻时刻相关过程或ON/OFF会话 | 自相关、持续时间、会话到达间隔 |
| 短时突发 | 带起止时间、位置和范围的局部事件 | 发生率、峰均比、持续时长 |
| 大量小需求、少数大需求 | 按业务类别混合的正值分布，可候选截断对数正态/Gamma | 分位数、尾部、零需求比例和终端速率上限 |

这些是工程模型选项，不是已确认的卫星规律。[Alasmar等研究](https://arxiv.org/abs/2007.10150)支持其所研究地面网络短时间聚合流量的对数正态拟合，不能推出所有卫星每束需求都服从该分布。分布、统计尺度和参数必须一起记录。

例如可使用相关扰动 `z_t=ρz_(t−1)+√(1−ρ²)Lη_t`，其中`LLᵀ`给出空间协方差、`η`为独立标准正态；`ρ`和空间相关距离随场景家族变化。这只是可解释的短期相关模型，不能据此声称具有长程相关。对零均值高斯`z`，正值扰动可用`exp(z−Var(z)/2)`避免平均负载因方差增加而无意上升；应从目标平稳高斯分布初始化，或使用各时刻实际方差修正。截断、混合及非高斯扰动须另算均值，不能直接沿用此式。

### 4.4 同时保留负载变化与集中程度变化

需要分开两类场景：一类冻结总需求、改变空间集中形状，以检查热点影响；另一类保留用户数/会话变化导致的自然总量变化，以检查高低负载。归一化表达`q_g=L_t w_g/Σw`适合前者，后者不能每时刻重新压成同一总量。没有真实绝对需求时，把`L_t`明确列为实验假设并做低/中/高负载敏感性对照。

最后按用户归属汇总`D_i=Σ_u a_ui d_u`；同一用户业务不能因覆盖重叠重复计数，未覆盖需求单列。波束中心/宽度改变后重算归属、需求及信道，保持空间、业务与物理条件一致。

## 5. 怎样让泛化验证可信

1. **变化生成规则的参数。** 每个场景抽取不同业务类别比例、热点数/半径、接入比例、负载、相关长度和突发程度，并加现实关联约束。只改变随机种子但固定全部分布参数仍然范围有限；也不要无约束地把所有参数独立乱抽。
2. **保留不同生成机制的考核。** 训练可用热点核与会话模型；考核另保留真实轨迹快照、实测活动驱动地图或未参与拟合的布局家族，防止仅适应某一个生成器。只有一类合成器时应限制结论。
3. **先按区域、日期和轨迹划分，再做增强。** 相邻时刻、同一航迹片段和同一底图的多种覆盖方案留在同一分区；同一天24个小时加噪后随机拆分不能证明跨天泛化。标准化与参数拟合只用训练分区。
4. **校准统计，而不只看热力图像不像。** 核对总量与P50/P90/P99、热点前10%需求份额、零需求比例、峰均比、空间相关和时间自相关、活动持续时间。真实位置可校准地理；外部移动活动只能辅助业务形状；绝对请求缺失时保留参数区间与证据等级。
5. **分别报告常规、未见地理、未见需求、联合变化与压力场景。** 保留旧范围以看退化；同场景报告全体目标束终态SI/SGM、基本服务、低分位表现、功率及约束。第一/二阶段联评还计未覆盖需求。场景重复动作不是新增独立训练种子。

有代表性请求数据不足时，优先可解释模型；GAN/扩散模型也需要训练数据，不能凭空保证“真实”。可在后续有充分数据时讨论它们，本轮不作为主路线。

## 6. 推荐执行路线与授权边界

- **航空主线：**已有ADS-B资产核查 → ADSB.lol有限日期/空域覆盖核验 → 轨迹清洗与缺测标记 → 人数/接入/会话假设 → 多布局快照 → 第一阶段覆盖与每束需求。OpenSky视使用条件补充。若目标中国空域观测稀疏，保留缺测范围并采用合成航路场景，不把缺报当真实低需求。
- **当前代码过渡：**小型71束包只用于理解字段、聚合和统计；不能用它重复加噪充当广泛泛化证据。主训练仍需足够多的独立地理与业务家族。可公开再利用的船舶数据提供另一种空间时序参考，但不必为此扩大本轮研究成海事专题。
- **缺少任何位置资产时：**在当前卫星可服务范围建立机场/航路或地面热点的参数化布局，结合业务会话、周期与相关扰动；输出场景类型、参数、单位、来源与随机源。结论明确为“在这些假设和留出场景下的泛化”，随后用真实位置/业务资料逐步校准。

延续P02原/新数据两组同输入、同网络、同奖励、同掩码的候选比较，不增加已授权范围；本轮没有新任务ID、模型或训练结果。第一版仍一回合一个静态时刻，100个逐束动作不代表100个真实时间点。正式实施前须接入工作台的场景配置与独立验证/考核，遵守DQN/CUDA、冻结版本和后台子agent约定。

本轮证据支持“已有可用原料，组合路线可实施”，不支持“生成器已经完成”“真实业务泛化已提高”或“正式数据已接入”。完整前后对照尚未执行，效果待验证。

后续决定：用户同意欧洲数据路线，要求欧洲版环境与原环境分开；将单独进行几何、场景与工作台配置实现及正确性验证。该实现与正式性能训练分开记录，本调研不预先宣称环境实现完成。
