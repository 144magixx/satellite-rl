# 十八组实验的结果核查与补充评价

登记日期：2026-09-24。当前正式训练：`sac_comparison_20260924_r2`。

本文在十八组训练尚未结束、最终考核结果尚未产生时登记收尾方法。训练仍按既定的三网络、两套公式、三个种子及每次四十万交互步执行；以下不增加训练次数或延长任何模型的训练预算。源码和运行信息见[运行说明](十八组对照实验运行说明.md)。

## 主比较与曲线

主表使用预算终点模型，在同一百个考核场景、三个动作采样种子下计算终态需求满足率、供需匹配程度、总吞吐量和资源约束。未服务波束计零。验证选中模型和逐头最大概率动作作为补充，不用最终考核选择保存点。

保留每次训练的曲线，再分别在原公式和修正公式下把三种网络放在同图比较。同一验证轮次先对每次训练的固定场景与动作采样取平均，再报告三个训练种子的均值及样本标准差。验证在回合结束时进行，各次实际交互步数可能略有不同；横轴采用其均值，并保存每次实际步数，不插值、外推或按最终高低改变平滑方式。最终验证与最后一次周期验证重合时只计一次。

任何缺失场景、重复样本、缺失种子或不一致的预算终点记录，先核查数据，不把剩余部分冒充完整十八组比较。补充分析另存 `analysis/`，保留输入文件校验值、训练固定提交与后处理提交。

## 运行耗时与单次决策耗时

根据现有日志报告各次运行起止、真实交互步和更新次数、断点恢复次数及可确定的评价时间。不能可靠分离的阶段注明不可分离。三路共享 GPU 的作业耗时反映本次实际执行条件，不作为独占 GPU 时的网络速度排名。

全部训练和配套考核结束后，在 GPU 空闲时做一次统一推理计时：三种模型均加载预算终点权重并进入评价模式，使用同一份保存的 204 维实际状态数组、同一 DQN/CUDA 环境、线程数与精度设置。预热后多次计时，包含 CUDA 同步，分别说明纯网络前向和从状态输入到动作返回的范围，报告参数量、单次决策耗时的均值及分布。不得把没有同步的异步提交时间写成推理耗时。

## 需求与分配阶段的策略统计

使用最终考核的逐步动作及终态数组，分需求范围和处理阶段统计请求功率、请求/实际槽数、频率起点、零槽、裁剪和需求满足率。已处理与未处理束分开列数，全部波束都进入服务成绩的分母。先在各训练种子内汇总，再给跨种子波动。

需求与处理顺序在原场景生成方式中有关联；观察到的相关关系只用于描述策略，不能单凭相关关系宣称模型因果上学会按需求调整。

## 预先固定的补充场景

在所有预算终点模型上额外评价以下三种条件，不再挑选或修改模型：

| 条件 | 变化 | 保持不变 |
| --- | --- | --- |
| 较低需求 | 所有目标波束需求乘以 0.75 | 位置、组归属、次序、预算和信道参数 |
| 较高需求 | 所有目标波束需求乘以 1.25 | 位置、组归属、次序、预算和信道参数 |
| 同组次序变化 | 在每个组内按固定排列重新处理波束 | 波束身份与组归属、需求位置配对、预算、信道参数 |

使用已登记考核场景 81000–81019，每个条件二十个配对场景，动作种子仍为 91001、91002、91003。重排由独立随机源确定（场景编号加 100000），同步排列该束的全部字段，并保存排列与实际数组；不能把组号改变混入次序变化。原条件可复用最终考核的对应场景，不重复当成新的独立训练。

这些评价检查预定需求和次序变化下的适应范围，不代表全面泛化或真实通信性能校准。环境预算规则、奖励和网络均不再修改。若现有接口无法保持上述不变量，应明确缺少的评价，不能悄悄改变条件。

## 环境修正的单独对照

在共同的二十个固定场景和三个动作种子下，将兼容的原 Transformer 预训练权重分别放入修正前、修正后环境。使用保存的旧提交及当前固定环境，记录权重和场景校验值，统一按全部波束终态速率统计。旧错误环境的数值仅说明计算变化和旧策略适应情况，不进入新环境的模型排名。已有确定性功率、顺序和天线边界检查仍是计算正确性的主要依据。

参数量接近的 CNN/MLP 没有对应的历史训练权重，不拿其他结构的旧权重冒充其修复前结果。原算法在新环境重训的九组，才是两项学习公式修正的共同环境参照。
