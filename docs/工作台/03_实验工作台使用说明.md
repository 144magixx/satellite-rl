# 卫星资源分配实验工作台使用说明

## 启动与保存位置

在项目根目录运行：

```powershell
powershell -NoProfile -File scripts/start_workbench.ps1
```

浏览器打开 `http://127.0.0.1:8765/`。默认使用 `C:/Users/Admin/anaconda3/envs/DQN/python.exe`，可通过 `-DqnPython` 指定同一DQN环境的实际解释器；`-ArchiveRoot D:/paper` 指定实验保存根目录，`-Port` 更换端口。启动器在后台运行服务，关闭浏览器不会取消训练。

也可从明确的DQN解释器启动模块：`python -m satellite_rl.workbench.server --archive-root D:/paper`。从独立worktree开发时必须显式设置 `PYTHONPATH=<该worktree>/src`，防止可编辑安装仍导入日常开发目录。服务只监听本机回环地址，不需要云账户或在线前端依赖。

- 任务、日志、场景、配置和冻结源码：`outputs/workbench/`。
- 新模型：`models/runs/workbench/`。
- 既有正式实验从 `outputs/experiments/` 只读接入；工作台不会向旧监督进程发送恢复或停止指令。
- 每个训练任务使用提交版本的源码快照，并校验文件SHA-256、解释器、CUDA与实际导入位置。存在未提交源码时先完成验证和提交，再创建训练任务。

## 配置实验

算法支持SAC、PPO、DQN；新工作台的可配置网络明确标为 `workbench_*_v1`，不把新网络结构当成历史权重的原网络。历史预训练权重通过独立适配器严格加载。首版保留当前100波束、8组、每组100槽的物理布局，频率起点100档、请求槽数1–10档，功率档位可配置。

状态特征按勾选顺序拼接，并可上移、下移调整顺序。查看右侧的维度、偏移及归一化说明。默认保留原204维内容；可增加进度、组号、已服务缺口、全局/剩余业务需求和其他组占用。根据用户2026-09-25确认，默认全部业务需求在分配前已知；逐步获知模式会拒绝不可得的未来需求特征。此可见范围只约束模型输入，仿真奖励仍可由环境结算；奖励是否适合真实在线系统需另行研究。

网络可编辑MLP宽度/层数、CNN通道/卷积核、Transformer编码维度/层数/头数等。结构图来自实际构建和前向中的层形状，并显示完整网络参数量。可配置CNN仍采用一维卷积。Transformer现在可选择既有“逐标量令牌”或新增“原 T-SAC（13 令牌）”；点击原 T-SAC 预设会设置原204维状态顺序、编码128维、8个注意力头、2层、前馈512维、ReLU和Dropout 0.1。13令牌由地理、需求、剩余功率各1个令牌及10段频谱令牌组成，取第一个令牌进入三个动作头，与项目原T-SAC结构对齐；权重包格式和工作台训练实现仍单独记录，不冒充旧实验重现。旧配置未指定令牌布局时保留逐标量版本。

SAC的策略网络在动作采样和学习概率计算中均采用一致的eval模式（梯度仍正常计算），避免Dropout导致两处策略概率不同；价值网络按配置使用训练Dropout。两组掩码实验采用相同设置。PPO仍要求Dropout为0。

奖励保留原公式/原功率账、原公式/修正功率账、融合奖励，也可自选26类步进或终态组成项。每项显示含义、结算时点、符号与缩放；正权重乘以负惩罚项。`scale`为除数，不是再乘一次的权重。反向权重会改变业务目标，需明确理解。日志分别保存原值、缩放值和加权值，不能只看总回报。融合预设的历史单种子结果曾下降，并非推荐最优方案。

动作方式“原动作裁剪”复现当前环境；“联合可行动作投影”先按占用、连续槽数和预算寻找可行动作，再执行并记录请求/实际动作。投影修改了动作执行规则，不能把最终合法分配全部归功于模型。没有可行正槽动作时记录无服务分配。功率预算记账和实际辐射功率分别展示，原记账版本零槽请求也可能消耗预算。

新增“无效动作掩码”开关：默认关闭，沿用既有选择与裁剪；开启时在SAC抽样前联合检查起始频点和实际槽数，排除已占、跨占用和越界的连续槽段，同时为后续同组每束保留一槽、为后续每束保留最低功率档位。两个动作头仍并行输出，但从经过掩码的100×10组合概率表选一对动作。功率按同一剩余预算规则筛选。采样、策略/价值目标、熵及经验回放共同使用这套合法分布；合法动作数减少时目标熵随之调整。开启掩码要求SAC和“原动作裁剪”模式，不能与动作执行后的投影混用；其他算法会明确提示不支持。保留最低档资源保证当前资源条件下每束有槽和功率，不保证终态容量必然达到10%需求。

历史配置缺少掩码字段时按关闭处理；开启状态随配置保存、模型导出、断点续训和模型评价保留，不能在加载时静默丢失。模型测试中的贪心/固定策略保持原有基线规则，元数据明确其掩码为关闭，不会跟随被测模型偷偷改变基线。

## 训练与监控

保存方案后提交后台训练。任务按GPU资源排队；默认工作台最多一个训练/评价进程，并避让已有繁忙GPU作业。排队、预热、更新、验证、完成和失败应从状态及实际进程共同判断。未到更新门槛时的交互不是参数更新；监控分别显示两种计数。

监控读取工作台JSONL、历史CSV以及TensorBoard事件。全部标量入口可以搜索原始标签，曲线可查看原始数据、调整显示平滑、选择步数或记录时间，并叠加其他运行的同名指标。不同单位分别绘制，不用一条坐标轴把温度与损失混为同一尺度。

重点查看：

| 方面 | 记录内容 | 可协助排查 |
| --- | --- | --- |
| 业务效果 | 全部波束最终需求满足率、SGM、基本服务、最低/零容量、吞吐、公平性 | 分数是否来自全体波束，哪些束没有服务 |
| 学习过程 | 策略/价值损失、Q及目标Q、TD误差、梯度范数 | 数值是否发散、更新是否实际发生 |
| SAC | 温度、温度损失、总动作熵与频率/槽数/功率熵 | 温度异常、动作过于固定、探索与目标差异 |
| PPO | 概率比裁剪、近似KL、优势/价值诊断 | 一轮更新是否变化过大，价值估计是否有效 |
| DQN | 探索率、TD误差、目标网络更新 | 随机探索及目标更新是否符合设置 |
| 奖励 | 原始/缩放/加权组成项及总回报 | 某项量级是否压过其他业务目标、重复计罚 |
| 行为与资源 | 请求/实际频率、槽数、功率、裁剪、零槽、干扰、超限 | 是模型请求不当还是执行规则改变动作 |
| 执行与故障 | 心跳、吞吐、显存、运行设备、源码版本、日志和堆栈 | 是否停滞、错用源码/设备、从哪个正常断点恢复 |

历史运行未记录的内容保持缺失，不补零、不由其他指标猜测。记录中的NaN/Inf会提示，图形不把它们替换成正常成绩。大量点显示时按时间分段保留极值；JSONL/CSV原始文件可下载，平滑和抽样仅用于显示。

“停止并保存”在回合边界完成，因此点击后可能还需要当前回合的剩余步骤。断点包含网络、优化器、经验回放/采样状态、随机源与进度；恢复时回滚超出可信断点的规范日志，不把不完整数据重复计入。只导入推理权重不能精确续训。失败或进程中断时查看错误详情及最后正常断点；不修改原配置覆盖旧实验。

Windows上状态文件、场景和断点的原子替换已使用有上限的占用重试。旧冻结版本若因此中断，可通过同一工作台恢复API指定`source_repair=atomic_io_retry_v1`；服务只接受已记录的WinError 5/32替换故障，核对断点、源码哈希和训练逻辑等价性后，在原任务编号下绑定新冻结快照。原源码保留，旧job、断点、故障和根层日志先归档到任务的`recoveries/`，源码沿革保存在job的`source_history`。任何奖励、网络、环境、数据或训练逻辑变化都会被这个专用恢复流程拒绝。恢复后的根目录`failure.json`可保留为历史记录，须结合发生时间、当前状态和源码沿革判断，不能仅因旧故障文件存在就认定当前任务失败。

## 模型与测试场景

模型测试可选择新任务的终点/验证最佳/最新推理模型，或导入外部本地模型。工作台模型包是目录中的 `model.json` 与 `policy.pt`；导出ZIP后先解压再导入。旧权重须选择明确类型；支持仓库五套预训练模型以及匹配规模SAC权重。未知Python序列化模型对象不会默认执行。旧PPO direct使用3W功率步长，其余旧预训练使用5W，不能只因为输出维数相同就互换。

导入场景支持实际 `.npz`、包含多个 `.npz` 的目录，或CSV。CSV列为：

```text
beam_id,lat,lon,demand_mbps,group
0,31.2,121.5,500,0
```

首版CSV必须有100行，`beam_id`为0–99唯一编号；行顺序即处理顺序，不自动按需求排序。`group`可省略，填写时须等于行序号%8。需求单位明确为Mbps，经纬度单位为度。CSV采用当前固定的发射/接收增益和噪声温度；需要保留不同信道参数时使用包含全部字段的npz。场景校验包括位置、正需求、距离与位置一致性、身份和分组；导入不会覆盖原文件。

随机生成场景也保存实际数组及校验值，后续模型使用同一批文件。训练、可反复使用的验证、最终考核分开；如果依据考核结果修改方案，原考核场景已参与开发，不能继续当作独立证据。

评价可选确定动作或按策略采样、重复次数以及固定/贪心基线。基线使用同一场景和环境；原基线功率不在当前档位时，记录到最近可用档位的映射，避免暗中改变条件。结果含全部100束需求与最终速率、功率、频率槽、SGM、基本服务及请求/实际动作轨迹。

## 对比与验收边界

对比按实际场景校验值配对，同一场景的动作重复先平均，再计算相对第一个模型的差值。环境、记账或动作方式不同会明确提示，不能直接宣称算法进退。奖励总回报仅用于各自训练诊断，正式对比使用相同的终态业务、资源与约束指标。

已知的无效动作掩码开关可以作为研究因素，在其他物理参数、功率记账和随机/确定评价方式相同的情况下配对；页面会提示差值反映联合掩码、资源预留及学习配套的总体作用。预算、功率档位、基本服务门槛或裁剪/投影规则等不同仍拒绝直接配对。表中差值相对列表第一个运行；如果把掩码组列在前面，无掩码组的SI差值为负是正常的比较方向。

本轮交付的工程验证包括配置、算法实际更新、模型与断点、页面及后台流程。短训练只证明流程与数值能够运行。**新增状态、奖励和网络的效果待验证**，没有把一键运行成功当成学习提升，也没有自动启动参数搜索或多训练种子正式实验。详细验证记录见同目录的工作台验收记录。
