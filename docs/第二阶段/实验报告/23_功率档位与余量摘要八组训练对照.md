# 23 功率档位与余量摘要八组训练对照（W31）

2026-10-17｜方案见[方案31（精简执行版）](../方案/31_功率档位与余量摘要训练对照（精简执行版）.md)，研究设计来自[方案30](../方案/30_功率档位与余量摘要训练对照方案.md)｜报告由Claude Code撰写，代码与上机由Codex（GPT-6.1 Sol）完成。

## 一句话结论

**给模型加一个0.5瓦的低功率选项，是这一轮唯一起决定作用的改动。**供需匹配程度（SGM）从约0.61提高到约0.75，20个开发场景全部变好；总功率少用约四分之一到三分之一；需求满足率（SI）基本不变。把5瓦以上的档位细化没有用，余量摘要的作用也很小。

> 以上只是一个训练种子（51001）在20个开发场景上的结果，这些场景以前的实验也用过，还不算独立考核。

## 1. 这一轮做了什么

上一轮诊断（报告21、22）发现：有些波束只给一个频率槽、5瓦功率，容量仍然远超需求，多出来的功率只会增加对别的波束的干扰。可模型能选的最低功率就是5瓦，没法再往下调。

这一轮从头训练了八个新模型，检查三件事：

1. **档位是不是太粗？**保留5瓦下限，把5瓦以上的间隔从5瓦改成0.5瓦。
2. **最低5瓦是不是太高？**只加一个0.5瓦选项，或者把0.5—50瓦全部按0.5瓦细化。
3. **模型要不要看见已有分配留下的余量？**给模型加上100个频率槽的“余量摘要”：在某个槽发射，已经分配好的哪些波束会受干扰，这些波束离各自的需求还有多远。

| 编号 | 实验组合 | 可选功率 |
| --- | --- | --- |
| P00-M0 | 原档位（**对照组**） | 5、10、…、50瓦，10档 |
| P00-M1 | 原档位＋余量摘要 | 同上 |
| P10-M0 | 细化5瓦以上 | 5、5.5、…、50瓦，91档 |
| P10-M1 | 细化5瓦以上＋余量摘要 | 同上 |
| P01-M0 | 原档位＋0.5瓦 | 0.5、5、10、…、50瓦，11档 |
| P01-M1 | 原档位＋0.5瓦＋余量摘要 | 同上 |
| P11-M0 | 全区间细化 | 0.5、1、…、50瓦，100档 |
| P11-M1 | 全区间细化＋余量摘要 | 同上 |

八组共用同一套网络、奖励、训练数据（576个训练母场景）和超参数，各训练15万步。八组看到的训练场景顺序完全相同，都是1865个回合，所以差异只来自功率档位和摘要。评价使用20个开发母场景，每个场景做3次随机出动作，先按场景求平均，再对20个场景求平均。

## 3. 怎么理解这些结果

### 3.1 关键是“能把功率降到5瓦以下”

看第2节的表，四组带0.5瓦选项的结果几乎一样：SGM都在0.746—0.749之间。四组不带0.5瓦选项的都在0.59—0.62之间。两类之间相差约0.14，是门槛（0.01）的十几倍。

具体做了什么，可以看15万步评价里每个波束的终态：

| 编号 | 容量超过需求两倍的波束 | 容量不足需求90%的波束 | 选了5瓦以下的波束 | 每束平均功率 |
| --- | ---: | ---: | ---: | ---: |
| P00-M0 原档位（对照组） | 34.6% | 8.3% | 0% | 24.7瓦 |
| P01-M0 原档位＋0.5瓦 | 23.6% | 8.8% | 30.6% | 18.6瓦 |
| P11-M0 全区间细化 | 24.2% | 9.0% | 51.6% | 16.9瓦 |

- **有选择以后，模型大量使用低功率。**原档位＋0.5瓦这组，约三成波束选了0.5瓦。
- **“供给太多”的波束明显减少。**容量超过需求两倍的波束，从约35%降到约24%。这些波束原来就是被5瓦下限卡住、没法再少给，现在可以少给。
- **SI为什么几乎不变？**SI对超额供给是封顶的：一个波束的需求已经满足了，再多给也不加分。所以把这些波束的功率降下来不会损失SI，只会让供需更匹配，同时减少对别的波束的干扰。
- **“供给不足”的波束没有变化，一直在8%—9%。**说明低功率选项解决的是“给多了”的问题，对“给少了”的那部分波束没有帮助。这是下一步要研究的瓶颈。

### 3.2 只细化5瓦以上，没有用

细化5瓦以上（P10-M0）比原档位还略差：SGM少0.019，只有3个场景变好，功率反而多用4%。这说明问题不在“档位间隔太粗”，而在“最低5瓦太高”。

为什么细化后会略差，目前只有推测：可选档位从10个变成91个，模型要摸索的选项多了，同样15万步不一定学得透。这个推测没有专门验证。

### 3.3 有了0.5瓦以后，中间档位填不填都行

全区间细化（P11-M0）和只加一个0.5瓦（P01-M0）相比，SGM只差−0.002，20个场景里只有6个更好。也就是说，只要多出“0.5瓦”这一个选项，就拿到了几乎全部收益，没必要把1—4.5瓦全补上。

### 3.4 余量摘要：作用很小，可能对SI有一点帮助

| 功率档位 | 加摘要后SGM变化 | 加摘要后SI变化 | 加摘要后功率变化 |
| --- | ---: | ---: | ---: |
| 原档位 | +0.007 | +0.0027 | −117瓦 |
| 细化5瓦以上 | +0.013 | +0.0053 | −279瓦 |
| 原档位＋0.5瓦 | −0.0004 | +0.0057 | −143瓦 |
| 全区间细化 | +0.003 | +0.0033 | **+486瓦** |

- SGM变化在±0.01上下，和0.14的档位效应比起来可以忽略。
- 四种档位里，加摘要后SI都略有提高（+0.003到+0.006）。方向一致，但幅度很小，又只有一个种子，只能算“可能有一点帮助”。
- 功率变化方向不一致：三种档位下加摘要后功率降低，全区间细化下反而多用了486瓦。

## 4. 训练过程

![八组训练曲线](../../../outputs/experiments/s2_w31_20261017/analysis/fig1_training_curves.png)

*图2 训练回合的终态指标，200回合滑动平均；实线为无摘要，虚线为有摘要；横轴是训练交互步数。*

- **差距很早就出现了。**大约2万步时，带0.5瓦选项的组（绿、红）SGM就和其它组拉开了，此后一直保持，3万步后基本稳定。
- **SI八组走势几乎重合，**都从约0.89升到约0.965。
- **功率差别明显。**带0.5瓦选项的组总功率在1100—1450瓦，原档位和细化5瓦以上的组在1600—2050瓦。各组功率在4万步后都有缓慢回升的趋势。

![三个节点的开发评价](../../../outputs/experiments/s2_w31_20261017/analysis/fig2_eval_nodes.png)

*图3 5万、10万、15万步三个节点的开发评价。*

5万步时，带0.5瓦选项的组在SGM上就已经领先0.11—0.15，此后三个节点都保持这个差距。所以这个结论不是“恰好在15万步这一个点上好看”。SI在5万步时这几组略低（约0.951—0.958），到15万步追上了对照组。

## 5. 按事先规则选出的候选

方案30规定：在过门槛的组里，按SGM、SI、较低功率、分组编号依次比较，锁定一个主要候选。

- 过门槛的有三组：P01-M1、P11-M0、P11-M1。
- 按规则，锁定的主要候选是**P11-M1（全区间细化＋摘要，SGM 0.7488）**。

不过三组的SGM只差0.003，实际上分不出高低。如果只看实用，我更推荐**原档位＋0.5瓦（P01）**，理由有三：
1. 只比原来多一个选项，改动最小；
2. 收益和全区间细化一样；
3. 加上摘要后（P01-M1）功率最低，只有对照组的68%。

不加摘要的P01-M0，SI比对照组低0.0025，超出允许的0.002，只差0.0005没过门槛。它的SGM收益和其它三组一样大，20个场景全部变好。

**这条推荐是我对结果的解读，不是事先登记的选择规则。**

## 6. 计算开销

- **训练：**八组同时在两块RTX 4090D上跑，每块卡四组，GPU利用率95%—97%。每组训练约3.6小时，从启动到八组全部训练并评价完共约3小时40分钟（北京时间03:54启动，07:31—07:37陆续完成）。总计约7.4 GPU小时，远低于方案30登记的上限（首轮160 GPU小时）。
- **评价：**每个场景完成一次完整分配约1.6—1.8秒，各组相近。评价时四组共用一块卡，这只是大致水平，不是严格的计时对比。
- **显存：**每组模型约0.7—1.1 GB。四组同时跑，每块卡约用3.5 GB。

## 7. 限制

1. **只有一个训练种子（51001）。**换一个种子，结果的大小可能会有变化。不过0.14的差距是门槛的十几倍，而且20个场景全部同向，被推翻的可能性较小。
2. **评价场景以前用过。**这20个开发母场景在W26—W29的路线选择中都出现过，不是独立考核。
3. **0.5瓦是研究用的下限，**沿用前一轮诊断的范围，还没有核实卫星功放实际能不能稳定工作在0.5瓦。
4. **未来预留没有改。**每个还没分配的波束仍按5瓦、一个频率槽预留，低功率组是在这个保守规则下训练的。
5. **和第三阶段的衔接没有检查。**旧的第三阶段离散调整入口默认5瓦步长，能不能直接接收0.5瓦的分配，还要另外确认。
6. **没有做正式的统计检验。**报告给出的是均值、逐场景方向和最大最小值。
7. **执行方式和方案30不同：**这一轮没走前端工作台，由精简脚本直接在远端运行，见方案31。研究代码和W30冻结版本相同，这一点已逐项核对。

## 8. 接下来可以做什么（需要你决定）

1. **多种子复验（推荐优先）。**再加51002、51003两个种子，并准备40个从没用过的新考核场景。这是方案30原定的第二步，能确认“加0.5瓦”的效果在独立场景和不同种子下是否站得住。不过新场景还没有准备，要先做数据准备。
2. **把“原档位＋0.5瓦”并入第二阶段主线，**同时确认0.5瓦在物理上是否可行，以及第三阶段能否接收这样的分配。
3. **研究那8%—9%供给不足的波束。**低功率选项没有改善它们，这是剩下的主要瓶颈。
4. **把未来预留从5瓦放宽到0.5瓦。**这会同时改变可行域，建议作为单独一组对照，不要和上面的问题混在一起。
