# 32 FLOW-AO布局下的第二阶段重训与三阶段一致性方案

2026-10-17｜S2-W32｜Claude Code设计并撰写报告，Codex（GPT-6.1 Sol）实现与上机。用户指示：用目前表现最好的第一阶段算法，在20627、20653、20655三张卡上开始做，中间不停。

## 要解决的问题

第二阶段现有的训练数据（W26/W30/W31共用的input596）飞机是真实的，但“哪些飞机归哪个波束”来自第一阶段第7轮的旧布局（Wenv）：每景约80束，热点不拆，最忙一束186架飞机、4 Gbps，远超单束约1.1 Gbps的上限。S1-FIX的新骨架FLOW-AO在同一天场景上把负载摊到100束，白天最忙一束17—19架、约400 Mbps。第二阶段模型是在旧布局上学的，没有在新布局上验证过；按三阶段一致性铁律，最终的第二阶段也必须用第一阶段真实输出训练。

本轮做三件事：

1. **用FLOW-AO重新生成第二阶段数据。**同样的576个训练场景、20个开发场景、40个封存确认场景（飞机集合、稳定ID、位置、每机21.6 Mbps全部不变），只换布局。
2. **在新数据上重训第二阶段，并和规则比较。**同时回答“旧模型在新布局上还行不行”和“新布局下环境是否更能区分算法”。
3. **复核W31的结论在新数据上是否成立**（加0.5 W选项是否仍有效，余量摘要是否仍作用很小），这次用三个种子。

## 数据生成

- 第一阶段算法：FLOW-AO，含最小中心间隔规则，effort=1，使用S1-FIX冻结源码`19f6c45`，不改算法。
- 波束预算N=100（S1-FIX块B的默认值；块C尚未定下最终N）。若某景初始覆盖就需要超过100束，用其实际所需数（上限200）并记录；超过200的场景记失败、不纳入。
- 开发20景另生成N=60、150、200三档，只用于评价训练好的模型对波束预算的鲁棒性，不参与训练。
- 每景检查：每架飞机恰好归一束；逐束需求等于成员数×21.6 Mbps，全景总需求守恒；束宽在0.3°—1.0°；每个成员都落在所属波束的足迹内（用第二阶段物理的同一套角度计算核）；N≤200、无空束；第二阶段输入校验通过。

## 评价

全部在新布局上进行，口径与W31相同（每母3次随机动作，先按母平均再平均），新增**业务量加权满足率**（实际承载÷总需求）并按场景负载分档报告。

| 评价 | 对象 | 数据 |
| --- | --- | --- |
| 开发节点 | 12组的5万／10万／15万步 | 开发20景，N=100 |
| 规则对照 | 随机、固定、贪心（W26定义，原档位） | 开发20景与确认40景，N=100 |
| 旧模型迁移 | W31的P00-M0、P01-M1 15万步模型，不重训 | 开发20景，N=100 |
| 波束预算鲁棒性 | 新训P00-M0、P01-M0（种子51001）15万步 | 开发20景，N=60／150／200 |
| 封存确认 | 12组15万步终点 | 确认40景（2024-02-23／24），N=100 |

确认40景此前在W26用于四个状态组之间的比较，没有用于本轮任何选择；本轮模型固定取15万步终点，不按确认结果挑选。主要比较沿用方案30的门槛：相对同种子P00-M0，SGM≥+0.01、SI下降≤0.002、功率≤110%、约束通过；三个种子至少两个为正。
