# 关闭dropout与随机场景后的稳定训练方案

日期：2026-09-30。方案编号P05，研究范围为第二阶段频率槽与功率分配。**本次交付方案，不修改训练代码、不启动新训练或评价。** 首版推荐3组；用户追问“除了这三组还应该有什么”后，建议补R3形成下列4组核心对照。G08仍完成、跟进暂停；4组及专项候选都未批准或提交，不把讨论扩大解释为启动授权。

## 1. 目标：固定考题上的成绩改善并进入平台

用户希望看到奖励稳定上升、后期收敛。建议将验收目标明确为：**在同一批固定验证场景上，平均任务成绩随训练改善，后期波动较小；价值学习也停止持续漂移，最终实际服务改善。** 原始训练回报仍完整保留，其波动反映当回合场景和随机动作的变化。

当前图把7个模型、不同时间的场景难度和随机动作混在一起，即使100回合滑动平均也仍有周期。A的价值拟合已明显改善，但训练回报仍有强周期，说明不能把图中的每个下降都解释成策略退步。B打乱场景后周期减弱，也没有自动形成持续上升的回报曲线。

已有固定验证也说明“服务提高”和“旧奖励提高”不是同一件事：A在1万→40万步的平均回报59.54→64.19，SI88.17%→89.99%；B回报80.51→57.77，SI87.09%→89.31%。这些仅是两个端点，完整趋势见[固定验证曲线](../../../outputs/experiments/europe_ablation_20260929/analysis/figures/validation_curves.png)，不能用端点代替全程结论。

以后主图按以下方式组织：每个候选一张训练/验证图，另外只画少数关键方法的验证比较；同时展示原始点、预先固定的平滑线和服务指标。初始策略成绩已较高时，真实曲线可能很快进入高平台，上升阶段可以很短。目标是实际学习趋稳，不要求每一回合或每一个验证点都严格递增，也不承诺数学上的全局收敛。

## 4. 状态先补关键全局量，不重做2946维扩展

新增7个量：平均需求β、已处理比例、剩余需求，以及当前的基本服务达标比例H、基本服务进度B、需求满足率S、供需匹配G。原204维已经有剩余功率，可还原当前功率占预算比例。

所有服务量都对**全部100束**计算：已处理束采用经过当前全部干扰后的容量，未处理或未服务束容量为0。β与剩余需求来自规划时已经知道的完整场景需求，沿用现有用户业务假设；不读取未来动作或未来容量，也不声称这是完全可观测状态。

新增全局量通过一个小型支路与原编码输出融合，而非再次追加19个令牌。建议支路7→32→128，使用有界激活；输出乘一个初值为0的可学习门控，再加到原13令牌的编码输出。共有网络和动作头的初始化随机流保持不变，新增支路用隔离随机流初始化。

门控初值0旨在让初始Actor、双Q和目标网络输出与原204维一致，再逐渐学习新增信息；这是待实现设计，必须用数值检查证明，不能把门控为0当作已经证明等价。新增量固定归一化：H/B/S/G及进度本来在0–1；β除600 Mbit/s、剩余需求除100×600 Mbit/s，沿用已登记的需求参考单位，不按每个batch临时重估尺度，不裁掉高负载信息。输入范围和支路饱和情况先用训练场景检查。网络结构、有效维度、参数量和归一化版本进入模型元数据。

这一步区别于C1：C1虽然只开放3个新标量，却仍使用32令牌和许多未开放令牌。本候选保留原13令牌的信息通道，只增加一个受控的全局支路。

## 5. 奖励直接对应最终资源分配质量

### 5.1 先定义最终想优化什么

令最终容量为C_i、需求为D_i，未服务束C_i=0，分母始终为100：

\[
H=\frac1{100}\sum_i\mathbf1[C_i/D_i\ge0.1],\quad
B=\frac1{100}\sum_i\min\left(\frac{C_i}{0.1D_i},1\right),
\]

\[
S=\frac1{100}\sum_i\min(C_i/D_i,1),\quad
G=\frac1{100}\sum_i SGM_i.
\]

建议第一版终态目标：

\[
J=4H+B+S+0.2G-0.01\frac{P_{\mathrm{actual}}}{3000\ \mathrm W}.
\]

H是达标束比例，不是“该回合全100束都成功”的0/1标记；全体成功比例仍单列评价。4H强化基本服务，B使欠供束接近10%门槛时也能得到连续反馈，S关注业务满足，G限制供需偏差，功率项仅在服务相近时提供较小的资源偏好。系数是事前登记的候选，未证明最优，也不能数学保证所有束先达标或明显节能。

J约在−0.01至6.2之间。H的临界值/浮点容差须与正式基本服务指标一致；G仍用原SGM，β为本场景100束平均需求；P取实际发射累计功率。不能用请求功率、只看已服务束或忽略后续干扰。

这与历史`fused`的`2Δ基本服务总和＋ΔSI总和＋0.2ΔSGM总和−本步功率/3000`不同：终态目标加入达标束比例，并使用下面的折扣/终止一致反馈。[历史融合奖励在无掩码场景失败的记录](03_融合奖励失败后的第二阶段改进方案.md)保留；不将同一公式改名视为已解决问题，R2的效果必须重新验证。

### 5.2 用正确处理折扣的逐步反馈

通俗地说，每步检查“这次分配让整个场景向最终目标靠近了多少”，包括它对前面波束造成的损失；同时保证这些逐步反馈汇总后仍对应终态目标。

令非终态的当前势函数Ψ_t=20J_t，初态Ψ_0=0；到真正终态时**强制Ψ_T=0**。只在最后一步给基础奖励b_{T−1}=20J_T，其余b_t=0：

\[
r_t=b_t+\gamma\Psi_{t+1}-\Psi_t,\qquad\gamma=0.99.
\]

正常100步回合的环境折扣回报恰为：

\[
R_\gamma=\sum_{t=0}^{99}\gamma^t r_t
=20\gamma^{99}J_{100}\approx7.395\,J_{100}.
\]

所以在正常固定长度回合中，逐步反馈没有额外改变**这个新终态目标**的排名。它不是对旧奖励最优策略的保持保证；SAC还同时优化动作熵，也不保证有限神经网络一定学好。势函数方法的理论来源见[Ng、Harada、Russell原论文](https://ai.stanford.edu/~ang/papers/shaping-icml99.pdf)，上述有限回合代数另行核对。

20为预先选定的尺度候选：仅新增一束完整服务、其他束和功率不变时，目标增加最多约1.24个奖励单位；新增一束达到10%基本服务时约1.02。后续干扰、功率变化和折扣项会改变实际奖励，正的服务增量也可能伴随负的逐步奖励。必须先核训练场景上的奖励分布及TD尺度，不直接夹断奖励，否则会破坏上式关系。

原生未折扣回报`sum(r)`仍保留，它等于`20J_T−20(1−γ)Σ_{t=1}^{99}J_t`，并不等于R_γ或J。固定长度下R_γ和J只差常数，主图可用一条曲线、明确标两者换算，不把相同数据包装成两份独立证据。异常提前结束会改变折扣因子，必须保留未服务束0分并标异常，不能作为正常平台成绩；终止样本的SAC目标只有r，不再自举。

25MHz＋最低5W造成的小需求过供仍然存在，不能承诺SGM接近1。本阶段不同时改槽宽、功率档或人为抬高需求；若以后研究粒度，另设保持总资源可比的环境对照。

## 6. 价值学习先诊断，再决定是否需要额外改法

除了现有loss/TD/Q/target/α，增加采样诊断：终止与非终止TD分别统计、实际熵与合法目标熵差、α×熵相对奖励及Q的尺度、双Q差、梯度裁剪前范数。每50步采样，保存原始记录，标明这不是全部更新次数；从冻结断点做小探针，不改变训练随机流。

若R0稳定，继续维持原MSE与学习率，不为了曲线形状再增加改动。若它失稳：

- 误差集中于少数离群目标：候选单因素比较MSE与Huber（阈值δ=2只是待检验起点，效果待验证）。Huber对大误差使用线性增长，区别于MSE的平方增长；依据见[PyTorch官方说明](https://docs.pytorch.org/docs/stable/generated/torch.nn.modules.loss.HuberLoss.html)。实施时另核DQN中实际安装版本，不能混淆Huber的δ与SmoothL1的β及尺度。
- 大多数样本持续漂移：候选单因素降低Critic学习率1e-4→5e-5。
- 只有证据表明温度回路持续失衡时，才另行研究目标熵或温度约束；不能仅凭α较大就加上限。

这些不自动追加到4组核心方案，不同时实施，也不通过恢复旧任务偷偷换损失/参数。若需要，先改方案和预算。非有限数、资源账不一致、CUDA退出等按故障处理；学习明显漂移则保留断点、日志和分组探针，不能当作正常完成收敛。

## 7. 怎样验收“上升并趋稳”

### 固定验证安排

复用已冻结01-12的20个验证场景，各3次随机动作；每个检查点使用同一场景及动作随机数，与训练RNG隔离。保存步0的初始策略成绩，随后2000、5000、10000步，此后每10000步验证。初始验证使用策略本身，不能和预热期间随机探索的回报混为一类。

主验证保持随机动作口径；另列确定动作诊断，其规则对所有候选一致，不只给表现好的模型改动作方式。最终主结果统一取40万步终点权重；验证最好权重另存且标来源，不能靠新考核挑选权重。

所有候选共同记录J及Z=J/6.2，以及SI、SGM、平均基本达标束数、全100束达标比例、功率、槽数和约束。旧奖励与新奖励的原生回报分别画，不按数值大小互相排名。

训练图保留每回合原始点，辅助线固定为100回合尾随均值；固定验证图保留全部检查点，可另加3点尾随均值，但平台验收只用未平滑值。若画场景波动带，先平均各场景3次动作，再画20个场景均值的25%–75%分位范围，明确这是场景差异而非训练种子置信区间。训练/验证/考核图分别标清横轴步数、场景数、动作重复数和奖励版本。

### 预先登记的工程验收目标

以下为候选验收阈值，不是理论充分条件，也未证明当前物理资源能全部达到；正式运行前冻结，不能看到最终考核后改标准。

1. **有进步：**末5个验证点的平均Z，比步0高至少0.005；已有高初始成绩导致增益不足时，记“趋稳但新增收益未证实”，不制造低起点。
2. **进入平台：**最后10个验证点的Z最大−最小不超过0.01，末5点与前5点均值差的绝对值不超过0.005；保留所有原始点。低分横线不能仅凭平台条件判成功。
3. **价值学习趋稳：**后段分组TD、相对TD与Q/target不持续数量级增长；实际熵−目标熵的差距不持续扩大，α不在后段持续成倍增加。目标标准差接近0时同时看绝对TD，避免比值误判；α本身的绝对大小不作为唯一门槛。
4. **服务和约束：**完整100束处理、功率不超3000W、无非法槽和裁剪；固定验证上末5点的SI相对前5点下降不超过0.3个百分点。最终共同考核中候选对参照的SI下降不超过0.3个百分点、全100束基本达标比例下降不超过3个百分点，并同时检查J和SGM的变化。有取舍如实报告，功率降低伴随明显服务下降不判成功。

R2希望在这些条件下进一步提高基本服务或SGM：全100束达标比例提高5个百分点、SGM提高0.03可作为方向目标，不承诺二者都实现。各阈值需结合验证波动解释，20场景×3不是60个独立场景，单训练种子也不证明跨种子稳定性。

### 正式共同考核

01-15和01-18已经参与开发解释，不再作为下一轮全新独立考核。建议预先冻结另一未用于开发的日期（候选01-19，需先确认数据可得和覆盖），均匀预选100个时刻，不按成绩筛选。4个新模型及旧A/B在同一100场景各3次随机动作，最多1800次模型分配；固定/贪心各100次，共最多2000次，统一工作台记录。若数据日期或范围需变更，应在评价前记录，不能静默换集合。

## 10. 四组核心之外，哪些按需补充

**优先补R3，再根据证据选专项，不一次把所有候选开跑。** 下表是额外研究选项，均不含在160万步建议核心预算，也没有新授权；正式专项若开展，需事前固定参照、唯一变化因素、单seed51001、共同预算与留出考核。

| 专项 | 精确对照 | 何时值得做 |
| --- | --- | --- |
| 价值学习稳定性 | 从一个明确的参照复制，分别只改MSE→Huber，或只改Critic学习率1e-4→5e-5；一次选一个 | 分组TD证明误差来自离群目标，或多数样本持续漂移时 |
| 温度机制 | 固定同一状态、奖励和学习配置，仅比较自适应α与固定α（0.3仅为待验证候选） | 熵差持续扩大且α/Q目标回路漂移；不是只因α数值大 |
| 联合动作价值 | 保持因子化策略与合法掩码，比较三头加和Critic与显式评价组合动作的Critic | 稳定机制后TD仍与槽数×功率等相互作用相关，且合法动作小例揭示表达限制 |
| 纯信息贡献 | 同211维、同融合支路及初始化，但7个额外输入恒零，支路仍可训练；与真实7量比较 | 准备声称“新增信息本身有效”，而非仅证明整个状态包有效 |
| 逐步反馈贡献 | 同R2的211结构、新J、20倍尺度及γ，仅取消势函数反馈，前99步0、最后20J | 需要区分新终态目标和逐步反馈究竟哪项带来提升 |
| 较全面状态再验证 | 在已稳定的共同学习设置下，同一32令牌骨干的少量/全面信息两组；两者都dropout0、场景重排、同奖励 | 核心训练趋稳后，再检验旧C组的全局信息是否因训练机制受限；单跑全面组与211相比不能纯归因信息 |

永久关闭211融合门控只会回到R0，不能替代“同结构但7输入恒零”的训练对照。推理时临时删掉信息也可能造成输入分布变化，仅是诊断，不等于从头训练消融。Huber与学习率、温度不可一起改后归因，固定温度也不承诺更稳。

联合动作价值是与掩码不同的问题。冻结代码`e25ae56/.../agents/workbench_algorithms.py:28–33`把每个Critic的频点、槽数、功率三头相加，双Q在各自求和后取小。槽数与功率对容量存在相互影响，可先从**同一真实终止前状态**复制环境，固定频点，选四个都合法的两槽数×两功率动作，分别执行一次，计算`Δ=r11−r12−r21+r22`。每个加和Critic在此四动作上的矩形差为0；真实终止奖励的Δ若超出数值误差，证明该状态上的表达限制，但不证明它是漂移根因。Δ接近0也不证明所有状态都可加。应在多个可达状态核对量级，保留资源账和后续干扰；本次只提出探针，尚未执行。

若开展联合Critic训练，目标期望仍须按合法联合动作概率计算，保持双Q规则、同预算和场景；报告参数量、显存与吞吐差异，不能把额外模型容量混成纯交互效应。因子化Actor仍不自动获得“选完槽数再决定功率”的条件分布，因此不能宣称已实现完整联合策略。

低成本评价应补齐，但通常不需要每项再训练一个模型：

1. **负载分层：**先用训练集总需求的33%/67%分位冻结低/中/高负载阈值，再对共同考核场景分类；各层报告SI、SGM、全100束基本达标、功率和容量偏差，不因某模型成绩重新划层。
2. **新日期与地理布局：**共同未参与开发日期仍是正式主考核；额外未用于调参日期可作扩展考核，所有方法面对相同实际场景，明确相邻快照的相关性。
3. **最小动作与资源粒度：**选代表性小需求场景，在其他束分配固定时检查合法1槽/5W及可行频点，并重算全体干扰和资源账。区分粒度限制、策略过量和后续干扰；局部重分配不等于全局最优下界。先评价与解析，不为每个需求区间单独重训。

若以后确需改槽宽或最低功率，另立物理环境对照、保持总带宽/功率可比，并贯通前端与动作含义，不能插入核心矩阵。若用一次考核结果来挑专项方案，该批数据已参与开发，专项最终结论需新的留出考核。当前只扩充方案，未执行以上训练或评价。
