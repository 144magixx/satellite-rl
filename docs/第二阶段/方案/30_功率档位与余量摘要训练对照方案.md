# 30 功率档位与余量摘要训练对照方案

2026-10-16｜新研究组建议 S2-W30｜GPT-6 Astra设计，后续代码、核验与报告按项目约定由GPT-6.1 Sol承担。

**当前仅设计。** 本轮新训练、参数更新、PHY调用、数据生成和远端操作均为0。W29已经结案，未用额度不转入本方案；W28、第一阶段及已有自动跟进的暂停不因此解除。下文是新的有限预算建议，不是已启动任务。

## 1. 这一轮要弄清什么

前一轮发现：有些束即使只给一槽、5瓦，供给仍偏多；把5瓦以上的档位变细，固定前缀下的额外收益很小，允许低于5瓦后的空间较大。A0的细档位与低功率诊断只计算固定前缀，没有继续处理后续束；A1才是在原功率域改一次动作、接着用冻结旧策略处理剩余束。两者都没有训练会使用新档位的新策略，不能回答“从头学会新动作域以后，整景是否更好”。

这一轮直接训练，并分开检查三个问题：

1. **档位是不是太粗。** 保持最低5瓦，只把5瓦以上的间隔从5瓦变成0.5瓦。
2. **最低5瓦是不是太高。** 先只加一个0.5瓦选项，再检查补齐低功率区间是否还有帮助。
3. **模型是否需要更明确地看见此前分配的余量。** 给它增加100个槽各自的摘要，告诉它在这个槽发射时，此前哪些束可能受到影响、这些束离自身需求有多近。

摘要取自当前已经发生的分配，不看未来实际动作，不另做动作搜索。最终仍由模型一次输出频率、槽数和功率，整景完成后计算成绩。

## 2. 推荐八组，每组从头训练15万步

| 分组 | 模型可选功率 | 是否增加100槽余量摘要 |
| --- | --- | --- |
| 原档位 | 5、10、…、50瓦，共10档 | 否 |
| 原档位＋摘要 | 同上 | 是 |
| 只细化5瓦以上 | 5、5.5、…、50瓦，共91档 | 否 |
| 只细化5瓦以上＋摘要 | 同上 | 是 |
| 只加一个低功率选项 | 0.5、5、10、…、50瓦，共11档 | 否 |
| 只加低功率选项＋摘要 | 同上 | 是 |
| 全区间细化 | 0.5、1、1.5、…、50瓦，共100档 | 否 |
| 全区间细化＋摘要 | 同上 | 是 |

“只加一个低功率选项”故意不是等间隔菜单：它保留原十档，只多一个0.5瓦。若改成0.5、5.5、10.5等，会移动原来的档位，难以分清效果从哪里来。0.5瓦沿用已经诊断过的范围，作为有明显区分度的研究下限；它不是已核实的实际功放能力。

八组共**120万次新训练交互**，先用训练种子51001。每组固定150000步终点，50000、100000步只看学习过程；不因中途低分删掉某组，也不只给某个组追加训练。

四块独立GPU合格且可用时，第一波跑四种功率菜单的原状态组，第二波在同一块GPU上跑相应的加摘要组。这样两波完成首种子，方便对照。四个端口未必是四块GPU，实施时须核唯一身份、账号、任务归属及共享磁盘；没有四块独立可用GPU就排队，科学预算不变。两波所处时段不同，不能用训练墙钟直接证明摘要更快或更慢；正式推理计时安排在相同设备、相同负载条件下完成。

六组方案可以删掉“只加一个低功率选项”的两组，每种子省30万步。但那样只能回答“先细化，再放低下限”的顺序收益，不能检查低功率选项单独有没有用。**推荐保留八组**，比六组多三分之一训练，换取更清楚的解释。

## 3. 怎样比较，什么时候继续复验

先看全部八组固定终点，不和旧实验的历史分数直接相减。最重要的几组比较是：

- 原档位与只细化5瓦以上：检查保留5瓦下限时，细档位是否值得。
- 原档位与只加0.5瓦：检查一个低功率选项能否解决主要问题。
- 只细化5瓦以上与全区间细化：检查低于5瓦的整段选项有没有额外作用。
- 只加0.5瓦与全区间细化：检查有了低功率选项后，填满中间档位是否仍有必要。
- 每种功率菜单内，有摘要与无摘要：检查摘要的作用是否依赖功率菜单。

这些比较同时报告最终SGM、最终SI、功率、约束、完整分配情况和实际耗时。既报告改善，也保留退步场景。SGM衡量供需匹配，SI保护实际服务水平，不能只挑其中一个好看的数。

首轮用已见开发20母场景，每母3次随机动作重复。以下沿用此前全策略比较所采用的实用改善尺度，并在本方案重新登记，不将一次动作诊断门移作训练准入门，也不因已有小收益而降低要求：相对本轮重训的原档位无摘要组，终点平均SGM至少提高0.01，SI下降不超过0.002（0.2个百分点），平均功率不超过对照110%，硬约束无违规且完整分配不退步。

若没有组达到，就完整报告本轮结果并结束，不改门槛、换种子或只延长某组补救。若有组达到，按SGM、SI、较低功率、固定分组编号依次打破并列，锁定一个主要候选。只有首轮八组完整结束、开发候选过门、40个新确认母已合格封存三项同时满足，才进入以下**有限复验**；新确认不可得就停在开发交付，不自动追加两种子：

- 增加51002、51003两个训练种子，八组都重训15万步，追加240万步；保留完整矩阵，才能继续讨论各因素及交互在不同种子下的表现。
- 使用提前封存的40个新确认母场景，对三个种子的全部24个终点共同评价，每母仍3次动作重复。候选在开发阶段锁定，不能看确认结果重新挑一个赢家。
- 主要候选相对原档位无摘要组，仍按上述SGM、SI、功率和约束标准判断；同时要求三个种子中至少两个SGM为正差，并公开每个种子的结果。三个种子仍不足以保证普遍稳定。

完整复验最多使训练总量达到**360万步**。如果只负担得起首轮，八组单种子仍能回答初步比较，但应明确是单种子结果。若以后只给候选和对照补种子，就只能验证这一对，不能宣称八组因素都已得到跨种子确认。

**进入新训练的条件是工程正确、数据与资源合格，以及获得本方案的实施授权。** W29一次动作干预未过旧门，不阻止新学习问题的设计；科学筛选只决定首轮完整结束后是否值得追加复验。

## 4. 保持哪些条件不变

以W26真实S10配置为参照：本束宽度输入保留，Transformer仍为14令牌、d128、2层、8头、FF512，双Q仍用原加性结构，实际奖励仍为legacy_repaired，gamma为0.99、固定alpha为0.01。训练warmup为2000、batch为256、replay容量为20000，Actor／Critic学习率分别沿用1e-5／1e-4；冻结实现前逐项核对原配置，而非只凭本表重建。

训练仍复用W26的576个冻结母场景与真实布局，不同时增加网络、改奖励或扩训练数据。全部飞机、稳定ID、每机21.6 Mbps、唯一归属、真实束宽与可变非空N≤200保持。这里的“T0架构”不表示退回T24旧异质需求或固定100束数据。

100个频率起点、1—10连续槽、50瓦最大整束功率、3000瓦总功率、原同组互斥规则都不变。没有零槽、静默动作、跳过服务、连续功率或第三阶段优化。

**主矩阵每个未来束仍统一预留5瓦和一槽。** 降低当前束可选功率，不同时放松此前束能花掉的预算。因此低功率组仍受原5瓦未来预留约束，它检验的是这一保守预留规则下的新菜单。把未来预留也改成0.5瓦会同时改变可行域与早期分配，应另作对照，不能混进本轮下限作用。

## 5. 技术附录：实现与公平边界

### 5.1 功率菜单需要贯通整个学习过程

当前实现有固定十档、按索引换算5瓦以及固定动作维数的路径。后续不能只改配置：Actor、两个在线Q、两个目标Q、联合掩码、随机warmup、回放动作、断点schema和请求／实际动作日志必须使用同一张明确功率表。旧权重不强行加载到新动作头，所有组均从头建立权重、优化器和回放池。

共享contracts／link当前没有5瓦下限，但也不能替本实验核验50瓦上限及菜单成员资格。本轮输入、动作日志和导出必须显式保存并校验完整物理功率表、各菜单实际下限（0.5或5瓦）及50瓦上限、整束瓦特单位whole_beam_watt、总功率≤3000瓦、未来每束5瓦／一槽预留、正功率且无跳过服务、动作schema版本与内容SHA；不能仅凭宽松共享校验通过就称动作合法。不热改共享物理版本或PHYSICS_SHA。第三阶段部分旧离散优化入口固定discrete_step_w=5，这不代表第三阶段所有物理路径都要求最低5瓦；本组第三阶段调用为0，旧入口不能把新菜单静默解释成原十档，未来衔接须另行资格核验，本轮不声称已兼容。

可选档数变大，输出头参数和联合计算量也会增加。每网功率输出预计增加129×（新档数−10）个参数；batch256下，一张B×100×10×P的float32联合表由十档时10.24 MB增至百档时102.4 MB，真实计算有多张中间张量。实施前必须测实际峰值显存及真实梯度更新；不能宣称细化只有微小成本。同交互预算不是同计算预算。

固定alpha也不表示熵奖励尺度完全不变：功率最大熵从ln10到ln100，alpha乘这一项的上限差约0.02303。主实验保持alpha不变，**比较的是新离散菜单及其学习过程的整体效果**，不能纯归因于物理分辨率。保存合法功率档数、实际功率熵、最大熵、归一化熵和alpha×熵，以及其它动作头的熵；不根据结果逐组调alpha。

### 5.2 余量摘要的固定定义

对当前束i与槽k，使用：

x[k] = log1p(Σj 1[k属于此前已分配束j的实际槽] × exp(−|Cj/Dj−1|) × (1 W)κ(i→j,k)/(nj,k＋Ij,k))。

Cj是当前前缀容量，Dj是真实需求，κ是每瓦发射对接收束的干扰系数，噪声n与已有干扰I均以瓦计。仅统计此前已经分配的束；空前缀为零。接近需求的束获得较高权重，但该权重不是精确SGM导数。使用无量纲log1p原式，不新增按成绩拟合的缩放或裁剪；原S10各通道归一化保持原样，非有限输入须明确报错。

100个值并入现有十个槽令牌：每令牌原有10干扰＋10占用输入列，增加10个摘要列，由20列变30列；令牌总数仍14。预计每个编码器增加1280个参数，Actor、在线Q和目标Q都要一致。无摘要组真正不构建这部分，不用零通道或无效参数凑相同形状。

因此该对照是“新增摘要表示及其必要投影”的处理，不是完全等参数的信息实验；它也不能单独证明余量权重优于普通出向干扰摘要。构建摘要必须复用环境已有的全N束容量、冻结kernel／耦合矩阵和实际前缀分配，从已有数组算出I与X，**额外PHY和额外kernel调用均为0**。构建摘要的算术与时间仍实计；如果实现必须再调用容量计算或重建kernel才能得到特征，则工程资格不通过，修正实现后才可准入，不能另开科学调用额度。

### 5.3 随机性与评价

相同形状的共享参数使用同一组件随机流初始化；新增功率行、输入列使用独立组件流和相同初始化分布。可按实际瓦数配对共享输出行，但新增列和菜单归一化会改变初始策略，不能说八组初始函数完全相同。初始策略与实际参数清单保存。

场景顺序、初始化、回放采样、动作采样和评价分别管理随机流；同母共享随机数不表示执行相同动作。评价用独立环境与随机状态，不影响后续训练。沿用原随机直出、每母3次动作的口径；不把某组改成最大概率动作再与其他随机组比较。

所有分数来自全部真实N束的完整终态，包含后续干扰，未服务束记零。每母先平均动作重复，再做同母配对，随后对母与训练种子等权。训练曝光、真实更新数、回合数和失败都保留；不能把相同回放索引说成相同状态转移。

## 6. 数据、统计与有限预算

新确认建议四个从未用于本项目路线选择的日期，每日期10母。先核历史日期用途，冻结源文件、时刻、稳定ID和名单，只允许看数据资格，不看策略成绩。W26原确认的2024-02-23／24已经被使用，不能再称新独立考核。

新日期是否可获得、现有冻结布局生成器能否产生足量合格布局尚未核实。最多预登记80个源时刻、每时刻一次布局尝试，按固定时刻顺序取每日期前10个合法母，保存失败与排除原因；不足就报告缺口，不重复母、不删飞机、不改请求、不挑容易的布局，也不无限重试。没有新数据时可以完成开发比较，但不宣布独立泛化；条件复验入口须事先明确数据缺口。

| 复核、图表、传输与收尾 | 合4 worker小时；只读日志算术与I/O另记录，不制造新科学查询 |

前向上限按实际路径保守封顶：全部正式与工程交互／评价最多2次整网前向，3552024＋392次更新每次最多16次整网前向，独立工程前向最多8192次；合计不超过66959616，向上取67000000作为计数硬限。真实SAC常规更新通常少于16次；差额不能换成候选筛选、额外评价或训练。额外前向诊断必须限在独立工程8192次内。

以上活动时间合520 worker／GPU小时（GPU训练480＋其它40），另设从首个执行作业开始累计168小时的组级运行窗口；四独立GPU全可用时只是有界排程，不是实测工期承诺。等待资源不消耗科学调用，但占用该窗口。到限保存断点并按未完成交付，不改变预算或把截断算作科学失败；工程测量若显示上限不能覆盖既定终点，须在任何正式训练开始前统一修订规划。存储不足同样先处理资格，不能用吞吐测试或重试无限延长。

## 7. 其它因素怎样处理

本轮不同时改变模型宽度、训练日期数量、奖励、温度或未来预留。否则即使更好，也解释不清原因。

若摘要有效、且需要把收益归因于“余量权重”，后续可在预锁定的一种功率菜单上增加权重恒为1的摘要对照，最多三个种子、每个15万步，作为另立的45万步上限建议。它不是本轮自动任务；若根据确认结果选它，原确认数据对该后继已参与开发，需要新的独立确认。

同理，1瓦中间粒度、放松未来预留、熵尺度控制都只保留为后继问题，每次最多一个明确对比。当前先完整回答这八组，不把节省额度转成无限扫描。

## 8. 存储与交付

每个实际存储位置保留一套共享输入、冻结源码和规范结果，四个远端若共享NFS只算一个存储位置。每组保存0／50k／100k／150k的策略、完整在线Critic和配置，以便核验学习曲线和价值来源；活动训练只保current与上一可信完整恢复断点。正式原始动作、每步服务、每回合全束终值、失败、预算和曲线全部保留，静态输入用引用，长记录用可恢复的压缩分块。

按完整24组规划，每位置暂估输入2 GiB、结果与固定节点24 GiB、四活动worker恢复16 GiB、源码报告2 GiB、传输临时2 GiB，工作集46 GiB；再预留单套归档44 GiB及恢复安全余量16 GiB，峰值约106 GiB。**这只是空间规划，尚未现场核验。** 实施前用真实断点和日志增长测量修正；空间不够先减少并发或清理已核副本，不删必要科学原件或改变训练预算。规范原件与备份验完后，清理无活动依赖的临时副本并留下小型回执。

最终报告先回答“哪种菜单值得用、摘要在哪种菜单下有帮助、付出多少计算和功率”，再给训练曲线、逐母差值、全部种子、失败与限制。本轮方案阶段只做文档和引用检查，不把任何待执行项目写成通过。
